# Graft ブックの情報と依頼の観点 仕様書・実装指示（v0.6）

この文書は、`docs/仕様書_VBA連携.md`（v0.3。以下「VBA連携仕様」）の続きとして、次の 5 機能（A〜D と、v0.5 で足した E。書き換えの F は次の版の予定で、章立てだけ置く）の仕様と実装指示をまとめたものである。実装は `CLAUDE.md` の流儀（日本語コメントで「なぜ」を厚く書く、警告ゼロ、`Graft.Tests` と `Graft.UiTests` の全件成功を確認してから完了報告）に従うこと。コードの名前はファイル名・型名・メソッド名で示し（行番号は書かない）、**「（新設）」と付けたもの以外は、現在のコードに実在する名前**である。

| 記号 | 機能 | 対象 | 一言 |
|---|---|---|---|
| A | ブックの情報 | VBA プロジェクトのみ | シート・テーブル・名前・見出し・参照設定を、コンテキスト収集の項目として AI に渡す |
| B | 依頼の観点 | すべてのプロジェクト（VBA は追記つき） | 「読みやすく」「不具合を直す」などのチップを選ぶと、依頼文に指示が入る |
| C | 反映前の自動控え | VBA プロジェクトのみ | 「Excel へ反映」で上書きされる前の Excel 側の本文を、毎回世代つきで残して戻せる |
| D | 保存時の自動反映 | VBA プロジェクトのみ（既定オフ） | ミラーのファイルを保存したら、そのモジュールだけ Excel へ送る |
| E | リボン（customUI）の読み取り（v0.5） | VBA プロジェクトのみ | 保存済みのブックを読み取り専用で開いて、リボンの XML（customUI）を読み、構成・コールバックと VBA の照合・XML の全文を AI に渡す（15 章） |
| F | リボンの書き換え（次の版・予定） | VBA プロジェクトのみ | AI が直したリボンの XML を、ブックへ書き戻す（**この版では作らない**。16 章に章立てだけ置く） |

v0.2 は、段階 Q1〜Q4 の実装で仕様から外れた点・仕様が決めていなかった点を、実装のとおりに書き直したもの（次の「v0.1 から v0.2 への変更点」。理由は各章の本文にも残した）。v0.3 は、4 機能の点検で見つかった不具合の修正を反映したもの（「v0.2 から v0.3 への変更点」）。 v0.4 は、ブックの情報に**シートごとの見せ方**（出さない／構成だけ／見出し＋N 行／全部／範囲を指定）を足し、ブック全体の「値の見本」のオン・オフをそれに一本化したもの（次の「v0.3 から v0.4 への変更点」）。v0.5 は、**リボン（customUI）の読み取り**（機能 E。15 章）を足したもの（「v0.4 から v0.5 への変更点」）。

決定済みの事項（利用者が決めたもの）は本文に断定で書いた。仕様書の作成中に私が決めたこと・迷ったことは付録Aにまとめた。**COM と VBE の挙動は Linux の CI で確かめられない。「実機で要確認」と書いた事項は推測であり、実装者は Windows 実機で確かめてから仕様を確定する（付録B）。**

## v0.5 から v0.6 への変更点（収集画面の配置の作り直し）

利用者の要望: 「AIに渡すファイルを選ぶ」画面が窮屈で、ファイルを選ぶ一覧が見えない（VBA プロジェクトでは、ブックの情報とシート一覧がファイル一覧の上に積まれ、ファイル一覧が 0 行になっていた）。根は「縦に積むものが多すぎて、伸び縮みするのがファイル一覧だけ」という構造にあった。設計案から**案 A「一覧を主役にする」**を選んだ。機能は 1 つも減らさず、配置と操作の手段だけを変える。

| 章 | v0.5 の記述・挙動 | v0.6（変更後） |
|---|---|---|
| 5.3・15.5 | ブックの情報の行・リボンの行を、ファイル一覧の上に縦に積む。シート一覧は高さ 260px の上限で内側にスクロール | **窓の幅で置き場所を変える**。広い窓（860px 以上）はファイル一覧の**右の列**（仕切りで幅を変えられる）、狭い窓（860px 未満）は**「ブックの情報」タブ**。ブックの情報の枠とリボンの枠は 1 つの部品にまとめ、置き場所を変えるときは**親を付け替える**（同じ部品を 2 つ作らない）。列全体が 1 つの縦スクロールで、シート一覧の高さの上限は外す。値が渡る注意は枠の上のほう（取得状況の下）へ。狭い窓では、ファイル選択タブの先頭に「ブックの情報: 内容も出す　シートの値: …」の 1 行も出し、**値が渡る注意を、ファイル選択タブを見ているときも常に出す** |
| 5.3 | シートの行は、見せ方の選択・行数（範囲）・数式のチェックを縦に並べる | 行数（範囲）と「数式も含める」を 1 行に並べ、入りきらなければ折り返す（1 シートあたり縦に 1 行減る） |
| 6.2 | チップは見出しごとに 1 行ずつ縦に積み、折りたたまない | 見出しのかたまり（見出し＋チップ）を**横へ流して折り返す**（既定の窓で通常 2 行・VBA 3 行。以前は 5 行・6 行）。収集の窓だけ、見出しの左に「**たたむ**」ボタンを置く（下の 6.2）。**全チップは最初から並ぶ**ことは変わらない |
| 画面 | 追加の除外パターンは右の柱（窓の幅の 1/3）。空でも幅を占めていた | ファイル一覧の**下の折りたたみ**。初期状態は常に閉じ、件数（「2 件」）は見出しに常に出す |
| 画面 | 状況の文（トークン数の助言など）は、ボタンの左の狭い列（4〜5 行に折り返す） | ボタンの**上の全幅の行**（最大 3 行。全文はツールチップ）。文が無いときは行ごと消える |
| 画面 | 窓の既定 760×720（最小 600×520）。窓の題名と同じ文言の見出しが本文の先頭にもあった | 既定 **960×700**（最小 **640×560**）。重複する見出しは外す。タブの中身の左右の端は、共通テーマの `TabControl` の `flush` クラスで、上の収集モード・下のボタンと同じ 16px に揃える |
| 画面 | 状況の文のトークン数（「約90427」）と、ボタンの行の「推定トークン数」（「約85365」）が食い違うことがあった | 数字を含む文は、推定が変わるたびに同じ書き方で作り直す（`SetSizeStatus`）。目安以下になったら助言は消える |

ファイル一覧の行の高さ（36px）は変えない（別件）。

## v0.4 から v0.5 への変更点（リボン（customUI）の読み取り）

利用者の要望: Excel のリボン（タブ・ボタン）を直したい・足したいとき、AI が今のリボンの定義（customUI の XML）と、それが呼ぶ VBA の手続きを知らないと、存在しない id や、呼び先の無いコールバックを書いてしまう。ブックを zip として開いて XML を取り出し、貼り付ける手間をなくしたい。**今回は読み取りだけ**で、書き換えは次の版（16 章）。

| 章 | v0.4 の記述・挙動 | v0.5（変更後） |
|---|---|---|
| 1.4・15 | リボンは対象外（ブックの情報はシート・テーブル・名前・参照設定） | **機能 E（15 章）を新設**: 保存済みの .xlsm／.xlam／.xlsb を Open XML パッケージ（zip）として**読み取り専用**で開き、関係の一覧（`_rels/.rels`）から customUI の部品（通常 `customUI/customUI14.xml`、古い形式は `customUI/customUI.xml`。両方あれば両方）を読む。**Excel（COM）は呼ばない**。.xls は対象外 |
| 15.1・15.5 | — | 読むのは**最後に保存した内容**で、Excel で編集中の未保存の変更は含まれない。画面の行と依頼文の冒頭に、取得日時とファイルの更新日時を添えて明記する |
| 4.1・15.5 | — | `VbaLink.RibbonState`（`Full`／`StructureOnly`／`Hidden`。既定 `Full`）を追加。コンテキスト収集の窓に、「ブックの情報」の行と同じ並びで**「リボン（customUI）」の行**を置く（3 状態・プロジェクトごとに記憶）。「構成だけ」は構成（id・label・種類）とコールバックの一覧、「内容も出す」はそれに XML の全文（文字数の上限つき） |
| 15.4 | — | コールバック（`onAction`・`getEnabled`・`onLoad` などの `on*`／`get*`／`loadImage` 属性）の名前を、VBA のミラーの `Sub`／`Function` と照合し、**「VBA に見つかりません」「Public ではないため呼べません」を明記**する（純ロジック `VbaRibbonCallbackMatcher`。`Public`／`Private`、`Module1.OnBtn` のモジュール名つき、大文字小文字を扱う） |
| 15.3 | — | XML の解析は `System.Xml.Linq`。**外部実体の解決を無効にする**（`DtdProcessing.Prohibit`、`XmlResolver = null`。XXE 対策）。DTD を含む部品は読まない。zip の部品は展開しながら読み、**上限（既定 2 MB）を超えたら読むのをやめる**（zip 爆弾対策）。新しい NuGet は使わない |
| 15.6 | 依頼文は「前提 → ブックの情報 → 観点 → 対象ファイル」 | **「前提 → ブックの情報 → リボン → 観点 → 対象ファイル」**。テンプレート変数 **`{{ribbon}}`** を新設（無いテンプレートでは、ブックの情報・観点と同じ規則で差し込む）。観点を選ばず、リボンも「出さない」（または customUI が無い）なら、依頼文は従来と**1 バイトも変わらない** |
| 15.7 | — | 取るタイミングはブックの情報と同じ（コンテキスト収集を開いたとき・依頼文コピーのとき）。読めないとき（ファイルが無い・壊れている・ロック・customUI の XML が壊れている）は収集を止めず、**理由を行に 1 行で出す**（読めなかったときだけ警告にも載せる）。customUI が無いブックは「このブックにリボンの設定はありません」 |
| 9 | — | `Vba.RibbonMaxChars`（既定 30000、2000〜200000）を追加。XML の全文を載せる最大文字数で、`Vba.WorkbookInfoMaxChars` とは別 |
| 16 | — | リボンの書き換え（機能 F）は**次の版**。この版では章立てだけ置く（ブックを保存して閉じる → 控え → 差し替え → 開き直す、毎回確認、未保存があれば止める、XML の検査） |

## v0.3 から v0.4 への変更点（シートごとの見せ方）

利用者の要望: 「このシートは 5 行目まで、このシートは全部見せないと理解できない」のようにシートごとに事情が違うのに、ブック全体で「見出し＋N 行」（値の見本。既定オフ）の 1 種類しか選べない。

| 章 | v0.3 の記述・挙動 | v0.4（変更後） |
|---|---|---|
| 5.1・5.2 | 値の渡し方は、ブック全体の「値の見本」のオン・オフと行数 N（設定）の 1 種類。「内容も出す」では、見本がオフでも各シートの 1 行目（見出し）が渡る | **シートごとに見せ方を選ぶ**: 出さない／構成だけ（既定）／見出し＋N 行（N はシートごと）／全部（1 シート 500 行・50 列まで）／範囲を指定（A1 形式）。**既定は全シート「構成だけ」**で、見出し行も渡らない（値が渡るのは、利用者が値の渡る見せ方を選んで確認したシートだけ）。数式を含めるかもシートごと |
| 5.2 | 見本をオンにするときの確認（ボタンは「値の見本を渡す」「やめる」） | **値が渡る見せ方（見出し＋N 行・全部・範囲を指定）を選ぶときに、シートごとに同じ確認**を出す（ボタンは「値を渡す」「やめる」。既定は「やめる」）。「出さない」「構成だけ」へ戻すときは出さない |
| 4.1 | `VbaLink` の `WorkbookInfoSampleValues`・`WorkbookInfoIncludeFormulas` | **`WorkbookInfoSheetViews`（シートのコード名ごとの見せ方）を追加**。旧 2 項目は移行のためだけに読み、新しい版はオンにしない。**移行**: シートごとの記録を一度も作っていない（`WorkbookInfoSheetViews` が null）既存のプロジェクトで `WorkbookInfoSampleValues` がオンなら、全シート「見出し＋N 行」（N は設定 `Vba.WorkbookInfoSampleRows`、数式は `WorkbookInfoIncludeFormulas`）として読む。利用者が最初に 1 枚の見せ方を変えた時点で、全シートの結果を記録へ確定し、旧 2 項目をオフに戻す（以後は再移行しない） |
| 4.1 | 別のブックへ結び直したら、値の見本のオンだけを解除する | 別のブックへ結び直したら、**シートごとの見せ方を（「出さない」も含め）すべて消して全シート構成だけに戻す**（確認をやり直させる。コード名は別のブックでも `Sheet1` などと重なるため） |
| 5.3 | 行に「値の見本」のボタンと「数式も含める」を置く | **ブック全体の値の見本のオン・オフは無くし**（UI が二重にならないように）、3 状態の行の下に**シートの一覧**を出す（シートごとの見せ方の選択・N・範囲の入力・数式のチェック・切った旨の注記）。3 状態（内容も出す／構成だけ／出さない）は残る。全体が「出さない」のときはシートごとの設定を無視し、「構成だけ」のときは値を渡さない（ただし**「出さない」にしたシートは守る**）。一覧は「内容も出す」のときだけ出す |
| 5.5 | `VbaWorkbookInfoOptions` は `SampleRows`・`IncludeFormulas` で値の見本を指示する | **`Views`（`VbaSheetViewSet`。シートごとの見せ方）に置き換え**、`AllMaxRows`・`AllMaxColumns` を足す。**値を読むのは値が渡る見せ方のシートだけ**（Excel の読み取りを増やさない）。「出さない」のシートはテーブルも読まない。読む範囲の計画（見出し＋N 行・全部の上限・範囲と使用範囲の共通部分）は純ロジック `VbaSheetReadPlanner` に出し、Windows のブリッジと Fake が共有する |
| 5.5 | 上限は列数・見本の行数・セルの文字数・全体の文字数 | **「全部」「範囲を指定」の上限（既定 1 シート 500 行・50 列。設定 `Vba.WorkbookInfoAllMaxRows`〔10〜5000〕・`Vba.WorkbookInfoAllMaxColumns`〔5〜200〕）**を足す。読む範囲そのものを小さくして読み、切ったときは**「何行・何列のうち何行・何列を出したか」と、続きは「範囲を指定」で選ぶことを依頼文に明記する** |
| 5.7 | 「## 先頭行の見出し」「## 値の見本」の節 | 値は**「## シートの値（AI に渡ります）」の節にまとめ**、シートごとに `### 集計（Sheet1）: 見出し＋5 行`・`全部`・`範囲 A1:F30` の見出しで出す。「全部」「範囲を指定」の表は、先頭の列に行番号、見出しの行に列の文字を置く（範囲の先頭が見出し行とは限らないため。A1 形式で指示を書きやすくなる）。全体の文字数の上限で落とす順は「シートの値（末尾のシートから。入る行数までは残す）→ 参照設定 → …」 |
| 5.1 | 「出さない」の扱いは無い | 「出さない」のシートは、シートの行・そのシートのテーブル・シート限定の名前・参照先がそのシートの名前・そのシートに触れる「読み取れなかったもの」の注記を、すべて出さない |
| 9 | `Vba.WorkbookInfoSampleRows` は「値の見本の行数」 | 「見出し＋N 行」の N の**既定**（見せ方を選んだときの最初の行数）と、移行のときの N。**`Vba.WorkbookInfoAllMaxRows`・`Vba.WorkbookInfoAllMaxColumns` を追加**（範囲検証つき） |
| 5.2 | 「オフにしたら直ちに捨てる」は、見本のオフと数式のオフ | **値が渡らない見せ方へ戻したシート**、数式をオフにしたシート、**全体を構成だけ・出さないにしたとき**の全シートの値を、メモリから直ちに捨て、プレビュー欄も空にする。設定でブックの情報の取得や VBA 連携をオフにしたら、次のコピーに入らない（出力の直前に引き直す。v0.3 から変わらず） |

## v0.4 の点検での修正（シートごとの見せ方の不具合）

v0.4 の実装を点検して見つかった不具合を直した。本文は、下の表のとおりに書き換えてある（各章の本文にも理由を残した）。

| 章 | 修正前 | 修正後 |
|---|---|---|
| 4.1・5.2 | 結び直しても、選択中のプロジェクトの収集のモデルは作り直されず、前のブックの見せ方と取得結果のまま、新しいブックの値を確認なしで読み、次の操作で古い見せ方を保存へ書き戻した | **結び直したら、収集・依頼文のモデルを作り直す**（`ProjectPaneViewModel.WorkbookRelinked`）。加えて、**取得・出力・操作の直前に、取得に使ったブックのパスと、いま紐付いているブック（`VbaLink.WorkbookFullName`）を突き合わせ**、違えば取得結果と見せ方を捨てる。見せ方の保存は、**保存側の最新に対して対象のシートだけを差し替える**（古い一覧で全体を上書きしない） |
| 5.1・5.5 | 「出さない」のシートが取得結果に載らない（時間切れ・読み取り失敗・シート数の上限）と、そのシート名と、そのシートを指す名前付き範囲・注記が出た | **取得結果に全シートの名前（`VbaWorkbookInfoSnapshot.AllSheets`。表示名とコード名）を、値を読まないシートも含めて載せる**。それでもブックの全シートに無いシートを指す名前・注記は伏せる側に倒す。**「出さない」のシートのテーブルを指す名前（構造化参照 `=単価表[金額]`）も伏せる**（出してよいテーブルの一覧に無いテーブルを指す名前は伏せる） |
| 5.2 | 取得の途中で数式をオフにし、次の取得が失敗すると、古い取得の数式つきの値が戻った。構成だけに戻したシートの値もメモリへ戻った | **取得に世代番号を付け、古い世代の結果は捨てる**。格納するときに、取得に使った見せ方といまの見せ方を突き合わせ、値が渡らない・数式オフのシートの値と数式は落とす |
| 4.1・5.2 | 記録はコード名だけで引くので、Excel が同じコード名を別のシートに割り当てると、値が渡る記録が確認なしで引き継がれた | **記録にシートの表示名も持つ**（`VbaSheetViewSetting.SheetName`）。**コード名が同じでも表示名が食い違い、かつ値が渡る見せ方の記録は、「構成だけ」に落として再確認を求める**。表示名を変えただけのシートと別のシートとは記録から区別できないので、どちらも安全側（再確認）に倒す。取得結果に無いコード名の、値が渡る記録は落とす（「出さない」「構成だけ」の記録は残す）。表示名の記録が無い既存の記録は、見せ方を変えずに表示名を添えるだけ |
| 5.2 | 「範囲を指定」へ選び直すと、確認の文面は「このあと入力する範囲」なのに、以前の範囲が入力なしで読まれた | **値が渡らない見せ方へ戻すとき、範囲も消す**。値が渡る見せ方どうしの切り替えで範囲が残っているときは、確認の文面に「指定済みの範囲 A1:B2」と明示する |
| 5.2・5.3 | コード名が空（または重なる）シートがあると、2 回目の取得で例外になった | 例外にしない。**コード名が空のシートは、見せ方を選べない行**（常に構成だけ。画面でも選べない）にする |

## 1. 目的と基本方針

### 1.1 目的

- A: AI が「どんなシートや表があるブックか」を知らないまま VBA を書くと、存在しないシート名・列を前提にした回答になる。ブックの構造を、依頼のたびに手で説明しなくて済むようにする。
- B: 依頼の目的（読みやすく、速く、安全に…）を毎回文章で書く手間と、書き方による結果のばらつきをなくす。通常のコードのプロジェクトにも使える。
- C: VBA連携仕様の想定外の上書き（不具合 1・2・6 のような場合）でも、Excel 側の本文を取り戻せるようにする。
- D: 手で直して Excel で試す往復を速くする。

### 1.2 基本方針

- **適用エンジンと履歴の仕組みには手を入れない。** 観点・ブックの情報・控えは、どれも「依頼文を作る側」または「Excel との同期の側」の機能で、`ApplyEngine`、`PathGuard`、`RevisionStore`、`BackupManager`、`RevisionRestorer` は変更しない（VBA連携仕様 1.2・13 と同じ）。
- **COM を呼ぶ部分は Windows 専用**で `Platform/Windows` に閉じ込める。Linux と未対応環境では `Platform/Null` が E706 を返し、A・C・D の UI は出ない。B は COM を使わないので全環境で動く。
- **判定や整形のロジックは `Core/` の純ロジック**に置き、`Graft.Tests` で固める。
- **Excel に繋がらなくても、依頼文の作成は止めない。** A の取得失敗は警告だけで続ける（VBA連携仕様 7.2 の自動 Pull と同じ扱い）。
- **控えは「戻せること」を優先し、掃除は自動の分だけ**にする（利用者の VBE の編集を救う最後の砦は、自動では消さない）。
- **10 万行の編集性能の約束（`tests/Graft.UiTests` の `PerformanceTests`）に影響させない。** エディタの保存経路と `DocumentSession` には触れず、D は保存が終わったあとの通知（後述）から別の経路で動かす。AvaloniaEdit は 11.1.0 のまま。

- **移行（v0.4）**: `WorkbookInfoSheetViews` が null で `WorkbookInfoSampleValues` がオンの既存のプロジェクトは、全シート「見出し＋N 行」として読む（N は設定 `Vba.WorkbookInfoSampleRows`、数式は `WorkbookInfoIncludeFormulas`）。値の見本をオンにする確認は以前に済んでいるので、移行では確認を出さない。利用者が最初に 1 枚の見せ方を変えたとき、残りのシートの移行結果を記録として確定して保存し、旧 2 項目をオフに戻す（`ContextCollectViewModel.MaterializeSheetViews`）。**見本がオフだった既存のプロジェクトは、全シート構成だけになる**（v0.3 では「内容も出す」なら各シートの 1 行目が渡っていたが、v0.4 の既定では渡らない。渡る量が減る側の変更で、必要なら見せ方で「見出し＋0 行」を選べば同じになる）。

### 4.4 控えのファイル名と種別

控えの置き場は既存のまま `AppPaths.GetVbaRescueDirectory(projectId)`（`vba-sync/<プロジェクトId>.rescue/`）。ファイル名は既存の `VbaRescueNaming.BuildFileName` の形（`<モジュール名>-<yyyyMMdd-HHmmss>.txt`、同じ秒は `_2` と連番）を守り、**種別を接尾辞で表す**。

| 種別（`VbaRescueKind`。新設） | ファイル名 | 残す場面 | 自動の掃除 |
|---|---|---|---|
| `Legacy`（従来） | `Mod-20261121-103000.txt` | 衝突で「Graft 側で上書き」を選んだ直前、書き戻し失敗（E809）。VBA連携仕様 5.5・7.5 | **しない** |
| `Auto` | `Mod-20261121-103000-auto.txt` | 「Excel へ反映」（手動・適用後・取り消し後・D）で Excel を上書きする直前 | する（7.3） |
| `Mirror` | `Mod-20261121-103000-mirror.txt` | 控えをミラーへ戻す直前の、ミラー側の本文 | する（7.3） |

- 解析は `VbaRescueNaming.Parse(fileName)`（新設）が正規表現 `^(?<n>.+?)-(?<d>\d{8}-\d{6})(?:-(?<k>auto|mirror))?(?:_(?<seq>\d+))?\.txt$` で行う。**VBA のモジュール名には `-` が使えない**ので、名前と日時の区切りで一意に切れる。解析できないファイルは一覧に出さず、掃除の対象にもしない（利用者が置いたファイルを消さない）。
- 中身は UTF-8（BOM なし）。モジュール本文を正規化せずそのまま書く（戻したときに行末・空白が変わらないように）。

## 5. 機能 A: ブックの情報

### 5.1 AI に渡す中身

ブック全体の出し方（3 状態）が決めるもの:

| 項目 | 内容 | 全体が「構成だけ」 | 全体が「内容も出す」 |
|---|---|---|---|
| シート | 表示名、コード名（`Sheet1` など。ドキュメントモジュールのファイル名と対応する）、表示状態（表示／非表示／VeryHidden）、使用範囲 | ○ | ○ |
| テーブル（ListObject） | テーブル名、シート名、範囲、列名 | ○ | ○ |
| 名前付き範囲 | 名前、参照先、スコープ（ブック全体／シート限定）。**参照先が範囲参照でない式（定数・数式）の名前は、値が渡るシートが 1 枚も無いとき名前（とスコープ）だけ**（v0.3 の「見本がオフのとき」の後継） | ○ | ○ |
| 参照設定 | 名前、説明、パス、組み込みか、参照切れか（**読み取りのみ**） | × | ○ |
| シートの値 | シートごとの見せ方（5.2）で選ばれたもの | × | **シートごとに選んだものだけ**○ |

全体が「出さない」なら何も渡さず、シートごとの設定は無視する（Excel にも問い合わせない）。

シートごとの見せ方が渡すもの:

| 見せ方 | 渡すもの |
|---|---|
| 出さない | そのシートは何も渡さない（シートの行・そのシートのテーブル・シート限定の名前・参照先がそのシートの名前・そのシートに触れる「読み取れなかったもの」の注記も出さない） |
| 構成だけ（**既定**） | シート名・コード名・使用範囲・テーブル名と列名（v0.3 までの「構成だけ」と同じ粒度）。**セルの値は渡さず、読みもしない** |
| 見出し＋N 行 | 使用範囲の先頭行（見出し）と、続く N 行の値（N はシートごと。0〜100。0 なら見出しだけ） |
| 全部 | 使用範囲の値すべて。ただし 1 シート 500 行・50 列まで（設定で変更。5.2） |
| 範囲を指定 | 利用者が入れた範囲（例 `A1:F30`）の値。使用範囲との共通部分だけを読み、同じ上限が掛かる |

- 「構成だけ」は、AI に「どのシート・表・名前があるか」だけを知らせたいときの状態。付録A-1 に理由を書いた。
- 先頭行の見出しは「使用範囲の最初の行」であって、テーブルのヘッダー行とは限らない。**v0.4 では、見出し行も「見出し＋N 行」を選んだシートにしか渡らない**（v0.3 までは「内容も出す」なら見本がオフでも全シートの 1 行目が渡っていた）。1 行目がデータのシートでは、その行の値が渡るので、確認ダイアログの文面にも「見出し行（1 行目）」が渡ることを書く。テーブルがあるシートはテーブルの列名が見出しの役を果たす。
- 隠しシートも含める（表示状態を併記する）。VeryHidden のシートが利用者の意図で隠されている場合があるため、AI に渡ることは UI の注意書きに含める（5.3）。「出さない」を選んだシートは、隠しシートでも何も出ない。

### 5.2 シートごとの見せ方（v0.4。旧「値の見本」の後継）

- **既定は全シート「構成だけ」**。値が渡る見せ方（見出し＋N 行・全部・範囲を指定）は、プロジェクトごとに、利用者がシート 1 枚ずつ選んだときだけ有効になる。値が要らないシートでは、**セルを読む COM 呼び出しを一切行わない**（取得量を減らし、社外秘を Graft のメモリにも載せない。`VbaSheetReadPlanner` が「読まない」計画を返し、ブリッジはその計画のとおりにしか読まない）。なお、使用範囲が 1 セルだけのシートが空かどうかの判定のための 1 セルの読み取りだけは、構成の取得に付随して行う（値は保持せず、スナップショットにも入れない）。
- **選ぶ場所**: コンテキスト収集の窓の「ブックの情報」の枠の中にあるシートの一覧（`VbaWorkbookInfoRowViewModel.Sheets`。5.3）。各行に、見せ方の選択（ComboBox）、「見出し＋N 行」のときは N の入力、「範囲を指定」のときは範囲の入力、値が渡る見せ方のときは「数式も含める」のチェックを置く。
- **確認**: 値が渡る見せ方を新しく選ぶときに、確認ダイアログを出す（選択ダイアログ `VbaChoiceWindow`。ボタンは動詞の「値を渡す」と「やめる」で、既定〔Enter・Esc・×〕は「やめる」。ダイアログが配線されていない環境〔テスト・画面なし〕でも、確認を省略せず「やめる」と同じ結果になる）。文面は、シート名と、見せ方に応じた渡る範囲（見出し行〔1 行目〕と続く N 行／使用範囲の値すべて〔最大 500 行・50 列〕／このあと入力する範囲）、「個人情報や社外秘が含まれていないか確認してください」、「選んだ見せ方はプロジェクトごとに記憶されます（値そのものは保存しません）」。断られたら何も変えず、画面の選択も元に戻す。「出さない」「構成だけ」を選ぶときは出さない。同じ見せ方のまま N・範囲・数式を変えるときは出さない。
- **注意の常時表示**: 値が渡るシートが 1 枚でもある間は、「シートの値: N 枚のシートの値が AI へ渡ります（集計・明細）」をブックの情報の行に**常時**出す（全体が「構成だけ」「出さない」のときは出さない）。依頼文コピーのドロップダウンにも同じ注意を 1 行出す。
- **記憶**: シートの**コード名**に結び付けて、プロジェクトごとに `VbaLink.WorkbookInfoSheetViews` へ保存する。記録には、そのときのシートの**表示名**も添える（`SheetName`）。シートが消えた記録のうち、「出さない」「構成だけ」は残してよいが表示しない。**値が渡る見せ方の記録は、取得結果に無いコード名なら落とす。コード名が同じでも表示名が食い違うなら、「構成だけ」に落として再確認を求める**（Excel は削除したシートのコード名を別のシートへ割り当てうる。表示名を変えただけなのか別のシートなのかは記録から区別できないので、安全側に倒す。「出さない」の記録は、表示名が違っても残して更新する）。表示名の記録が無い既存の記録は、見せ方を変えずに表示名を添えるだけ。保存するのは見せ方・N・範囲・数式の選択だけで、値そのものは保存しない。
- **数式**: 「数式も含める」はシートごと（既定オフ）。値が渡る見せ方どうしの切り替えでは引き継ぎ、値が渡らない見せ方へ戻すときは外す（次に値を渡す見せ方を選ぶ確認で、利用者が知らないまま数式まで渡らないように）。数式は参照先のシート名・セル構造を AI に伝えるが、値と同じく中身を含みうる。
- **「全部」の上限**: 1 シートあたり **500 行・50 列**（設定 `Vba.WorkbookInfoAllMaxRows`〔10〜5000〕・`Vba.WorkbookInfoAllMaxColumns`〔5〜200〕。既存の「VBA 連携」タブに足す）。全体は既存の `Vba.WorkbookInfoMaxChars`（既定 20000）。**上限を超えた分は読まずに切り、依頼文に「何行・何列のうち何行・何列を出したか」と、「範囲を指定」で続きを選べること（続きの範囲の例つき）を明記する**。画面のシートの行にも同じ事実を出す。「範囲を指定」にも同じ上限を掛ける（100 万行の列を指定されても 500 行だけを 1 回で読む）。文字数の上限で入りきらないときは、末尾のシートから落とし、最後の 1 枚は入る行数まで残す。「全部」「範囲を指定」の切り詰めの注記は、**読んだ行数ではなく実際に出した行数とアドレスで 1 つにまとめ**（「対象は N 行・M 列ありますが、先頭の K 行・M 列（A1:…）だけを出しています」。続きの範囲の例も出した次の行から）、値を丸ごと落としたシートは「文字数の上限のため、次のシートの値は出していません: 「シート名」…」と名前を挙げる。「見出し＋N 行」は従来どおり「文字数の上限のため、見出しに続く N 行のうち K 行だけを出しています」と書く。
- **「範囲を指定」の入力の検証**（`VbaA1Range`。純ロジック）: 受け付けるのは `A1`・`A1:F30`（小文字・前後の空白は許す。`$` は列の前と行の前だけ〔`$A$1`・`A$1`・`$A1`〕。向きが逆なら正規化）・列範囲 `A:F`・行範囲 `3:10`。**全角で打っても、最初に NFKC で半角へそろえてから読む**（`Ａ１：Ｆ３０` は `A1:F30`。数字は `[0-9]` で見る）。**名前付き範囲は不可**（範囲が決まるのに Excel への問い合わせが要り、別のシートや別のブックを指しうるため、「このシートの値だけを渡す」という選択が崩れる）。シート名つき（`Sheet1!A1`）・複数領域・列行の範囲外も不可。不正な入力は、入力欄の下に理由（日本語 1 文）を出し、**依頼文には入れない**（それまでの範囲も取り消し、そのシートの値は渡さない。画面に見えている入力と実際に渡るものを食い違わせない）。範囲が空のままのときも渡さず、その旨を入力欄の下に出す。
- 行数 N は 0〜100（入力欄で検証する。範囲外・整数以外は理由を出して保存しない）。設定 `Vba.WorkbookInfoSampleRows`（既定 5、範囲 1〜20）は、「見出し＋N 行」を選んだときの N の既定と、移行のときの N。セル内の長い文字列は `Vba.WorkbookInfoMaxCellChars`（既定 60）で `…` つきで切る。「見出し＋N 行」の列数は `Vba.WorkbookInfoMaxColumns`（既定 30）まで。
- **オフにしたら直ちに捨てる**: 値が渡らない見せ方（構成だけ・出さない）へ戻したシートの値、数式をオフにしたシートの値、全体を「構成だけ」「出さない」へ戻したときの全シートの値を、メモリ上の取得結果から直ちに捨て、コンテキスト収集の窓のプレビュー欄も空にする（取り直しに失敗しても、前回の値が出続けないように。1.2.0 で直した不具合と同じ注意）。設定でブックの情報の取得や VBA 連携をオフにしたら、次のコピーに入らない（出力の直前に設定を引き直す。5.4）。
- **既存の「値の見本」との関係**: ブック全体の値の見本のオン・オフは UI から無くした（4.1 の移行）。UI は 3 状態の行とシートの一覧だけで、値を渡す操作は一か所に一本化されている。

### 5.3 渡し方（コンテキスト収集の項目）

- **ミラーにはファイルを作らない。** コンテキスト収集の画面に、**「ブックの情報」の枠**を 1 つ出す。ファイルのノードではなく、専用の行（`VbaWorkbookInfoRowViewModel`。新設）にして、`Files` の選択集計・除外・差分方式の記憶とは混ぜない。VBA プロジェクトのときだけ表示する。**置き場所は窓の幅で決める**（v0.6）: 広い窓（幅 860px 以上）ではファイル選択タブの中、ファイル一覧の**右の列**（ファイル一覧 5：ブックの情報 4。仕切りで幅を変えられる）。狭い窓（860px 未満）では**「ブックの情報」タブ**（タブの並びは「ファイル選択」「ブックの情報」「プレビュー」）。同じ部品の親を付け替えるだけで、2 つ作らない。通常のプロジェクト（ブックの情報が無い）では、列もタブも出さず、ファイル一覧が全幅になる。
- シートごとの見せ方の一覧（5.2）は、この枠の中の、3 状態の行の下に出す（「内容も出す」のときだけ）。以前は一覧の高さに上限（260px）を置いて内側でスクロールさせたが、v0.6 では上限を外し、**ブックの情報の側の列全体を 1 つの縦スクロール**にした（ブックの情報の枠とリボンの枠を、自然な高さで縦に並べる。入れ子のスクロールにすると、リボンの枠が付いたとき、シート一覧が 2 枚ぶんしか見えなかったため）。シートの行は、行数（または範囲）の入力と「数式も含める」を 1 行に並べ、入りきらなければ折り返す。まだ取得していないときは「取得すると、ここにシートが並びます」と案内する。
- 既存の 3 状態の操作（クリックで 内容も出す → 構成だけ → 出さない と巡る。`ContextCollectViewModel` の `NextState` と同じ順）で選ぶ。選んだ状態は `VbaLink.WorkbookInfoState` に保存する（`ProjectStore.UpdateAsync`。`PersistFileStatesAsync` と同じ作法）。**既定は「内容も出す」**（5.1 のうち値の見本を除いたものが出る）。
- 行には、取得日時、取得できなかったときの理由、値が渡るシートがある注意（5.2）を併記する。値が渡る注意は、スクロールで見えなくならないよう、枠の上のほう（取得状況の下）に置く。**狭い窓でブックの情報がタブへ移っているあいだは、ファイル選択タブの先頭にも 1 行（「ブックの情報: 内容も出す　シートの値: 1 枚のシートの値が AI へ渡ります（集計）」。「「ブックの情報」タブで変えられます」の案内つき）を出し、値が渡る注意を、どのタブを見ていても常に出す。**「出さない」のときは Excel に問い合わせない。
- **依頼文コピー**: `{{files}}` などと同じ要求（`ContextRequest`）に、ブックの情報の文を載せる（`ContextRequest.WorkbookInfoText`。新設）。テンプレート変数 **`{{workbook}}`** を新設し、展開結果は 5.7 の形（見出し `# ブックの情報` から）。
  - 本文に `{{workbook}}` が無いテンプレートでは、`{{files}}` を自動で足す仕組み（`PromptTemplateRenderer` の `appendFilesIfAbsent`）と同じ考え方で、**「# 対象ファイル」の直前**（観点の文があればその前）に差し込む（6.3 の差し込み規則を共有）。テンプレートの本文そのものは書き換えない。
  - 「出さない」、VBA でない、取得に失敗して前回の成功分も無い、のいずれかのときは何も出さず、見出しだけが残らない。
- **コンテキスト収集の窓のコピー・プレビュー・ファイル保存**（`ContextCollector.CollectAsync`）: 「# 前提」の直後・プロジェクト構成の前に差し込む。窓の出力には「# 対象ファイル」の見出しが無いため。
- トークンの推定（`TokenEstimator`）は、ブックの情報（と、v0.5 ではリボン）を含めた展開結果で計算する。
- **リボン（customUI）の行（v0.5）**は、この枠のすぐ下に、同じ作りで並べる（15.5）。v0.6 では、ブックの情報の枠とリボンの枠を 1 つの部品（列）にまとめ、広い窓でもタブでも、2 つの枠が一緒に動く。

### 5.4 取るタイミング

既存の自動 Pull（VBA連携仕様 7.2）と同じ契機で、**Pull の直後**に取る。

- `ContextCollectViewModel.InitializeAsync`／`RefreshAsync` の走査の前（Pull の直後）。
- 依頼文コピーの組み立て（`PromptCopyViewModel` の `RefreshAsync`。走査済みでも、ドロップダウンを開くたびの組み立てで取る）。
- 取得は、`ContextCollectViewModel.PullFromExcelAsync` と並べて `FetchWorkbookInfoAsync`（新設）を呼ぶ。窓口は `MainViewModel.CreateVbaContextPull` と同じ作りで `MainViewModel` が `ContextCollectViewModel` に渡す（`VbaWorkbookInfoFetchAsync` デリゲート。新設）。
- 取得しない条件: VBA プロジェクトでない、`Vba.Enabled` が false、`Vba.CollectWorkbookInfo` が false（9章）、項目の状態が「出さない」。いずれも Excel を呼ばない。
- 同じ組み立ての中で重複して取らない（取得は 1 回の契機につき 1 回。結果は `ContextCollectViewModel` が保持して、テンプレート 1 件ごとの展開では使い回す）。

### 5.5 読み取り（IVbaBridge への追加）

```csharp
/// <summary>ブックの構造（シート・テーブル・名前・参照設定。options のシートごとの見せ方で、値が渡るシートだけセルの値も）を読む。書き込みはしない。</summary>
Task<GraftResult<VbaWorkbookInfoSnapshot>> ReadWorkbookInfoAsync(
    string workbookFullName, VbaWorkbookInfoOptions options, CancellationToken ct = default);
```

- `NullVbaBridge` は E706。`FakeVbaBridge` には、返すスナップショット、失敗させる `GraftIssue`、遅延、呼び出し回数と最後に受け取った `options`、**値を実際に読んだシートの記録（`InfoValueReads`。値が要るシートだけ読んだことを確かめる）、テーブルを読んだシートの記録（`InfoTableReads`）、シートの全セル（`SheetGrids`。大きなシートで「全部」「範囲を指定」を確かめる）**の口を足す（v0.4。Fake も `VbaSheetReadPlanner` の計画で値を詰める）。
- **読み方（`WindowsVbaBridge.Info.cs`）**。`StaWorker` の 1 呼び出しの中で、シート単位に一括で読む。セルを 1 つずつ読まない。
  1. ブックを引く（VBA連携仕様 5.2 の ROT。見つからなければ E804）。
  2. `Worksheets` を列挙する（グラフシートは対象外）。**先に、全シートの `Name`・`CodeName` だけを列挙して取得結果（`AllSheets`）に載せる**（セルは読まない。値を読まないシートや、時間切れ・読み取り失敗・枚数の上限で読めなかったシートの名前も分かり、「出さない」のシートを指す名前・注記を確実に伏せられる）。そのうえでシートごとに、`Name`・`CodeName`・`Visible` と、`UsedRange` の `Rows.Count`・`Columns.Count`・`Address(False, False)` を取る（開始の行・列は `Address` から読むので、`Row`・`Column` は取らない）。空のシート（`UsedRange` が A1 だけで `Value2` が `Empty`）は使用範囲 null とする。
  3. 値（v0.4）: **見せ方が値の渡るシートだけ**、`VbaSheetReadPlanner.Plan` の計画（先頭のセルの行・列と、行数×列数）のとおりに、`Cells.Item(行, 列)` から `Resize(行数, 列数)` した範囲の **`Value2` を 1 回**で読み、2 次元配列（`object[,]`、下限 1）を受ける（1 セルだけのときは配列ではなくスカラーが返るので、両方を扱う）。数式を含める指示のシートは、同じ範囲の `Formula` も 1 回読み、`=` で始まるセルは `=式 → 値` の形にする。「見出し＋N 行」は先頭の 1+N 行を最大 `MaxColumns` 列まで、「全部」は使用範囲を 500 行・50 列まで、「範囲を指定」は範囲と使用範囲の共通部分を同じ上限まで。**構成だけ・出さないのシートでは、この手順の COM 呼び出しを 1 回も行わない**。
  4. 計画の詰め直し（`VbaSheetReadPlanner.Assemble`）: 「見出し＋N 行」は先頭行を `HeaderRow`（数式なし）、続く行を `SampleRows` に、「全部」「範囲を指定」は `VbaSheetBlock`（読んだ値と、切る前の行数・列数）にする。
  5. `ListObjects` を列挙し（**「出さない」のシートは読まない**）、`Name`・`Range.Address`・`HeaderRowRange.Value2`（列名を 1 回で）。`Names` を列挙し、`Name`・`RefersTo`（シート限定かは、`Name` の文字列 `Sheet1!税率`・`'売上 2026'!税率` から分けるので、`Parent` は読まない）。`_xlnm.*`（印刷範囲など）と `_FilterDatabase` は除く。
  6. 参照設定（`IncludeReferences` のとき）: `VBProject.References` の `Name`・`Description`・`FullPath`・`BuiltIn`・`IsBroken`。**`Workbook.VBProject` に触れない（E802）ときは参照設定だけを省き**、`Omitted` に理由を残す。シート・テーブル・名前は `VBProject` に依存しないので読める。ロック中（E803）でも `References` は読めない見込みなので同様に省く（実機で要確認）。
- **`VbaCellText.Render(object? value2, int maxChars)`**（`Core/Vba`。純ロジック）がセルの値を文字列にする: `Empty`/null → 空、`string` → 改行・タブを空白 1 つに畳んで `maxChars` で切る、数値 → 不変カルチャで、真偽値 → `TRUE`/`FALSE`、**エラー値（`Value2` では HRESULT に近い負の整数で返る）→ `#N/A` 等の名前**（`-2146826246` → `#N/A`、`-2146826281` → `#DIV/0!`、`-2146826273` → `#VALUE!`、`-2146826265` → `#REF!`、`-2146826259` → `#NAME?`、`-2146826252` → `#NUM!`、`-2146826288` → `#NULL!`。値は実機で確かめる。付録B）。日付は `Value2` では日付の連番（`double`）になり、日付かどうかは表示形式を読まないと分からない。**この版では連番のまま出し、日付の判別はしない**（表示形式の取得は COM 呼び出しが増えるため。付録A-7）。

| 名前付き範囲 | 200 | 超過分を省く |
| 参照設定 | 100 | 超過分を省く |
| 出力全体の文字数 | `Vba.WorkbookInfoMaxChars`（20000） | `VbaWorkbookInfoFormatter` が末尾から切る。切る順は **シートの値（末尾のシートから。1 枚を落とす前に入る行数まで残す）→ 参照設定 → 名前付き範囲 → テーブルの列名 → シート**（構成ほど後まで残す）。切ったら末尾に「（長いため一部を省略しました）」 |

- **時間切れ**: 呼び出し全体は既存の `Vba.CallTimeoutMs`（既定 30 秒）に従う（5.3 のスレッドの捨て方も同じ）。それとは別に、ブリッジはシートの合間に `options.Budget`（`CallTimeoutMs` の 2/3）を見て、**超えていたらそこまで読めた分を返し**、`Omitted` に「時間がかかったため、シート X 以降は読めていません」を残す。モジュールの書き込みと違い、途中までの結果に危険は無いため。1 呼び出しが戻らない（マクロ実行中・モーダル表示中）場合は、全体の時間切れで E805。
- **E813 は使わない。** 読み取りは `VBProject.Mode`（デザインモード）を要求しない。マクロの実行中に Excel が呼び出しを拒否したら、`ComRetry` の再試行のあと E805。

### 5.6 失敗時の扱い（収集を止めない）

| 状況 | 結果 | 依頼文・収集 |
|---|---|---|
| ブックが開いていない（E804）、Excel が応答しない（E805）、通信の失敗（E801）、保護ビュー・ロック等の利用不可 | 取得を諦める | 前回成功した分が同じセッション内にあれば、**それを使い**、見出しの行に「（取得日時: …。最新を読めていません）」を添える。無ければ何も出さない。どちらも警告を 1 件出す |
| 一部だけ読めた（参照設定のみ E802、時間切れ、上限） | 読めた分を使う | `Omitted` を E815（警告）にして出す |
| すべて読めた | — | 警告なし |

- 警告の出し先は、自動 Pull の警告と同じ（コンテキスト収集の窓ではステータス欄 `StatusMessage`、依頼文コピーではドロップダウンの状況欄）。Pull の警告と同時に出るときは 1 行に連結する。
- 値が渡る見せ方を選ぶ確認ダイアログ（5.2）以外に、ブックの情報の取得でダイアログを出さない（衝突ダイアログのようなものは無い）。

### 6.2 画面

- **置き場所は 2 か所**: 依頼文コピーのドロップダウン（`PromptCopyViewModel` の画面）と、コンテキスト収集の窓。どちらも同じ `PromptFocusPanel`（新設）を置き、**同じ選択状態**（`ContextCollectViewModel.Focus`。`PromptFocusSelectionViewModel`）を共有する。片方で選べば、もう片方にも反映される（`Context` を両者が共有しているのと同じ）。
- 5 つの見出しごとにチップを折り返しで**最初からすべて並べる**（最初から隠さない。v0.5 までは「折りたたまない」と書いていた。たためるのは、収集の窓で利用者がたたむボタンを押したときだけ。下の「たたむ」ボタン）。チップは `ToggleButton` 相当で、複数選べる。VBA の見出しは VBA プロジェクトのときだけ出す。自作の観点があれば末尾に「自分用」の見出しを出す。
- **見出しのかたまり（見出し＋そのチップ）は、縦に積まずに横へ流し、入りきらなければ折り返す**（v0.6）。収集の窓の既定の幅（960px）で、通常のプロジェクトは 2 行、VBA は 3 行になる（以前は縦に積んで 5 行・6 行）。幅の狭い置き場（依頼文コピーのドロップダウン）では、かたまりが 1 行に 1 つしか入らないので、従来どおり縦に積まれる（見た目は変わらない）。収集の窓だけ、見出しの文字の幅を 64px 固定から文字の幅に詰める（64px のままだと、760px の窓で 2 かたまりがぎりぎりになり、フォントが少し違うだけで 1 行に 1 つへ戻るため）。
- **「たたむ」ボタン**（v0.6。収集の窓だけ。`PromptFocusPanel.IsCollapsible`）: 見出しの左に置く。**既定は必ず開いた状態**で、**たたんだ状態は記憶しない**（窓を開くたびに開いた状態へ戻る。`IsCollapsed` は画面の状態で、ViewModel にも設定にも持たない）。たたむと、チップの一覧を隠し、見出しの行に「選んでいる観点の名前」（「読みやすく・不具合を直す・速く」。無ければ「選んでいません」）を 1 行で出す。**たたんでも選択は変わらない**（見出しの数と「すべて解除」も使える）。つまり、**全チップは最初から並び、たためるのは利用者の操作だけ**。読み上げ名は状態で変える（開いているとき「依頼の観点の一覧をたたむ」、たたんでいるとき「依頼の観点の一覧を開く」）。Tab で届き、Enter・Space で開閉する。依頼文コピーのドロップダウンにはこのボタンを出さない。
- チップにマウスを乗せると一言の説明を出す（`HelpTip.Standard`／`Detailed` の作法。`SettingsHelpTipCoverageTests` の「操作可能なコントロールに HelpTip が付いている」検査に通すこと）。AI に渡す指示文は画面に出さない。読み上げ用の名前は「チップ名（選択中／未選択）」。
- パネルの見出しに、選択数（「依頼の観点 3」）と「すべて解除」のボタンを置く（「すべて解除」は見た目は見出しの行の右端。Tab の順は、画面の読み順に合わせて、チップのあとになる）。
- チップを切り替えたら、依頼文コピーのトークン推定を再計算する（「選んだファイルも付ける」の切り替えと同じ `RefreshAsync(keepSelection: true)`。1 回の計算では同じ選択で通す）。
- **最後の選択はプロジェクトごとに記憶**する（`ProjectOverrides.PromptFocusIds`）。プロジェクトを開き直したとき、前回の選択を復元する。保存は選択が変わってから 500ms 後にまとめて 1 回（`ProjectStore.UpdateAsync`。古いスナップショットで丸ごと上書きしない）。

### 6.3 展開の規則

- 新しいテンプレート変数 **`{{focus}}`**（展開結果は 6.4 の形）。**何も選ばれていなければ空**で、前後の空行を詰めて痕跡を残さない。
- `{{focus}}` を含まないテンプレートで 1 つ以上選んだ場合は、次の順で差し込み位置を決める（`{{files}}` の自動付加と同じ考え方。テンプレートの本文そのものは書き換えない）。
  1. テンプレート本文の「`# 対象ファイル`」だけの行の**直前**。
  2. 無ければ、`{{files}}` を含む行の直前。
  3. 無ければ、ファイル部分が自動付加されるとき（`appendFilesIfAbsent`）は、付加する「# 対象ファイル」の直前。
  4. 付加するファイルも無いときは、末尾。
- `{{workbook}}`（5.3）があるときは、その**直後**に置く（v0.2。前提 → ブックの情報 → 観点 → 対象ファイル の順を守るため。冒頭の変更点の表）。
- **展開の実装上の約束**: 観点とブックの情報の文は、ほかの変数（`{{tree}}`・`{{files}}`・`{{standingContext}}` など）の展開が**済んだあと**に差し込む。本文中の `{{focus}}` を先に私用領域の文字のマーカーへ置き換えておき、最後にマーカーを文に置き換える。理由は 2 つ: ファイルの中身に `{{focus}}` という文字列があっても置換されないこと、自作の観点の文に `{{files}}` と書かれていても再展開されないこと。
- コンテキスト収集の窓のコピー・プレビュー（`ContextCollector.CollectAsync`）では、「# 前提」の直後に、ブックの情報 → 観点の順で差し込む（`ContextRequest.FocusText`。新設）。
- 画面の並び順で連結する（クリックした順ではない）。同じ選択なら、いつも同じ依頼文になる。

```
- 渡したファイルの中だけを変える。確かめられないものは推測で書かず、質問する。
```

### 6.5 指示文（組み込み）

#### 6.5.1 汎用（全プロジェクト）

統合したチップは、元の複数の観点の要点を重複なくまとめた。`Body` に入れる全文は次のとおり。

**読みやすく**（コードを整える＋シンプルにする）
```
## 読みやすく
- 目的: 読みやすさを上げ、同じ動作をより少ない概念・行数で書く。動作は一切変えない。
- やること: 字下げ・空行・1行の長さをそろえる。意味の分かりにくい名前を内容が分かる名前にする（外部から呼ばれる公開名は除く）。重複した式を変数にまとめる。マジックナンバーを名前付き定数にする。使われていない変数・引数・分岐・import・コメントアウトされた古いコードを消す。1か所でしか使わない抽象化（インターフェース・基底クラス・ラッパー）と、標準ライブラリで置き換えられる自前の処理は取り除く。
- やらないこと: 処理の順序・条件・戻り値・例外の種類の変更、ファイルの分割や移動、新しいライブラリの導入、長い1行や入れ子の三項演算子への詰め込み。
- 既存の書き方（命名規則・括弧の位置・引用符）に合わせ、ファイルの中で書き方を混在させない。
```

**保守しやすく**（保守性を高める＋古い書き方を新しくする）
```
## 保守しやすく
- 目的: 次に直す人が、安全に・速く変更できる形にする。外から見た動作は変えない。
- 長い関数（目安 50 行以上）を、意味のまとまりごとに名前の付いた関数へ分ける。深い入れ子は早期リターンで浅くする。同じ処理の重複を1か所にまとめる。グローバルな状態や隠れた依存は引数で渡す形にする。設定値・文字列の決め打ちは定数か設定に寄せる。
- 非推奨の API や古い構文は、プロジェクトが使っている言語・ライブラリの版で使える今の書き方に置き換え、「旧 → 新」を一覧で示す。版が分からないときは、置き換える前に質問する。
- 判断の理由が読み取れない箇所には「なぜそうするか」のコメントを1行添える。
- 変更が大きくなる場合（目安: 3 ファイル以上、または 200 行以上）は、コードを出す前に分割の計画を箇条書きで示し、確認を求める。
- 公開されている関数・クラス・設定項目の名前と引数は変えない。変える必要があるときは理由を書き、呼び出し側もすべて直す。
```

**変更は最小限**
```
## 変更は最小限
- 目的: 依頼の達成に必要な行だけを変え、差分を小さくする。
- 整形・命名・並び順など、依頼と関係のない変更はしない。気付いた改善点は、コードを変えずに最後に箇条書きで挙げる。
- 既存の構造・書き方を活かし、新しい関数やファイルを足すのは避けられない場合だけにする。
```

**不具合を直す**（不具合を探して直す＋非同期・並行処理）
```
## 不具合を直す
- 目的: 渡したコードの中の不具合を見つけて直す。
- 次の観点で確かめる: 境界値（0 件・1 件・最大）、null／空文字／未初期化、型の変換と桁あふれ、ループの終了条件、例外が起きたときの後始末、日付・時刻・文字コード。非同期・並行処理があるときは、共有状態への同時アクセス、await の付け忘れ・同期的な待ち（.Result／.Wait など）、キャンセルと時間切れの扱い、UI スレッドでの重い処理、例外が拾われずに消える処理、資源の解放順も確かめる。
- 見つけた不具合ごとに「どの入力で（どの順序で動くと）・何が起き・なぜか」を1〜2行で書いてから直す。確信が持てないものは直さず「疑わしい点」として挙げる。
- 直すのは不具合の箇所だけにする。ついでの整形や命名の変更はしない。
- 不具合が見つからなかった場合は、無理に変更を出さず、確かめた観点を挙げて「見つからなかった」と答える。
```

**エラーに強く**（エラー処理＋入力の検証とエッジケース＋ログ）
```
## エラーに強く
- 目的: 想定外の入力や失敗で、データを壊さず・原因が分かる形で止まるようにする。正常な場合の動作は変えない。
```

## 7. 機能 C: 反映前の自動控え

### 7.1 何をするか

「Excel へ反映」で Excel 側が上書きされる**直前**に、上書きされる各モジュールの Excel 側の本文を、毎回 `.rescue/` に世代つきで残す。残す場面は `VbaSyncService.PushCoreAsync` を通るすべての反映（手動の「Excel へ反映」、適用後の自動 Push、取り消し・復元後の Push、衝突の「Graft 側で上書き」、D の保存時の自動反映）。

### 7.2 控えを残す手順（`PushCoreAsync`）

1. 書き込みの対象（`writes`）のうち、**既存のモジュールを上書きするもの**（`VbaSyncAction.Push`）が対象。`PushCreate`（Excel に無い新規）は残す本文が無いので対象外。
2. **衝突の上書き（`VbaSyncAction.Conflict` の「Graft 側で上書き」）は、従来どおり `KeepRescueCopyAsync` が `Legacy` の控えを残す**ので、自動控えは重ねて作らない。
3. 控えの本文は、`BuildPlanAsync` が既に読んでいる `work.Excel[相対パス].Code` を使う（**追加の COM 呼び出しはしない**）。
4. 同じモジュールの最新の `Auto` の控えと本文のハッシュ（`VbaTextNormalizer.Hash`）が同じなら、書かない（同じ内容の世代が積み上がらないように）。
5. `<モジュール名>-<yyyyMMdd-HHmmss>-auto.txt` を書く（4.4。同じ秒は連番）。時刻は `VbaSyncService` の `_clock`。
6. **全モジュールの控えを書き終えてから** `WriteComponentsAsync` を呼ぶ。
7. 控えを書けなかったとき（ディスクの空き不足など）: **反映は止めず**、そのモジュールには E816（警告）を出して続ける。理由は、通常の反映では Excel 側の本文は直前の同期の内容と同じであることがほとんどで（変わっていれば衝突として別に止まる）、控えを書けないだけで利用者の作業を止めるのは釣り合わないため。衝突の上書きだけは従来どおり、控えを書けなければ上書きしない（失われるのが利用者の VBE の編集だから）。
8. 控えを書いたあと、掃除（7.3）を呼ぶ。掃除の失敗は反映の結果に影響させず、ログ（`Logger`）に警告として残す。

### 7.3 世代数・容量の上限と掃除

| 規則 | 値 | 設定 |
|---|---|---|
| 1 モジュールあたりの `Auto`＋`Mirror` の世代数 | 20 | `Vba.RescueMaxGenerations`（範囲 1〜200） |
| 1 プロジェクトの控え全体の容量 | 50 MB | `Vba.RescueMaxTotalMB`（範囲 5〜1000） |

`VbaRescuePruner.Plan(entries, maxGenerations, maxTotalBytes)`（新設。純ロジック）が、消すファイルの一覧を返す。

1. モジュールごとに、`Auto` と `Mirror` を新しい順に並べ、`maxGenerations` を超えた古い方を消す。
2. 全体（`Legacy` を含む）の合計が `maxTotalBytes` を超えるなら、`Auto` と `Mirror` を**古い順**に、合計が収まるまで消す。
3. **`Legacy` は自動では消さない**（容量の計算には入れる）。`Legacy` だけで上限を超えたときは、何も消さずに一覧の画面で警告する。
4. **各モジュールの最新の `Auto` 1 件は、容量を理由に消さない**（容量が小さすぎる設定でも直近の控えは残す）。
5. 掃除は、控えを書いた直後と、「Excel 側の控えを見る」を開いたときに行う。起動時や定期の掃除はしない。実際の削除は `ITrashService` ではなく通常の削除（控えを消すだけで、利用者の作成物ではないため）。削除に失敗したファイルは次回に回す。
6. プロジェクトを削除しても、控えは消さない（既存の `ProjectStore.RemoveAsync` の扱いのまま。Excel 側から失われた本文を含みうる）。

### 7.4 一覧・差分・戻す

- 入口: プロジェクトの右クリック「**Excel 側の控えを見る…**」（VBA プロジェクトのときだけ）とコマンドパレット。ファイルを見るだけなので、Excel が開いていなくても、`Vba.Enabled` が false でも開ける（戻すのは 7.5）。
- `VbaRescueWindow`（新設）: 左にモジュールごとの控えの一覧（日時、種別〔「反映前の自動控え」「上書き前」「戻す前のミラー」。`Legacy` は E809 の書き戻し失敗も同じ表示〕、行数、サイズ）、右に**選んだ控えと現在のミラーの差分**。差分は `DiffViewModel`（左右比較）で、`VbaConflictDiff` と同じく 2 つの本文から `BlockPlan` を作る。
- ボタン: 「**ミラーへ戻す**」「控えを削除」「保存先を開く」。
- 履歴（リビジョン）とは混ぜない（付録A-8）。戻した結果は履歴に記録されず、`Logger` に `vba-rescue` として残す。

### 7.5 戻す: ミラーに取り込む形にする

「戻す」は、**控えの本文をミラーのファイルへ書く**（Excel には書かない）。その後、ミラーは「未反映」（`VbaSyncAction.Push`）になり、戻した内容は利用者が「Excel へ反映」で送る。

1. 対象のミラーのファイルに**未保存のタブ**があれば、Pull と同じ確認（`BeforeApplyAsync` と同じ保存確認）を出す。断られたら戻さない。
2. 現在のミラーの本文が控えと違うなら、その本文を `Mirror` の控え（`-mirror.txt`）として先に残す。**これを残せなければ、戻さない**（E816）。
3. ミラーのファイルに書く（`FileTextIO.WriteAsync`。既存のファイルは `TextShape` を保ち、無ければ UTF-8・BOM なし・CRLF）。**同期基準（`VbaSyncStateStore`）は触らない**。ミラーだけが変わるので、`VbaSyncPlanner` が自然に「未反映」と判定する。ミラーのファイルが無い（削除保留の）モジュールなら、ファイルが再び現れて削除保留が解除される。
4. 書いたあと、ステータスに「戻しました。履歴には記録されません。Excel に送るには『Excel へ反映』を押してください」と出し、「今すぐ Excel へ反映」のボタンを添える（押すと、そのモジュールだけ `PushAsync`。Excel 側が変わっていれば衝突ダイアログ）。
5. エディタで開いているタブは、既存の `FileWatchService` の仕組みで再読込される（VBA連携仕様 7.2）。
6. **Excel へ直接書く形にしない理由**: 直接書くには、E813（実行中）・CP932・衝突検査・同期基準の更新といった Push の安全装置を別の経路で作り直す必要がある。ミラーを経由すれば、すべて既存の Push が担う（付録A-4）。

## 8. 機能 D: 保存時の自動反映

### 8.1 動作と既定

- `VbaLink.AutoPushOnSave`（既定 **false**）。プロジェクトの右クリックのチェック項目「**保存したらそのモジュールを Excel へ反映する**」で切り替える（`AutoPushAfterApply`・`SaveWorkbookAfterPush` と同じ並び。`Vba.Enabled` が false のときは無効）。
- オンのとき、エディタで **VBA のミラー内の同期対象のモジュール**を保存すると、そのモジュールだけを Excel へ送る。

### 8.2 契機: 保存の通知から、別の経路で動かす

- **`DocumentSession` と保存経路には触れない。** 契機は、保存が成功したあとに `EditorPaneViewModel` が上げる `TabSaved`（`SaveActiveAsync`・`SaveAllAsync` の成功後）。`MainViewModel`（新ファイル `MainViewModel.VbaSaveSync.cs`）がこれを購読する。
- ハンドラが**同期で行う仕事は、条件の判定とキューへの追加だけ**（数マイクロ秒）にする: 現在のプロジェクトが VBA でアクティブ（`IsVbaActive`）、`AutoPushOnSave` がオン、保存したファイルがミラーの中、`VbaMirrorLayout.TryParse` が成功する同期対象、適用中（`IsApplyInProgress`）でない。条件を満たしたら `VbaSaveCoalescer`（8.3）に相対パスを渡して**すぐ戻る**。ファイルの読み込み・ハッシュ・COM は、すべてキューの先の非同期の処理で行う。
- 保存した瞬間に適用中のときは何もしない（適用後の Push が、Push 判定のモジュールも同梱する。VBA連携仕様 7.2b）。
- 保存の通知からキューに入ったあと、送る時点（静かになってから）で適用中、または取り消し・復元の後の反映の最中（`_isVbaPushing`）なら、終わってから送る（溜め直して、もう一度静かになるのを待つ）。手動の「Excel へ反映」の最中（`IsWritingToExcel`）は、`VbaSyncService` のゲートで順番に並ぶので、ここでは止めない。
- 経路の対象外（付録A-9）: タブを閉じるときの保存、適用前の保存確認（`SaveFilesAsync`）、エクスプローラー経由の変更。これらは通常どおり「未反映」のバッジに残り、手動の「Excel へ反映」か次の保存で送る。

### 8.3 まとめ・間引き（`VbaSaveCoalescer`。純ロジック）

- 同じモジュールの保存が続いたとき（`SaveAllAsync` や連続保存）は、**最後の通知から 500ms 静かになったら 1 回**だけ送る。複数のモジュールが溜まったら、1 回の `PushAsync(project, only: 溜まった相対パス)` にまとめる。
- 反映の最中に来た保存は、終わったあとに続けて 1 回処理する（同時に 2 つ走らせない。`VbaSyncService` の `_gate` による直列化にも任せる）。
- 時刻はテストで差し替えられるよう、時計と遅延を注入する。
- 実装: `VbaSaveCoalescer(flush, quiet, clock, delay, onError)`（`Core/Vba`）。`Add(projectId, relativePath)` は表を更新するだけですぐ戻る。送信（`flush`）は 1 つのポンプだけが呼ぶので重ならず、`flush` が false を返したら「いまは送れない」として溜め直す。例外は `onError` に渡して次へ進む（ポンプが止まって以後の保存が送られなくなるのを避ける）。ポンプは最初の `Add` を呼んだ同期コンテキスト（UI スレッド）で始まり、送信の続きもそこへ戻る。

### 8.4 1 モジュールだけを読む（性能と Excel の負荷）

現在の `VbaSyncService.BuildPlanAsync` は、`only` で対象を絞っても、Excel の**全モジュールを読み**（`ReadComponentsAsync(…, null, …)`）、ミラーの**全ファイルを読む**（`ReadMirrorAsync`）。保存のたびにこれを行うと、大きなブック（約 100 モジュール）では Excel を数秒占有し、利用者の操作を妨げる。そこで、**対象を絞った読み取りを新設**する。

- `BuildPlanAsync` に「名前で絞る」引数を足し、`scope` があるときは `ReadComponentsAsync(workbook, names: 対象のコンポーネント名)` と、対象のミラーファイルだけの読み取りにする（`IVbaBridge.ReadComponentsAsync` は既に `names` を受ける）。`scope` が null のときの動作は変えない。
- 絞ったときの計画は、対象のモジュールの判定だけを返す（`VbaSyncPlanner` の判定表はそのまま）。削除保留や記録の破棄など、全体を見ないと出せない判定は、絞った読み取りでは行わない。
- 手動の「Excel へ反映」・適用後の Push は従来どおり全体を読む。**絞る読み取りは D だけが使う**（手動の Push に影響させない）。
- 実装: `VbaSyncService.PushSavedAsync(project, savedPaths)`（D 専用。`IsWritingToExcel` の旗も立てる）→ `PushCoreAsync(narrowRead: true)` → `BuildPlanAsync(narrowRead: true)`。Excel は対象のコンポーネント名だけを `ReadComponentsAsync(names)` で読み、ミラーは対象のファイルだけ読む（ディレクトリを走査しない。対象外のファイルへの E810 は出さない）。計画の入力（ミラー・Excel・同期状態）を対象に絞る既存の仕組みのおかげで、対象外のモジュールの記録を破棄したり、削除保留の印を付けたりしない。
- 反映前の自動控え（7章）の掃除は、D では 30 秒に 1 回に間引く（保存のたびに控えのフォルダを走査・削除しないため。上限は目安なので数十秒のあいだ少し超えても実害が無く、超過分は次の掃除でまとめて消える。手動の反映は従来どおり毎回掃除する）。

### 8.5 衝突・エラーの扱い（作業を止めない）

- **ダイアログを出さない。** 保存のたびに割り込まないため。
- 衝突（`VbaSyncAction.Conflict`）: **送らない**。その場でバッジの印だけ付ける（**通知は出さない**。保存のたびに割り込まないため）。`VbaBadgeLogic` に「保存時の自動反映をしなかった衝突 N」を足し（メモリだけ。起動をまたいで残さない）、名前の下の補足行とツールチップに出す。手動の「Excel へ反映」の衝突ダイアログ（VBA連携仕様 7.5）で解決する。次に同じモジュールが衝突なしで反映できたら印を消す。手動の取込・反映で衝突を解決した（または衝突でなくなった）モジュールの印も消す（`ProjectPaneViewModel.MarkVbaSaveConflicts`・`ClearVbaSaveConflicts`。メモリだけ）。
- E805（応答しない）、E813（マクロの実行中・中断中）、E804（ブックが開いていない）、E801、E811（CP932）、E808: **通知だけ**（ステータスバーの数秒で消える通知。`ShowApplyUndoNotice` と同じ作法）。内容は「E813 マクロの実行中: 保存のみ。Excel へは未反映」の形（v0.3。理由を先頭に出す。E817 の趣旨を、理由のコードと「保存のみ・未反映」で伝える）。ファイルは保存済みで「未反映」のまま残る。
- 通知の理由は、ステータスバーの幅（`MaxWidth` 520px）で省略されても読めるよう、<b>文の先頭に置き</b>、エラーの見出しをそのまま使わず短い言い回しにする（`VbaSaveNoticeThrottle.ShortReason`。例: E813「マクロの実行中」、E805「Excel が応答しません」、E804「ブックが開いていません」）。ステータスバーの通知にはツールチップで全文も出す。
- 通知は**同じコードなら 60 秒に 1 回**までに間引く（`VbaSaveNoticeThrottle`）（連続保存で通知が積み上がらないように。E811 は文字コードの問題が直るまで毎回出るので、モジュール名つきで 1 回に絞る）。
- 自動で再試行しない（マクロ実行中などに保存のたびにタイマーで叩き続けない）。次の保存か手動の反映で送る。
- 成功したら通知は出さず、プロジェクトペインのバッジの件数（未反映）が減るだけにする。`SaveWorkbookAfterPush` がオンなら、自動反映のあとにブックも保存する（読み取り専用なら E807。通知）。
- 反映の前に、7章の自動控えが働く（同じ `PushCoreAsync` を通るため）。

### 8.6 10 万行の性能の約束への影響

- 保存経路（`DocumentSession.SaveAsync`）、`EditorPaneViewModel.SaveActiveAsync`・`SaveAllAsync` のコードは変えない。`TabSaved` の購読者が 1 つ増えるだけで、ハンドラは 8.2 のとおり即座に戻る。
- VBA でないプロジェクト、`AutoPushOnSave` がオフのプロジェクトでは、ハンドラは最初の条件判定で戻る。
- テスト: `PerformanceTests` が引き続き通ること、および「`FakeVbaBridge` を 10 秒遅らせても、`TabSaved` のハンドラが 50ms 以内に戻る」こと（11.2）。

## 15. 機能 E: リボン（customUI）の読み取り（v0.5）

### 15.1 目的と範囲

- **目的**: Excel のリボン（タブ・グループ・ボタン）は、ブックの中の **customUI**（XML）で定義され、ボタンを押したときに呼ぶ VBA の手続き（コールバック）の名前もその XML に書かれる。AI がこの XML と、呼び先の VBA の有無を知らないまま「リボンにボタンを足して」に答えると、存在しない `idMso`、名前空間の合わない XML、呼び先の無い `onAction` を書く。ブックを zip として開いて XML を取り出し、貼り付ける手間をなくし、AI に**今の定義**を渡す。
- **対象**: 保存済みの .xlsm／.xlam／.xlsb（zip ＝ Open XML パッケージ）。VBA プロジェクトのときだけ項目を出す。VBA 連携が使えない環境（Windows 以外）では項目を出さない（ブックの情報と同じ条件。読むのはファイルだけで COM は使わないが、機能の入口をそろえる）。
- **非対象**: 書き換え（16 章。次の版）、.xls（古い形式）、customUI 以外の部品（リボンの画像〔`customUI/_rels/*.rels` が指す画像〕、カスタム XML パーツ）、Excel で編集中の**未保存の変更**、リボンの実際の見た目。
- **読むのは最後に保存した内容である**。Excel で開いて編集していても、読むのはディスク上のファイルなので、保存していない変更は入らない。このことを、画面の行（取得日時とファイルの更新日時）と依頼文の冒頭（15.5）、取扱説明書に明記する。AI が「いまの画面と同じ」と思い込んで古い XML を前提に答えるのを防ぐため。

### 15.2 パッケージの読み取り（`VbaRibbonPackageReader`）

Windows と Linux で同じに動く（Excel を呼ばず、ファイルを読むだけ）。

1. 拡張子が `.xls`／`.xla`／`.xlt`、またはファイルの先頭が OLE の複合ファイルのしるし（`D0 CF 11 E0 A1 B1 1A E1`）なら、**対象外**（`LegacyFormat`）として知らせる。
2. ファイルを `FileMode.Open`・`FileAccess.Read`・**`FileShare.ReadWrite | FileShare.Delete`** で開く。**Excel が開いている間も読める**ようにするため（共有の指定が足りないと、Excel が書き込み権限で開いているブックは共有違反になる。**実機で要確認**。付録B）。開けなければ、無い（`FileNotFound`）・他のプログラムが使用中か権限が無い（`Locked`）を区別して返す。
3. `System.IO.Compression.ZipArchive`（読み取りのみ。新しい NuGet は使わない）で開く。zip として読めなければ `Corrupt`。
4. 関係の一覧 **`_rels/.rels`** を読み、関係の種類が次のものを探す（`Target` が外部〔`TargetMode="External"`〕のものは除く）。**両方あれば両方読む**。
   - `http://schemas.microsoft.com/office/2007/relationships/ui/extensibility`（新しい形式。通常 `customUI/customUI14.xml`）
   - `http://schemas.microsoft.com/office/2006/relationships/ui/extensibility`（古い形式。通常 `customUI/customUI.xml`）
5. `Target` は部品名に直す（先頭の `/`・`./` を除く、`%20` などのエスケープを戻す、`\` を `/` に）。**パッケージの外へ出る `..` を含むものは使わない**。部品名の大文字小文字は区別しない（OPC の規則）。
6. 見つかった部品を読む。BOM（UTF-8・UTF-16）または宣言の `encoding` に従って文字列にし、先頭の BOM は取り除く。

**結果の種類**（`VbaRibbonReadStatus`）と、画面の 1 行に出す理由:

| 種類 | 意味 | 画面の 1 行 |
|---|---|---|
| `Ok` | 部品を 1 つ以上読めた | 「取得: 日時（ファイルの更新: 日時。最後に保存した内容です）」。一部の部品だけ読めなかったときは、その理由を続ける |
| `NoRibbon` | 読めたが customUI が無い | 「このブックにリボンの設定はありません」（警告にしない） |
| `LegacyFormat` | .xls | 「古い形式（.xls）のブックは、リボン（customUI）の読み取りの対象外です。」（警告にしない） |
| `FileNotFound` | ファイルが無い（移動・削除・改名） | 「ブックのファイルが見つかりません…」 |
| `Locked` | 開けない（使用中・権限） | 「ブックのファイルを開けません（他のプログラムが使用中か、読む権限がありません）。」 |
| `Corrupt` | zip として読めない・`_rels/.rels` が無い | 「ブックのファイルを zip として読めません…」 |
| `PartsUnreadable` | 部品はあるが、すべて読めない（XML が壊れている・DTD を含む・大きすぎる・部品が無い） | 「部品を読めません（部品名: 理由）」 |

**大きさの上限（zip 爆弾への備え。`VbaRibbonLimits`）**: 実物の customUI は多くても数十〜数百 KB なので、部品 1 つの展開後の大きさを **2 MB**、関係の一覧を **256 KB** までとする。**展開しながら読み、上限を超えた時点で読むのをやめる**。zip の見出しに書かれた展開後のサイズは、嘘を書けるので信用しない（見出しで明らかに大きいものを開かない早道には使うが、最終的な上限は実際に読んだ量で決める）。読むのは関係の一覧と customUI の部品だけで、ほかの部品は開かない。上限を超えた部品は、理由つきで「読めなかった部品」になる（ほかの部品は読む）。

### 15.3 XML の解析と構成の取り出し（`VbaRibbonXmlAnalyzer`）

- 解析は `System.Xml.Linq`（`XmlReader` → `XDocument`）。**外部実体の解決を無効にする（XXE 対策）**: `DtdProcessing.Prohibit`、`XmlResolver = null`、`MaxCharactersInDocument` に上限。さらに、解析の前に `<!DOCTYPE` の有無を文字列で見て、あれば「DTD を含むため、安全のため読みません」という理由で読まない（例外の文面は言語で変わるので、理由を確実に伝えるため）。customUI に DTD を使う正当な理由は無い。
- **構成として出す要素**: `id`（無ければ `idQ`）・`idMso`・`label`・コールバック属性のどれかを持つ要素と、`tab`・`group`・`ribbon`・`backstage`・`qat`（属性が無くても骨格として意味がある）。`tabs`・`items` のような入れ物だけの要素は出さず、字下げの深さにも数えない。
- 各要素は、**種類**（要素名。名前空間は付けない）・**id**（`idMso` は `idMso=Copy` の形）・**label**（`getLabel` のように動的なものは無し）・**コールバック**を持つ。
- **コールバック属性**: `on*`（`onAction`・`onChange`・`onLoad`・`onShow`…）と `get*`（`getLabel`・`getEnabled`・`getImage`・`getItemCount`…）と `loadImage`。接頭辞のあとが大文字のものだけ（`one` のような別の属性を取り違えない）。値が空のものは数えない。
- 名前空間（2009/07 の `customui`、2006/01 の旧形式）は区別せず、ローカル名で読む。

### 15.4 コールバックの照合（`VbaRibbonCallbackMatcher`。純ロジック）

構成から集めたコールバックを**名前ごとに 1 件にまとめ**（大文字小文字違いは同じ名前。使われている所は `onAction（button btnRun）` の形で集める）、VBA のミラー（`Modules/`・`Classes/`・`Forms/`・`Documents/` の全モジュール）にある `Sub`／`Function` と照合する。

| 結果 | 条件 | 画面・依頼文の文言 |
|---|---|---|
| `Found` | `Public`（または修飾なし）の `Sub`／`Function` が 1 つ以上ある | 「あります: Module1」（標準モジュール以外は「クラス Foo」のように種類を添える。同名が複数のモジュールにあれば、その旨） |
| `NotPublic` | 同名はあるが `Private`／`Friend` だけ | 「Public ではないため、リボンから呼べません（Module1 の Private）」 |
| `NotFound` | 無い | **「VBA に見つかりません」** |
| `ModuleNotFound` | `Module1.OnBtn` のようにモジュール名を付けたが、そのモジュールが無い | 「VBA に見つかりません（モジュール「Module1」がありません）」 |
| `Unchecked` | ミラーのフォルダを読めなかった | 「VBA のミラーを読めなかったため、照合できていません」（リボンの構成は出す） |

- 大文字小文字は区別しない（VBA の名前は区別しない）。**修飾なしは全モジュールを探し**、`Module1.OnBtn` はそのモジュールの中だけを探す。`プロジェクト名.Module1.OnBtn` のように 3 つ以上つながっていれば最後の 2 つ（モジュール名と手続き名）、`Book.xlsm!Module1.OnBtn` は `!` より前を無視する。
- 手続きの宣言は行頭の `[Public|Private|Friend] [Static] Sub|Function 名前` を行単位で見る。**コメント行（`'`・`Rem`）と `Declare Function`（外部 API の宣言）、`Property` は数えない**。行継続（`_`）で宣言を折り返したものは見落とす（「見つかりません」と出る側＝念のため確認してもらう側の誤り）。完全な構文解析はしない。
- 画面の行には要約（「コールバック N 件（VBA に見つからない・呼べないもの M 件）」と、その名前の先頭 5 件）を出す。

### 15.5 画面と出し方

- **行**: コンテキスト収集の窓の「ブックの情報」の枠のすぐ下（同じ列。広い窓ではファイル一覧の右、狭い窓では「ブックの情報」タブ。5.3）に、同じ作り・同じ操作（クリックで 内容も出す → 構成だけ → 出さない と巡る）の**「リボン（customUI）」の行**を置く（`VbaRibbonRowViewModel`。ファイルのノードではなく専用の行）。VBA プロジェクトのときだけ表示する。取得日時・ファイルの更新日時・理由・コールバックの要約・「**読むのは最後に保存した内容です**」の注意を、常に出す（「出さない」のときは注意を出さない）。（v0.6 で収集画面の配置を作り直し、ブックの情報の枠とリボンの枠は 1 つの列にまとめた。）
- **3 状態**（`VbaLink.RibbonState`。`Full`／`StructureOnly`／`Hidden`。意味はファイルの 3 状態・ブックの情報と同じ言い方で、選んだ状態はプロジェクトごとに記憶する）:
  - **内容も出す**（既定）: 構成・コールバックと VBA の照合・**XML の全文**（文字数の上限つき）。
  - **構成だけ**: タブ・グループ・コントロールの **id・label・種類**と、コールバック（`on*`／`get*`／`loadImage`）の一覧（VBA との照合つき）。XML の全文は出さず、**メモリからも直ちに捨てる**（構成は残す）。
  - **出さない**: 何も渡さず、**ブックのファイルも読まない**。
- **既定を「内容も出す」にする理由**（利用者の問いへの判断。付録A-23）: customUI は VBA と同じ**コード**で、シートの値のような**データ**ではない。リボンの修正を AI に手伝わせるには、`size`・`imageMso`・`screentip` などを含む XML の全文が要る（構成だけでは、既存の属性を落とした書き換え案になりやすい）。社外秘の値は含みにくい。一方で `label` や `screentip` に業務名・部署名が入りうるので、「構成だけ」（label は出る）か「出さない」へ下げられるようにし、**画面と依頼文の冒頭で何を渡しているかを常に見せる**。シートの値のような確認ダイアログは出さない（VBA のコード本体が確認なしで渡るのと同じ種類の情報のため）。label を渡したくないときは「出さない」を選ぶ。
- **出力の形**（`VbaRibbonFormatter`。改行は LF 固定で、差し込み側が自分の改行へそろえる）:

````markdown

- 読んだもの: **最後に保存したときのファイルの内容**です（Excel で開いて編集中の、まだ保存していない変更は含まれません）。
- 取得: 2026-11-22 10:30 ／ ファイルの更新: 2026-11-21 18:02
- 部品: customUI/customUI14.xml（新しい形式）

## 構成

  - ribbon
    - tab tabMain label="業務"
````

### 15.6 渡し方（依頼文・コンテキスト収集）

- `ContextRequest.RibbonText`（新設）に、リボンの文を載せる。
- **依頼文のテンプレート展開**（`PromptTemplateRenderer`）: テンプレート変数 **`{{ribbon}}`** を新設する。並びは「前提 → ブックの情報 → **リボン** → 観点 → 対象ファイル」。`{{ribbon}}` があればそこへ、無ければブックの情報・観点と同じ規則（①「# 対象ファイル」だけの行の直前 ②`{{files}}` を含む行の直前 ③自動付加する「# 対象ファイル」の直前 ④末尾）で、**ブックの情報の後・観点の前**に差し込む。変数が無いほうの文は、変数のある隣の文へ寄せて並びを守る（`{{workbook}}` だけがあればリボンと観点はその直後、`{{focus}}` だけがあればブックの情報とリボンはその直前、`{{ribbon}}` だけがあればブックの情報はその直前・観点は直後）。空のときは変数が痕跡なしで消える。ほかの変数を展開したあとに差し込む（ファイルの中身や自作の観点に `{{ribbon}}` と書かれていても再展開されない）。**テンプレートの本文そのものは書き換えない**。組み込みのテンプレートに `{{ribbon}}` は足さない（差し込み規則が働く）。
- **コンテキスト収集の窓のコピー・プレビュー・ファイル保存**（`ContextCollector.CollectAsync`）: 「# 前提」・ブックの情報の直後、観点の前に差し込む。
- **同一性の約束**: リボンの文が空（「出さない」・customUI が無い・読めない・設定でブックの情報の取得がオフ）なら、**依頼文もコンテキスト収集の出力も、リボンを足す前と 1 バイトも変わらない**。観点を何も選ばなければ、観点の文も入らない。
- トークンの推定は、リボンの文を含めて数える。観点（チップ）の VBA 向けの追記に、リボン用の文は**足さない**（今回は不要）。VBA の前提の最終行（`hasWorkbookInfo`）の切り替えは、ブックの情報の有無だけで決め、リボンは見ない。

### 15.7 取るタイミングと失敗時

- **契機はブックの情報と同じ**: コンテキスト収集を開いたとき（走査の前。Pull の直後）と、依頼文コピーの組み立て（`FetchWorkbookInfoAsync` の中で、ブックの情報のあとに `FetchRibbonAsync`）。シートの見せ方を変えたことによる取り直しでは、ブックのファイルは変わらないので読み直さない。「出さない」から戻したときは読み直す。
- 取らない条件（ファイルを開かない）: VBA プロジェクトでない、`Vba.Enabled` が false、この環境で使えない、**`Vba.CollectWorkbookInfo` が false**、行の状態が「出さない」。出力の直前にも、設定と環境の「いま」を引き直す（オフにした直後に、取得済みの内容を出さない）。
- ブックのパスは、紐付いているブック（`VbaLink.WorkbookFullName`）。**別のブックへ結び直されたら、前のブックの取得結果を捨てる**（出力の直前にも突き合わせる）。
- **読めないときは収集を止めない**。理由を行に 1 行で出し、リボンなしで続ける。**警告にも載せる**のは「読めなかった」とき（`FileNotFound`・`Locked`・`Corrupt`・`PartsUnreadable`、一部の部品だけ読めなかったとき）で、ステータスの警告（`VbaWarning`）に連結する。customUI が無い・.xls は「読めなかった」ではなく「対象が無い」ので警告にしない。**前回成功した分は使い回さない**（ファイルを毎回読み直すだけの軽い処理で、古い XML を「いまの」ものとして渡すより、無いほうが安全なため。ブックの情報の「最新を読めていません」とは違う扱い）。
- 取得結果は**メモリにだけ**持つ（ディスク・ログに書かない）。「構成だけ」「出さない」へ下げたら、XML の全文をメモリから直ちに捨てる。プレビュー欄の古い出力も空にする。ログに残すのは「部品が N 件・コールバックが N 件」という事実だけ。
- 読み取りはスレッドプールで行う（大きなブックでも UI を止めない）。取得の世代番号で、古い取得の結果が新しい操作の結果を上書きしないようにする（ブックの情報と同じ）。

## 16. 機能 F: リボンの書き換え（次の版・予定。**この版では作らない**）

15 章（読み取り）に続く機能として、次の版で作る。ここでは**章立てだけ**を置き、細部は次の版の冒頭で決める。

### 16.1 目的

AI の回答に含まれる新しい customUI の XML を、ブックのリボンへ反映する（手で zip を開き、XML を差し替え、`_rels/.rels` と `[Content_Types].xml` を整える作業をなくす）。

### 16.2 手順（予定）

読み取りと違い、**ブックのファイルを書き換える**。Excel が開いているブックのファイルは書き換えられず、書き換えても Excel の保存で上書きされるため、次の順にする。

1. **ブックを保存して閉じる**（Excel に依頼する。保存と閉じるの確認は 16.3・16.4）。
2. **控え**: 書き換える前のブックのファイルを、控えとして残す（`.rescue/` と同じ考え方で、世代と容量の上限を決める）。
3. **差し替え**: パッケージの customUI の部品（と、必要なら関係・コンテンツタイプ）を書き換える。元のファイルは書き換えず、新しいファイルを作って置き換える（途中で失敗しても壊れない形）。
4. **開き直す**（利用者の許可を得て）。

### 16.3 毎回確認する（予定）

ブックの書き換えは取り返しがつきにくいので、**毎回、何をするか（閉じる・書き換える・開き直す）と、控えの場所を示して確認する**。「次から確認しない」は作らない。

### 16.4 未保存があれば止める（予定）

Excel でブックに未保存の変更があるときは、**書き換えを始めず**、保存するか中止するかを利用者に選んでもらう（未保存の変更を黙って捨てない）。保存できないブック（読み取り専用・保護ビュー）は止める。

### 16.5 XML の検査（予定）

書き込む前に、15.3 と同じ安全な読み取りで XML を検査する（整形式・DTD なし・名前空間・必須の属性・id の重複）。コールバックの名前が VBA に無いときは警告する（15.4 の照合を使う）。検査に通らないものは書かない。

### 16.6 この版でしないこと

書き換えそのもの、控えの保存、Excel の閉じる・開き直す操作、XML の検査の画面、`ApplyEngine` へのリボン用のブロックの追加。読み取り（15 章）が書き換えの前提を壊さないよう、**15 章の取得結果・照合は、書き換えの前後の差分の確認にも使える形で、そのまま残す**。
