# 確認手順: プロジェクトペインの使い勝手改善

対象コミット: （このドキュメントをコミットした時点の HEAD。`git log --oneline -1` で確認してください）
ブランチ: `claude/spec-implementation-7fhplo` から分岐した作業ブランチ

この手順書は、プロジェクトペイン（左上の「プロジェクト」一覧）に追加した7つの操作
（削除・ダブルクリックでエクスプローラへ切替・ピン留め・表示名変更・タグ編集・場所の変更・
フォルダのドラッグ＆ドロップ登録）が **Windows実機で正しく動くか**を確認するためのものです。

所要時間の目安: 約20〜30分。

---

## 0. 事前に知っておいてほしいこと（安全性について）

このセッションで追加した「削除」機能は、**Graftの登録（projects.jsonの1件）を消すだけ**で、
**実際のプロジェクトフォルダやその中のファイルには一切触れません。**
以下の手順では、削除の前後で実際にフォルダ・ファイルが残っていることを目で確認する項目が
あります（2-1）。ここは今回もっとも安全性が重要な箇所なので、必ず確認してください。

「場所を変更」（2-6）は、フォルダを移動・リネームして行方不明になったプロジェクトを
同じプロジェクトのまま繋ぎ直す機能です。内部的にはIDが変わり、それに伴って変更履歴
（`back/<プロジェクトID>/` フォルダ）も新しいIDの場所へ自動的に移動します。この移動が
正しく行われるかどうかも確認項目に含めています。

## 1. ビルド

PowerShell を開いて、上から順に貼り付けて実行してください。

```powershell
cd C:\Users\YUGO\Graft
git fetch origin
git checkout <このブランチ名>
git log --oneline -1
```

続けて自動テストとビルドを実行します。

```powershell
cd C:\Users\YUGO\Graft
dotnet build -c Release
dotnet test tests\Graft.Tests -c Release
dotnet test tests\Graft.UiTests -c Release
```

**期待する結果**: `dotnet build` が警告0・エラー0で成功する。両方の `dotnet test` が
全件成功する（Linux開発環境では Graft.Tests 456件、Graft.UiTests 367件がすべて成功して
います。Windows実機でこれと異なる結果になった場合は、そのまま報告してください）。

続けて発行（単一ファイルの exe を作る）します。

```powershell
cd C:\Users\YUGO\Graft
Remove-Item -Recurse -Force publish\Graft -ErrorAction SilentlyContinue
dotnet publish src\Graft\Graft.csproj -c Release -r win-x64 --self-contained true -o publish\Graft
```

> **注意**: 発行先を今までと同じ場所にしている場合、`settings.json` や `back/` などの
> データも同じフォルダにあります。今回は削除・場所の変更など**データを直接操作する機能**を
> 検証するため、**検証用に新しいフォルダへ発行する**ことを強くおすすめします。
> 既存の `publish\Graft` を使う場合は、先に `publish\Graft\back` と
> `publish\Graft\projects.json` をどこかへ退避してください。

## 2. 検証

`publish\Graft\Graft.exe` を起動してから進めてください。初回起動時にオンボーディング画面が
出た場合は「スキップ」で閉じてください。

まず、検証用に2つのフォルダを用意してください（デスクトップ等、どこでも構いません）。

```powershell
New-Item -ItemType Directory -Force C:\Users\YUGO\Desktop\GraftPaneTest\projA
New-Item -ItemType Directory -Force C:\Users\YUGO\Desktop\GraftPaneTest\projB
"テストファイルA" | Out-File C:\Users\YUGO\Desktop\GraftPaneTest\projA\a.txt
"テストファイルB" | Out-File C:\Users\YUGO\Desktop\GraftPaneTest\projB\b.txt
```

### 2-1. 削除（最重要: フォルダ・ファイルは絶対に消えないこと）

- [ ] プロジェクトペイン右上の「フォルダ」ボタンで `projA` を登録する。
- [ ] 一覧の `projA` を**右クリック**し、メニューに「場所を変更...」「表示名を変更...」
      「タグを編集...」「ピン留めする」「削除...」が並んでいることを確認する。
      （それぞれにマウスを乗せて、日本語の説明（ツールチップ）が出ることも確認する）
- [ ] 「削除...」を選ぶ。確認ダイアログが出て、**「フォルダそのものは削除されない」旨が
      本文に明記されている**ことを確認する（実際のフォルダパスも表示されるはず）。
- [ ] ダイアログの「履歴は残す」を押す。

**期待する結果**: 一覧から `projA` が消える。**Windowsのエクスプローラで
`C:\Users\YUGO\Desktop\GraftPaneTest\projA` を開き、`a.txt` がそのまま残っていることを
確認する。**

- [ ] 同じ `projA` フォルダをもう一度、プロジェクトペインの「フォルダ」ボタンで登録し直す。

**期待する結果**: 何事もなく登録できる（別プロジェクト扱いで重複したり、エラーになったり
しない）。

**違った場合に報告してほしいこと**: フォルダやファイルが消えていた場合は**最優先で
報告してください**（写真・エクスプローラのスクリーンショットがあれば添えてください）。

- [ ] もう一度、ヘッダーの削除ボタン（ゴミ箱アイコン）から `projA` を削除する。今度は
      「履歴も削除する」を選ぶ。

**期待する結果**: この場合もフォルダ・ファイルは一切消えない（ダイアログの選択に関わらず、
消えるのはGraftの登録情報とGraft自身が作ったバックアップだけ）。

---

### 2-2. ダブルクリックでエクスプローラへ切り替え

- [ ] `projB` を登録する。
- [ ] サイドバーの「履歴」アイコン（時計マーク）をクリックして、履歴ビューを表示させておく。
- [ ] プロジェクト一覧を開き（サイドバーの一番上のアイコン）、`projB` の**プロジェクト名を
      ダブルクリック**する。

**期待する結果**: サイドビューが自動的に「エクスプローラ」へ切り替わり、`projB` 内の
`b.txt` が一覧に表示される。

- [ ] 続けて、サイドバーのプロジェクトアイコンをもう一度クリックしてプロジェクト一覧を
      折りたたむ（同じアイコンをもう一度押すと折りたたまれます）。
- [ ] 折りたたまれた状態のまま、プロジェクト名の位置をダブルクリックする（一覧は畳まれて
      いますが、サイドバーの縦アイコン自体はクリックできます。もし畳まれていて操作しづらい
      場合は、一度展開してからダブルクリックしても構いません）。

**期待する結果**: エクスプローラへ切り替わり、かつ折りたたみが解除されて展開表示になる。

**違った場合に報告してほしいこと**: 何も起きない／別のビューに切り替わる／展開されない、
のどれか。

---

### 2-3. ピン留め

- [ ] `projA` を右クリックして「ピン留めする」を選ぶ。

**期待する結果**: `projA` の項目にピンの形をした小さいアイコンが表示され、太字になる。
一覧の並び順が変わり、ピン留めした `projA` が最上部に来る（他にピン留め済みのプロジェクトが
無い場合）。

- [ ] もう一度右クリックすると、メニューの項目が「ピン留めを解除する」に変わっていることを
      確認する。
- [ ] 「ピン留めを解除する」を選ぶ。

**期待する結果**: ピンアイコンが消え、太字も解除される。並び順も最終使用日時順へ戻る。

- [ ] ピン留めした状態でGraftを一度終了し、再度起動する。

**期待する結果**: ピン留めが再起動後も保たれている。

---

### 2-4. 表示名の変更

- [ ] `projA` を右クリック →「表示名を変更...」。入力欄に現在の表示名が入っていることを
      確認する。
- [ ] 「テスト表示名」と入力してOK。

**期待する結果**: 一覧の表示が「テスト表示名」に変わる。

- [ ] もう一度「表示名を変更...」を開き、入力欄を**すべて削除して空のままOK**を押す。

**期待する結果**: 表示名がフォルダ名（`projA`）へ自動的に戻る。

- [ ] Graftを再起動する。

**期待する結果**: 変更（または既定へ戻したこと）が保たれている。

---

### 2-5. タグの編集

- [ ] `projA` を右クリック →「タグを編集...」。
- [ ] `windows, テスト` と入力してOK（全角カンマ・半角カンマどちらでも、まずは半角
      カンマで確認してください）。

**期待する結果**: 一覧の `projA` の下に「windows / テスト」と表示される。

- [ ] もう一度開き、` windows ,, テスト ` のように前後の空白・空の要素を混ぜて入力しOK。

**期待する結果**: 前後の空白が落ち、空の要素は無視され、「windows / テスト」のまま変わらない
（4つ入力したつもりが2つのタグとして扱われる）。

- [ ] Graftを再起動する。

**期待する結果**: タグが保たれている。

---

### 2-6. 場所の変更（行方不明プロジェクトの再結び付け・履歴の引き継ぎ）

これは今回もっとも注意が必要な項目です。**履歴（バックアップ）が新しい場所に正しく
引き継がれるか**を確認します。

- [ ] `projA` をプロジェクトとして選択した状態で、何か適当な変更を1回**適用**し、履歴を
      1件作る（AIの出力の代わりに、下記のような簡単なパッチを貼り付けて「解析」→
      「適用」してください）。

```
<<<< PATCH
summary: 場所変更の確認用
type: feat
>>>>

<<<< FILE: a.txt
<<<<<<< SEARCH
テストファイルA
=======
テストファイルA（変更後）
>>>>>>> REPLACE
```

- [ ] 履歴ビューを開き、r1 が記録されていることを確認する。
- [ ] Graftを終了する（またはプロジェクト一覧から `projA` の選択を外す）。
- [ ] **Windowsのエクスプローラで**、`projA` フォルダそのものをリネームする（例:
      `projA` → `projA_moved`）。
- [ ] Graftを起動し直す（または一覧を更新する）。

**期待する結果**: `projA` が一覧にグレー表示・「未接続」として表示される。

- [ ] `projA`（未接続表示）を右クリック →「場所を変更...」。フォルダ選択ダイアログが開くので、
      リネーム後の `projA_moved` フォルダを選ぶ。

**期待する結果**: 「未接続」表示が消え、通常のプロジェクトとして再接続される。

- [ ] 履歴ビューを開き、**r1 が引き続き表示されることを確認する**（消えていない、
      「復元不可」等の警告が出ていない）。
- [ ] r1 を選んで「このリビジョンを取り消す」を実行できることを確認する（実行後は
      `a.txt` の中身が「テストファイルA」に戻ります）。

**期待する結果**: 履歴が失われず、以前と同じように復元操作ができる。

**違った場合に報告してほしいこと**: 「未接続」のまま変わらない／履歴が消えている／
「復元不可」という警告が出る、のいずれか。次のコマンドの出力もあわせて報告してください。

```powershell
Get-ChildItem C:\Users\YUGO\Graft\publish\Graft\back
Get-Content -Encoding UTF8 C:\Users\YUGO\Graft\publish\Graft\projects.json
```

- [ ] （重複登録が弾かれることの確認）別の既に登録済みのプロジェクト（`projB`）を選び、
      右クリック →「場所を変更...」で `projA_moved` フォルダを選ぼうとする。

**期待する結果**: エラーメッセージが出て変更が拒否される（`projA_moved` は既に別プロジェクト
として登録済みのため）。`projB` の登録内容は変わらないままであること。

### 2-7. フォルダのドラッグ＆ドロップ登録

- [ ] Graftのプロジェクト一覧が空、または他のプロジェクトが登録された状態にしておく。
- [ ] Windowsのエクスプローラを開き、`GraftPaneTest` フォルダの中身（`projA_moved` や
      `projB` ではなく、まだ未登録のフォルダがあれば新しく1つ作って）をGraftのプロジェクト
      一覧へドラッグ＆ドロップする。

**期待する結果**: ドラッグ中、一覧の背景色がうっすら変わり「ここに落とせる」ことが分かる
（実装した簡易な視覚フィードバック）。ドロップするとフォルダが一覧に追加される。

- [ ] 複数のフォルダを**同時に選択**してまとめてドラッグ＆ドロップする（新しく2〜3個
      フォルダを作ってから試してください）。

**期待する結果**: 落としたフォルダがすべて一覧に追加される。

- [ ] フォルダではなく**ファイル1つ**（例: `a.txt`）をドラッグ＆ドロップしてみる。

**期待する結果**: そのファイルの**親フォルダ**が登録される（エラーにはならない）。

**違った場合に報告してほしいこと**: 視覚フィードバックが出ない／登録されない／エラーに
なる、のいずれか。視覚フィードバックが出ないこと自体は軽微な問題として構いません
（実装した簡易な機能のため、Windows実機での見え方の違いはあり得ます）。
