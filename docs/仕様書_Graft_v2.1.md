# Graft — 仕様書 v2.1

プロジェクト管理を中核に、コードエディタと、対話型AIが出力したコードの安全な「接ぎ木」を統合した**クロスプラットフォーム**デスクトップ開発ツール。

> **実装者へ**: 本仕様書は実装の唯一の基準である。着手前に**附録A（実装者向け指示）**を必読のこと。v2.0 からの変更点は**附録B**にまとめる。v1.5〜v2.0 で実装済みの資産（パーサ・マッチング・適用・リビジョン・エディタ・エクスプローラ等）は捨てずに再利用する。

---

## 0. v2.1 改訂の背景

v2.0 は WPF による Windows 専用アプリだった。v2.1 では **Windows と Linux の両方で動作する**ことを要件に加える。

### 0.1 変更の動機

第一に、**Linux でも使いたい**という要求そのもの。

第二に、**開発中の品質検証が根本的に改善する**こと。WPF は Windows 実機でしか実行できず、ビルドが通っても起動時に落ちる種類の不具合（リソースの型不一致、`StaticResource` の解決失敗、コントロールテンプレートの表示崩れ）を自動検証できなかった。実際 v2.0 の開発では、これらを人手による実機確認でしか発見できなかった。

Avalonia は **headless モードで実際に描画し、フレームを画像として取得できる**。これにより以下が自動テストとして成立する。

- 画面を実際に描画し、レイアウト崩れ・リソース解決失敗を検出する
- ボタンのクリック、キーボード入力（日本語IMEを含まない直接入力）を再現し、操作シナリオを検証する
- スクリーンショットを保存して目視確認・回帰比較に使う

**この検証能力は品質要件そのものとして扱う**（18章・附録A.7）。

### 0.2 対応プラットフォーム

| OS | 位置づけ |
|---|---|
| Windows 10 (21H2以降) / 11、x64 | **正式対応**。全機能が動作する |
| Linux（x64、glibc ベースの主要ディストリビューション） | **正式対応**。一部のOS統合機能に制限あり（2.3） |
| macOS | 対象外。Avalonia の性質上おそらく動作するが、検証も保証もしない |

## 1. 概要

### 1.1 設計目標

v2.0 の5目標を維持し、1つ追加する。

1. **プロジェクト管理を中核とする。**
2. **一般的なコードエディタの機能を市販ソフト水準で備える。**
3. **トークン消費の最小化。** search/replace形式を第一級の入力として扱う。
4. **変更の追跡可能性。** 適用単位をリビジョンとして記録する。
5. **製品相当の完成度。** UI・エラー処理・異常系からの復帰を市販ソフトの水準で作り込む。
6. **（新規）プラットフォーム差を機能ではなく実装の詳細に留める。** OS固有機能は抽象化の背後に隠し、利用できない環境では機能を欠くのではなく**縮退した代替**を提供する。落ちたり無言で無視したりしない。

### 1.2 用語定義

v2.0 の用語を維持し、以下を追加する。

| 用語 | 定義 |
|---|---|
| プラットフォームサービス | OS固有機能（トレイ・ホットキー・クリップボード監視・ごみ箱・テーマ判定等）の抽象インターフェース群 |
| headless テスト | 画面表示なしにUIを構築・操作・描画して検証する自動テスト |

## 2. 動作環境・配布形態

### 2.1 フレームワークとランタイム

- フレームワーク: .NET 8 / **Avalonia UI 11**
- 実行形態: self-contained、単一実行ファイル（PublishSingleFile）。RID ごとに生成する
  - Windows: `win-x64` → `Graft.exe`
  - Linux: `linux-x64` → `Graft`
- ランタイム事前導入・インストーラ・管理者権限: いずれも不要
- レジストリ書き込み: 行わない（Windows でのテーマ判定等の**読み取り**のみ許可）
- ネットワーク通信: 一切行わない

### 2.2 依存ライブラリ

| ライブラリ | ライセンス | 用途 |
|---|---|---|
| Avalonia | MIT | UIフレームワーク |
| Avalonia.Desktop / Avalonia.Themes.Fluent | MIT | デスクトップ実行基盤・基礎スタイル |
| **AvaloniaEdit**（`Avalonia.AvaloniaEdit`） | MIT | コードエディタエンジン（AvalonEdit の Avalonia 移植版） |
| DiffPlex | Apache License 2.0 | 差分生成 |
| System.Text.Encoding.CodePages | MIT | Shift_JIS 対応 |
| Avalonia.Headless / Avalonia.Headless.XUnit | MIT | **テストプロジェクトのみ。** headless UIテスト |

**WPF・AvalonEdit（WPF版）への依存は撤去する。** これ以外の依存追加は禁止（必要と判断した場合は理由を添えて確認）。ライセンス全文はすべて埋め込みリソースとして同梱し、バージョン情報画面から参照できるようにする。

### 2.3 プラットフォーム別の機能対応

**「未対応」は許容しない。必ず縮退した代替を用意し、利用できない旨をUIに明示する。**

| 機能 | Windows | Linux | Linux での実装方針 |
|---|---|---|---|
| エディタ・エクスプローラ・接ぎ木・履歴・設定 | 対応 | 対応 | 差異なし |
| Shift_JIS の読み書き | 対応 | 対応 | `CodePages` はクロスプラットフォーム |
| 長いパス（MAX_PATH 超過） | `\\?\` 前置 | 該当なし | Linux にパス長の実用上限がないため何もしない |
| 安全な書き込み | `File.Replace` | `File.Move(overwrite)` | 既存の分岐を維持 |
| 多重起動の防止 | 名前付き Mutex | **ロックファイル**（`~/.cache` 等ではなくデータディレクトリ配下） | 既存ウィンドウの前面化は 2.4 の方式に従う |
| ごみ箱への削除 | `SHFileOperation` | **XDG Trash 仕様**（`~/.local/share/Trash`） | 実装できない場合は確認ダイアログのうえ通常削除。無言で消さない |
| ファイルマネージャで表示 | `explorer.exe /select,` | `xdg-open`（親フォルダを開く） | ファイル選択までは保証しない |
| トレイ常駐 | `Shell_NotifyIcon` | **`StatusNotifierItem`（D-Bus）** | 利用不可のデスクトップ環境では**トレイ機能を無効化し、その旨を設定画面に表示**する |
| グローバルホットキー | `RegisterHotKey` | **X11 は `XGrabKey`、Wayland は利用不可** | 利用不可の場合は `E601` として通知し、アプリ内ホットキーのみで動作を継続する |
| クリップボード監視 | `AddClipboardFormatListener` | **X11 は `XFixes` によるセレクション監視、Wayland は利用不可** | 利用不可の場合は `E602` として通知。手動での取り込み（`Ctrl+Shift+V`）は常に使える |
| システムテーマの追従 | レジストリ読み取り | **`org.freedesktop.appearance color-scheme`（XDG Desktop Portal）** | 判定できない場合はダークへフォールバック |

**Wayland では OS の設計上グローバルホットキーとクリップボード監視が実現できない。** これは制限として明示し、代替手段（アプリ内ホットキー・手動取り込み）が常に機能することを保証する。

### 2.4 プラットフォームサービスの抽象化

OS固有機能は `Graft.Platform` 名前空間のインターフェースとして定義し、実装を `Platform/Windows/` `Platform/Linux/` に分ける。**UI層・機能層はインターフェースにのみ依存する。**

```
IPlatformServices
├── ITrayIcon              トレイ常駐
├── IGlobalHotkeys         グローバルホットキー
├── IClipboardMonitor      クリップボード監視
├── ITrashService          ごみ箱への削除
├── IFileManagerLauncher   ファイルマネージャで表示
├── ISystemThemeWatcher    システムテーマの判定と変更通知
└── ISingleInstanceGuard   多重起動の防止と既存ウィンドウの前面化
```

各インターフェースは `bool IsSupported { get; }` を持ち、**利用可否をUIが判断できる**ようにする。利用不可の機能に対応する設定項目は、設定画面で無効表示にし理由を併記する。

いずれのプラットフォームでも成立しない場合に備え、**何もしない実装（NullObject）を必ず用意する**。呼び出し側が `null` 判定を書かなくて済むようにする。

### 2.5 フォント

プラットフォームで利用可能なフォントが異なるため、**フォールバックの並びで指定する**（先頭から利用可能なものを使う）。

| 用途 | 指定 |
|---|---|
| UI | Yu Gothic UI, Segoe UI Variable, **Noto Sans CJK JP, IPAexGothic**, sans-serif |
| コード | Cascadia Mono, **JetBrains Mono, Noto Sans Mono CJK JP, DejaVu Sans Mono**, monospace |

日本語グリフを持つフォントが1つも見つからない環境では、**起動時に警告を表示**する（`E705`）。文字化けを無言で放置しない。

### 2.6 フォルダ構成

実行ファイルと同じ階層に配置する（v2.0 と同一。ポータブル運用を優先し、XDG のディレクトリ規約には従わない）。

```
Graft/
├── Graft(.exe)
├── settings.json / projects.json / templates.json / queue.json / layout.json
├── onboarding.done
├── back/<プロジェクトID>/history.jsonl, r24_.../manifest.json …
└── logs/yyyyMMdd.log
```

実行ファイルのあるディレクトリが書き込み不可の場合（Linux で `/usr/local/bin` 等に置かれた場合）は、`$XDG_DATA_HOME/graft`（既定 `~/.local/share/graft`）へフォールバックし、**その旨をログとステータスバーに記録する**。

## 3. プロジェクト管理

v2.0 の3章を**変更なしで維持**する（projects.json、登録と未接続状態、常設コンテキスト、自動判定の3段階しきい値、プロジェクトごとのタブ・展開状態・ペイン寸法の記憶）。

パスの比較について明文化する。**Windows では大文字小文字を無視し、Linux では区別する**。プロジェクトIDの生成に使う正規化も同様に、比較規則をプラットフォームへ委ねる。

## 4. コードエディタ

v2.0 の4章を維持し、以下を変更する。

### 4.1 エンジン

**AvaloniaEdit** を採用する。API は AvalonEdit とほぼ同名で、`TextDocument`・`TextEditor`・`DocumentColorizingTransformer`・`FoldingManager`・`CompletionWindow` はいずれも対応物がある。

シンタックスハイライトは v1.5 から実装済みの**自前レキサ（`SyntaxLexer`、11言語）を唯一の定義**とし、AvaloniaEdit のカラライザへ接続する。AvaloniaEdit 内蔵の `.xshd` 定義は使用しない。

### 4.2〜4.8

v2.0 のとおり（エクスプローラ、タブ、編集機能、エンコーディングと改行、外部変更の検知、Git変更表示、接ぎ木との連携）。

Linux 固有の注意点を追記する。

- **4.2 削除**: ごみ箱は `ITrashService` 経由。XDG Trash を実装できない場合は確認のうえ通常削除とし、ダイアログにその旨を明記する
- **4.6 外部変更の検知**: `FileSystemWatcher` は Linux では inotify を使う。**監視数の上限（`fs.inotify.max_user_watches`）に達すると失敗する**ため、失敗時は `E704` として手動更新へ縮退する（この挙動は既に v2.0 で規定済み）
- **4.5 改行**: 既存ファイルの改行を保持する規則は変更しない。新規ファイルの既定改行は**プラットフォームの慣習ではなく設定値**に従う（プロジェクト間で挙動がぶれないようにするため）

## 5〜8章（入力フォーマット / マッチング / 適用 / リビジョン）

v2.0 の5〜8章を**変更なしで維持**する。これらは `Core` 層に閉じており、プラットフォーム依存を持たない。

適用エンジンの `File.Replace` フォールバック、長パス対応、多重起動防止はすでに `OperatingSystem.IsWindows()` で分岐済みであり、**その分岐をプラットフォームサービス（2.4）へ移す**。

## 9. UI/UX仕様

v2.0 の9章を維持し、以下を変更する。

### 9.1 設計原則

v2.0 を維持する（装飾なし・明度差3階層・絵文字禁止・ベクターのみ・色に依存しない状態表現・キーボード完結）。

**追加**: OS のネイティブな見た目に寄せない。**Windows と Linux で同一の外観**とする。Avalonia の Fluent テーマは土台としてのみ使い、色・寸法はすべて自前のトークンで上書きする。

### 9.2 レイアウト

v2.0 と同一（サイドバー48px ＋ サイドビュー ＋ エディタ領域 ＋ 接ぎ木パネル ＋ ステータスバー24px、コマンドバー40px）。

### 9.3 カラートークン

v2.0 の全トークンを**値も含めて維持**する。プラットフォームで色を変えない。

Windows のハイコントラストモード検出は `ISystemThemeWatcher` 経由とし、Linux では対応するデスクトップ設定があれば追従、なければ何もしない。

### 9.4 タイポグラフィ

2.5 のフォントフォールバックに従う。**サイズ・ウェイト・行間の指定は v2.0 のまま変更しない。**

### 9.5 アイコン

v2.0 の21種を維持する。すべてベクター（`StreamGeometry`）。**トレイアイコンも同じベクター定義から実行時に生成する**（Windows は HICON、Linux は PNG バイト列を D-Bus 経由で渡す）。ラスタ画像ファイルは同梱しない。

### 9.6 キーボード操作

v2.0 の表を維持する。プラットフォーム差を1点だけ設ける。

- **修飾キーの表記**: UI 上の表示は実行中のプラットフォームに合わせる（Windows: `Ctrl`、Linux: `Ctrl`）。現時点で差は生じないが、表示は抽象化しておく

### 9.7 High DPI・ウィンドウ

Avalonia は DPI スケーリングを標準で扱う。ウィンドウ位置・サイズ・最大化状態の復元と**画面外になった場合のプライマリ画面中央への補正**は v2.0 のとおり実装する。最小サイズ 960×600。

## 10〜14章（クリップボード監視 / コンテキスト収集 / リカバリ / トークン統計 / 安全機構）

v2.0 を維持する。以下のみ変更する。

- **10章 クリップボード監視**: `IClipboardMonitor` 経由とする。Wayland 等で利用できない場合は設定画面で無効表示にし、`E602` を一度だけ通知する

## 15. 設定ファイル（settings.json）

v2.0 の全キーを維持し、`platform` セクションを追加する。

```json
{
  "platform": {
    "trayEnabled": true,
    "globalHotkeyEnabled": true,
    "clipboardWatchEnabled": false,
    "useTrashOnDelete": true
  }
}
```

これらは**利用可能な場合のみ有効**になる。利用不可の環境では設定値にかかわらず無効として扱い、設定画面にその理由を表示する（例: 「この環境（Wayland）ではグローバルホットキーを登録できません」）。

## 18. 非機能要件

v2.0 の要件を維持し、以下を追加・変更する。

- 起動から操作可能まで1秒以内（**両プラットフォームで**）。
  ただし単一ファイル版の初回起動のみ、ネイティブライブラリの展開が入るため対象外とする
  （展開結果は再利用されるため、2回目以降はこの要件を満たす）
- 10万行のファイルを開いてスクロール・編集が遅延なく行えること（**両プラットフォームで**）
- ファイル横断検索は10万ファイル規模でもUIをブロックしない
- 常駐時のメモリ使用量150MB以下
- ネットワーク通信なし・自動更新なし
- **（新規）UIの自動検証**: 主要画面の描画・主要操作シナリオが headless テストとして自動実行でき、**CI相当の環境（画面なし）で完結すること**。リソース解決の失敗とレイアウト崩れをテストで検出できること

## 19. 実装構成

```
src/Graft/
├── Core/            パーサ・マッチング・適用・バックアップ・レキサ（UI・OS非依存）
├── Features/        プロジェクト管理・収集・横断検索・フック・Git（UI非依存）
├── Infra/           設定・ログ（UI非依存）
├── Platform/        新設。OS固有機能の抽象と実装
│   ├── IPlatformServices.cs ほかインターフェース群
│   ├── Windows/     Shell_NotifyIcon・RegisterHotKey・SHFileOperation・レジストリ読み取り
│   ├── Linux/       StatusNotifierItem・XGrabKey・XDG Trash・XDG Portal
│   └── Null/        何もしない実装（未対応環境向け）
├── Editor/          AvaloniaEdit 依存のエディタ層
├── ViewModels/      自前の軽量MVVM
├── Views/           画面
├── Themes/          カラートークン・シンタックス配色・アイコン・ロゴ
└── Assets/          同梱ライセンス
tests/
├── Graft.Tests/         Core/Features/Infra/Platform の単体テスト（net8.0）
└── Graft.UiTests/       新設。Avalonia headless によるUIテスト
```

**`Core`・`Features`・`Infra`・`Platform`（インターフェースとNull実装）は UI フレームワークへ依存しない。** テストプロジェクトがこれらのソースを直接取り込んで `net8.0` としてビルドすることで機械的に保証する（v1.5 から継続している方式）。

## 20. 実装フェーズ

v2.0（フェーズE1〜E5）の完了を前提とした増分として実施する。**各フェーズ完了時点で、少なくとも Windows 版が動作する状態を保つ**（移行途中で全機能が使えない期間を作らない）。

| フェーズ | 内容 |
|---|---|
| L0 | v2.0（Windows/WPF版）の完成。E4・E5の残作業と品質確認を終える |
| L1 | `Platform/` の抽象を定義し、既存の `OperatingSystem.IsWindows()` 分岐を Windows 実装として移設する。**この時点では WPF のまま**。挙動が変わらないことを確認する |
| L2 | Avalonia プロジェクトの追加、`tests/Graft.UiTests` の整備、テーマ・トークン・アイコンの移植。**最小の画面（シェルの骨組み）が Linux で描画できることを headless テストで確認** |
| L3 | `Views`/`ViewModels` の移植（エディタ領域・エクスプローラ・接ぎ木パネル・履歴・設定・各ダイアログ）。AvalonEdit → AvaloniaEdit |
| L4 | `Platform/Linux/` の実装（トレイ・ホットキー・クリップボード監視・ごみ箱・ファイルマネージャ・テーマ判定）。利用不可時の縮退とUI表示 |
| L5 | 主要画面・主要シナリオの headless UIテスト整備、両プラットフォームでの発行検証、WPF版の撤去、フォント・文言・性能の最終確認 |

### 20.1 実装状況（L5 完了時点）

L0〜L5 をすべて完了した。実測値と確認方法は以下のとおり。

| 項目 | 結果 |
|---|---|

### 20.2 実機確認で見つかった不具合（リリース前の通し確認）

画面のある環境（Xvfb）でアプリを起動し、5巡にわたって各機能を操作して確認した。
静的な検査やheadlessテストでは現れず、実際に触って初めて分かった不具合は以下のとおり。
いずれも修正し、回帰テストを添えている。

| 症状 | 原因 |
|---|---|
| 保存するたびカーソルが文末へ飛ぶ | 自分の保存をファイル監視が外部変更と見なし、文書を丸ごと差し替えていた |
| 保存したテーマが再起動で元に戻る | 起動時に設定を読み直してテーマを当て直していなかった |
| 複数行の入力欄で内容が途中で切れる | 共通テーマがスクロールバーの指定を無視し、中央寄せのまま固定していた |
| 透かし文字がまったく表示されない | 共通テーマのテンプレートが透かし文字を描画していなかった |
| 「解析」を押しても何も起きない場合がある | クリップボードを読めないとき、理由を示さず黙って処理を終えていた |
| ライトテーマでトグルボタンだけ浮いて見える | ToggleButtonにテーマ定義が無く、Avaloniaの既定色が当たっていた |
| 起動ログに未処理例外が記録される | 破損ファイルの退避が同時に走ると、移動済みのファイルを再度移動しようとしていた |
| OS固有機能 | Windows・Linux とも全機能が有効。利用できない項目は起動ログと起動時通知で提示する |

**Wayland での制約**: グローバルホットキーは他クライアントのキーをつかみ取れないため利用できない。
起動時に E601 として通知し、他の機能はそのまま使える。

## 附録A. 実装者（Claude Code）向け指示

v2.0 附録Aを以下の変更を除き**そのまま適用**する。

- **A.3改訂**: 本体プロジェクトの外部パッケージは Avalonia 一式（`Avalonia`・`Avalonia.Desktop`・`Avalonia.Win32`・`Avalonia.Themes.Fluent`）、**AvaloniaEdit**、DiffPlex、System.Text.Encoding.CodePages、Microsoft.Win32.SystemEvents とする。テストは xUnit・FluentAssertions・**Avalonia.Headless・Avalonia.Headless.XUnit**。これ以外の追加は理由を添えて確認。MVVMフレームワーク・DIコンテナ・TextMateSharp は引き続き禁止。シンタックスハイライトの定義は自前レキサに一元化する。
- **A.4追加**: `Core`・`Features`・`Infra`・`Platform`（抽象とNull実装）に UI フレームワークの型を持ち込まないこと。`Platform/Windows` `Platform/Linux` は各OS固有APIを使ってよいが、**必ず `IsSupported` で利用可否を返し、例外を投げずに縮退する**こと。
- **A.7改訂（テスト方針）**: 従来の単体テストに加え、**headless UIテストを必須**とする。
  - 主要画面（シェル・エディタ・エクスプローラ・接ぎ木パネル・設定・各ダイアログ）が**例外なく構築・描画できる**ことを1件以上のテストで保証する。リソース解決の失敗はここで検出する
  - 主要シナリオ（プロジェクト登録 → ファイルを開く → 編集 → 保存、パッチ取り込み → プレビュー → 適用、設定を開く → 変更 → 保存）を操作テストとして自動実行する
  - 代表画面のスクリーンショットを出力し、目視確認できるようにする
- **移行の進め方**: 20章のフェーズ順に進め、**各フェーズ完了時に既存の全テストが合格することを条件**とする。既存の `Core`/`Features`/`Infra` は原則変更しない。UI層は移植であって作り直しではない。**v2.0 で作り込んだ挙動（キーマップ、状態表現、アクセシビリティ、性能上の工夫）を落とさないこと。**
- コーディング規約（日本語・命名・Nullable警告ゼロ・1メソッド50行/1ファイル400行・async I/O・色のハードコード禁止・絵文字禁止）は v2.0 のとおり。
