# Windows実機検証手順

開発とテスト（自動テスト573件・スクリーンショット確認）はすべてLinux（Xvfb）上で行っており、
Windows固有の実装は**一度も実機で動かして確認できていません**。このドキュメントは、
Windowsをお使いの方に実際にGraftを動かして確認していただくための手順書です。

> この手順書は実装者（Linux環境で作業）が実機を持たないまま作成したものです。
> ここに書かれた「期待する結果」は設計上そうなるはずだという予想であり、
> 実機での動作を保証するものではありません。手順どおりに進めていただければ十分です。
> 予備知識は不要です。

---

## 0. はじめに

### 0.1 全体の所要時間

| 範囲 | 目安 |
|---|---|
| 準備（0章） | 約5分 |
| 準備＋最優先（1章） | 約25分 |
| 準備＋最優先＋次点（1〜2章） | 約45分 |
| すべて（準備＋1〜3章） | 約70分 |

時間が取れない場合は、**「1. 最優先」だけ**やっていただければ大丈夫です。
気が向いたら「2. 次点」「3. 余裕があれば」も進めてください。

### 0.2 進め方

- 上から順番に、チェックボックス `- [ ]` にチェックを入れながら進めてください。
- 各項目には「手順」「期待する結果」「結果が違った場合に報告してほしいこと」の3つが
  書いてあります。手順どおりにやって「期待する結果」のとおりになれば、そのままチェックを
  入れて次へ進んでください。
- 期待どおりにならなかった項目だけ、「報告してほしいこと」の内容と、可能であれば
  スクリーンショットやエラーメッセージの文面をメモしておいてください。全部そのまま
  貼り付けて返していただければ、それで十分です（0.4に報告用の表があります）。
- 危険な操作（ごみ箱への削除、自動起動の登録、Program Filesへの配置など）には、
  その場に「元に戻す手順」を書いています。心配な場合はまとめて後片付けする方法を
  4章に書いています。

### 0.3 準備

- [ ] **配布物を、書き込みできる適当な場所（デスクトップやドキュメントフォルダなど）に置く。**
      Program Files配下は使わない（それは1-4で意図的に試す場所です）。
- [ ] `Graft.exe` をダブルクリックして起動し、ウィンドウが表示されることを確認する。
      （エラーが出て起動すらしない場合は、それ自体が重大な報告事項です。エラーメッセージを
      控えてこの手順書はここで一旦止めてください。）
- [ ] 検証用サンプルを生成する。エクスプローラで `tools` フォルダを開き、
      `New-WindowsTestSample.ps1` を右クリック →「PowerShellで実行」を選ぶ。
      （右クリックメニューに出ない場合は、PowerShellを開いて次のように実行してください。
      `.\tools\New-WindowsTestSample.ps1` を、このリポジトリ／配布物のフォルダを
      カレントディレクトリにした状態で貼り付けてEnter）
      実行すると、デスクトップに `Graft検証サンプル` フォルダが作られます
      （生成されるものの一覧は `tools/New-WindowsTestSample.ps1` の冒頭コメント、または
      生成後の `Graft検証サンプル\このフォルダについて.txt` を参照してください）。

> **このPowerShellスクリプトも実機で実行確認できていません。** 途中でエラーが出た場合は、
> そのエラーメッセージをそのまま報告してください。それだけでも十分に価値のある情報です。
> 実行にあたり管理者権限は不要です。もし「スクリプトの実行が無効になっています」という
> 趣旨のエラーが出た場合は、PowerShellで次を一度だけ実行してから再度お試しください。
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

## 1. 最優先（目安 約25分）

一番不安が大きい4項目です。時間が無ければここだけで構いません。

### 1-1. ×ボタンでウィンドウを閉じたときにプロセスが終了する

- [ ] **なぜ確認するか**: Linuxにはウィンドウマネージャーの×ボタンに相当する操作がなく、
      自動テストでは再現できない領域のため（以前「×で閉じてもプロセスが終了しない」
      バグが実際にあり、修正済みですがWindows実機での再確認はまだです）。
- **所要時間**: 3分
- **手順**:
  1. Graftを起動する。
  2. 設定を開く（コマンドバーの「設定」ボタン、またはショートカット `Ctrl+,`）→「一般」タブを開き、
     「ウィンドウを閉じたときの動作」が **「終了する」**（既定値）になっていることを確認する。
     なっていなければ「終了する」に変更する。
  3. 設定を閉じ、ウィンドウ右上の **×ボタン** をクリックする。
  4. タスクマネージャー（`Ctrl+Shift+Esc`）を開き、「詳細」タブで `Graft.exe` を探す。
- **期待する結果**: ×を押すとウィンドウが閉じ、数秒以内に `Graft.exe` がタスクマネージャーの
  一覧から消える（プロセスが完全に終了する）。
- **結果が違った場合に報告してほしいこと**: ウィンドウは閉じたのに `Graft.exe` が
  タスクマネージャーに残り続けるか。逆に×を押しても反応しないか。エラーダイアログが
  出るか（出た場合はその文面）。可能であればタスクマネージャーのスクリーンショット。

### 1-2. 多重起動防止

- [ ] **なぜ確認するか**: 多重起動の判定に使う名前付きMutexは、Windowsだと
      `Global\` という特別な名前空間を使う実装になっており、この経路はWindows実機でしか
      最終確認できないため。
- **所要時間**: 3分
- **手順**:
  1. Graftを起動する（1つ目）。
  2. 起動したままの状態で、もう一度 `Graft.exe` をダブルクリックして起動する（2つ目）。
- **期待する結果**: 2つ目は新しいウィンドウを開かず、代わりに1つ目のウィンドウが
  最前面に表示される（最小化していれば元に戻る）。タスクマネージャーで確認しても
  `Graft.exe` のプロセスは1つだけ。
- **結果が違った場合に報告してほしいこと**: ウィンドウが2つ開いてしまうか。2つ目が
  何も起きずに終了するだけで、1つ目が前面に出てこないか。エラーが出るか（出た場合は
  その文面）。

### 1-3. 文字コード・改行コードの往復（Shift_JIS / UTF-8 BOM / CRLF / LF / 末尾改行なし）

- [ ] **なぜ確認するか**: Shift_JISの読み書きやBOM・改行の復元は自動テストでも
      確認していますが、実際のバイト列がWindows上で本当に1バイトも変わらず往復するかは
      実機でしか確認できないため（Windowsのメモ帳・エクスプローラ等、OS側の挙動も
      絡むため）。
- **所要時間**: 8分（準備でスクリプトを実行済みであること）
- **手順**:
  1. Graftの左端サイドバーで「プロジェクト」ビューに切り替え、右上のフォルダアイコンの
     ボタン（プロジェクトを追加）をクリックして、デスクトップの `Graft検証サンプル\project`
     フォルダを選んで登録する（このフォルダをGraftのウィンドウへドラッグ＆ドロップしても
     同様に登録できる）。
  2. `Graft検証サンプル\patches\01_正常系_文字コード改行往復.txt` を開き、中身を
     すべて選択してコピーする。
     （サンプル生成スクリプトの実行直後であれば、クリップボードに既にコピー済みのため
     この手順は不要な場合があります。）
  3. Graftのウィンドウをクリックしてアクティブにし、`Ctrl+V` を押す。
  4. 差分のプレビューが表示されるので、5件のファイル（`shiftjis-sample.cs` /
     `utf8bom-sample.txt` / `crlf-sample.txt` / `lf-sample.txt` /
     `no-trailing-newline-sample.txt`）すべてに変更が表示されていることを確認し、
     「適用」ボタンを押す。
  5. `shiftjis-sample.cs` をメモ帳で開く（右クリック→プログラムから開く→メモ帳）。
     日本語が文字化けしておらず、メッセージが
     `"こんにちは、これはパッチ適用後のメッセージです。"` に変わっていることを確認する。
  6. 残り4ファイルの状態を、PowerShellで機械的に確認する。`Graft検証サンプル\project`
     フォルダでPowerShellを開き（フォルダ内の空いている場所を Shift+右クリック→
     「PowerShellウィンドウをここで開く」）、次のテキストをそのまま貼り付けてEnterを押す。
     > **注意**: `[System.IO.File]` に相対パスを渡すと、PowerShellのカレントではなく
     > .NETプロセスのカレント（多くの場合 `C:\WINDOWS\system32`）を基準に探してしまい、
     > 「ファイルが見つかりませんでした」になる。`cd` しても .NET 側は追随しないため、
     > 下のコードでは `Resolve-Path` で絶対パスへ直してから渡している。

     ```powershell
     foreach ($name in 'utf8bom-sample.txt','crlf-sample.txt','lf-sample.txt','no-trailing-newline-sample.txt') {
         $path  = (Resolve-Path $name).Path
         $bytes = [System.IO.File]::ReadAllBytes($path)
         $text  = [System.IO.File]::ReadAllText($path)
         $hasBom = $bytes.Length -ge 3 -and $bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF
         $hasCrlf = $text.Contains("`r`n")
         $endsWithNewline = $text.Length -gt 0 -and ($text[$text.Length-1] -eq "`n" -or $text[$text.Length-1] -eq "`r")
         "{0,-38} BOM={1,-5} CRLFを含む={2,-5} 末尾が改行={3}" -f $name, $hasBom, $hasCrlf, $endsWithNewline
     }
     ```
     表示された表を、このドキュメントの末尾にある期待値の表と見比べる。
- **期待する結果**:
  - すべて「適用」が成功する（エラーにならない）。
  - `shiftjis-sample.cs` はメモ帳で文字化けせず開け、内容も書き換わっている。
  - PowerShellの結果が次の表と一致する。

    | ファイル | BOM | CRLFを含む | 末尾が改行 |
    |---|---|---|---|
    | utf8bom-sample.txt | True | False | True |
    | crlf-sample.txt | False | True | True |
    | lf-sample.txt | False | False | True |
    | no-trailing-newline-sample.txt | False | False | **False** |

- **結果が違った場合に報告してほしいこと**: 適用自体が失敗するファイルがあるか
  （エラーメッセージの文面）。`shiftjis-sample.cs` が文字化けするか。PowerShellの結果表が
  上記と食い違う項目（特に `no-trailing-newline-sample.txt` の「末尾が改行」が `True` に
  なっていないか＝改行が勝手に付け足されていないか、は重要な確認ポイントです）。

- **おまけ（任意、+2分）**: `Graft検証サンプル\patches\02_失敗ケース_存在しないコード.txt`
  も同様にコピーしてGraftへ`Ctrl+V`で貼り付けてみてください。このパッチは
  存在しないテキストをわざと指定しているため、「一致しませんでした」という趣旨の
  エラーが表示され、`crlf-sample.txt` の内容は変更されないのが正しい動作です。
  Graftが強制終了したり、ファイルが壊れたりしないことだけ確認してもらえれば十分です。

### 1-4. 書き込み権限が無いフォルダに置いたときの警告

- [ ] **なぜ確認するか**: 以前、`Program Files` のような書き込み権限の無いフォルダから
      起動すると、警告も出ないまま設定・履歴・バックアップが保存されない
      （最悪の場合は起動時にクラッシュする）不具合があったため。この経路はWindows特有の
      権限モデルに依存しており、実機でしか最終確認できません。
- **所要時間**: 5分
- **手順**:
  1. 管理者権限のPowerShell（スタートメニューでPowerShellを右クリック→
     「管理者として実行」）で、配布フォルダ一式を `C:\Program Files\GraftTest\` へコピーする。
     例（`"配布フォルダのパス"` の部分は実際のパスに置き換えてください）:
     ```powershell
     Copy-Item -Path "配布フォルダのパス" -Destination "C:\Program Files\GraftTest" -Recurse
     ```
  2. 管理者権限の**要らない**、通常のダブルクリックで `C:\Program Files\GraftTest\Graft.exe`
     を起動する。
- **期待する結果**: 起動直後に「このフォルダへ書き込めません」という趣旨のダイアログが
  表示され、対処方法（書き込み権限のあるフォルダへ移動する旨）が案内される。ダイアログを
  閉じるとGraft自体は使い続けられ、画面下部のステータスバーに警告が表示され続ける。
- **結果が違った場合に報告してほしいこと**: 警告なしに普通に起動してしまうか。逆に
  クラッシュして起動できないか。ステータスバーの警告がいつの間にか消えるか。表示された
  エラーメッセージがあれば全文。
- **元に戻す手順**: Graftを終了し、管理者権限のPowerShellで削除する。
  ```powershell
  Remove-Item -Recurse -Force "C:\Program Files\GraftTest"
  ```
  （通常お使いになる配布物は、これとは別の書き込み権限のある場所に置いたままで
  大丈夫です。）

## 2. 次点（目安 約25分）

余裕があれば進めてください。

### 2-1. ごみ箱への削除

- [ ] **なぜ確認するか**: `SHFileOperationW` というWindows APIを直接呼び出しており、
      ごみ箱へ正しく送られるかは実機でしか確認できないため。
- **所要時間**: 3分
- **手順**:
  1. Graftのエクスプローラ（サイドビュー）で、`Graft検証サンプル\project` の中の
     いずれかのファイル（例: `lf-sample.txt`）を右クリックし、「削除 (Delete)」を選ぶ。
- **期待する結果**: ファイルがGraftのツリーから消え、Windowsの「ごみ箱」を開くと
  そこに入っている（完全に消えているわけではない）。
- **結果が違った場合に報告してほしいこと**: ごみ箱に入らずいきなり完全に消えるか。
  エラーが出て削除自体ができないか。
- **元に戻す手順**: Windowsの「ごみ箱」を開き、該当ファイルを右クリック→
  「元に戻す」で `project` フォルダへ復元する。気にしない場合はそのままで構いません
  （4章の後片付けで `project` フォルダごと消してしまえば影響ありません）。

### 2-2. 長いパス（260文字を超えるパス）

- [ ] **なぜ確認するか**: `\\?\` プレフィックスによる対応をコードには入れてありますが、
      実際にWindows上のNTFSで260文字超のパスを読み書きできるかは一度も試せていないため。
- **所要時間**: 8分
- **手順**:
  1. Graftのエクスプローラで `project\long-path\...` の奥にある
     `長いパスのファイル.txt` を開く（サンプル生成時にコンソールへ表示されたパス長が
     260文字を超えていることを確認しておく。忘れた場合は `Graft検証サンプル\このフォルダに
     ついて.txt` からもたどれます）。
  2. 内容を確認し、末尾に何か1行追記して保存する（`Ctrl+S`）。
  3. 一度Graft上でこのファイルのタブを閉じ、もう一度同じファイルを開いて、追記した内容が
     残っていることを確認する。
- **期待する結果**: エラーなく開ける・保存できる・保存内容が正しく反映される。
- **結果が違った場合に報告してほしいこと**: 開けない、保存時にエラーが出る、保存した
  はずなのに反映されていない、のいずれか。表示されたエラーメッセージの全文。
- **補足**: もし保存に失敗する場合、Windows側の「長いパスを有効にする」設定
  （レジストリ `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem` の `LongPathsEnabled` が
  `0`）が影響している可能性があります。Graft自身は `\\?\` プレフィックスを使うため
  本来この設定の影響を受けないはずですが、念のため次のコマンドをPowerShellに貼り付けて
  値も一緒に報告してください。
  ```powershell
  Get-ItemPropertyValue -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' -Name LongPathsEnabled
  ```
  （このキー自体が存在せずエラーになる場合は「未設定（実質0）」という意味です。それも
  そのまま報告してください。）

### 2-3. ファイルロック（他プロセスが開いているファイルへの適用）

- [ ] **なぜ確認するか**: 他のアプリがファイルを開いたままの状態での書き込みは、
      Windowsでは「共有違反」が起きやすく、Linuxでは同じ条件を再現しにくいため。
- **所要時間**: 5分
- **手順**:
  1. PowerShellを開き、`Graft検証サンプル\project` フォルダに移動してから、次のテキストを
     貼り付けてEnterを押す（`crlf-sample.txt` を排他ロックしたまま止まります。**この
     PowerShellウィンドウは閉じずに、次の手順が終わるまでそのまま開いておいてください**）。
     ```powershell
     $fs = [System.IO.File]::Open("crlf-sample.txt", 'Open', 'ReadWrite', 'None')
     Write-Host "crlf-sample.txt をロックしています。確認が終わったら何かキーを押してください..."
     [Console]::ReadKey($true) | Out-Null
     $fs.Close()
     Write-Host "ロックを解除しました。"
     ```
  2. （手順1のウィンドウはそのまま）Graftで手順1-3と同じ `01_正常系_文字コード改行往復.txt`
     の内容をもう一度貼り付けて適用してみる（`crlf-sample.txt` を含む、他4ファイルも
     含むパッチです）。
  3. 確認が終わったら、手順1のPowerShellウィンドウに戻って何かキーを押し、ロックを
     解除する。
- **期待する結果**: `crlf-sample.txt` への適用だけが「ファイルが使用中です」といった
  趣旨のエラーになり、他のファイルへの適用はロックの影響を受けず成功する。Graftが
  クラッシュしたりフリーズしたりしない。
- **結果が違った場合に報告してほしいこと**: エラーメッセージの文面。ロックされていない
  他のファイルまで巻き込まれて失敗するか。Graftが応答しなくなるか。

### 2-4. クリップボード監視

- [ ] **なぜ確認するか**: `AddClipboardFormatListener` によるクリップボードの変更通知は
      Windows実機でしか確認できないため。
- **所要時間**: 5分
- **手順**:
  1. 設定（`Ctrl+,`）→「表示・コンテキスト」タブ→「クリップボード監視を有効にする」を
     オンにする。
  2. Graftのウィンドウを最小化する、または別のアプリ（メモ帳など）を前面に出す。
  3. `Graft検証サンプル\patches\01_正常系_文字コード改行往復.txt` をメモ帳などで開き、
     中身をすべて選択してコピーする。
- **期待する結果**: コピーした直後にGraft側で「パッチらしいテキストを検知した」ことが
  分かる反応（通知や確認ダイアログなど、設定の「クリップボード監視反応時の挙動」に
  沿った挙動）が起きる。
- **結果が違った場合に報告してほしいこと**: 何も反応しないか。逆に、パッチと無関係な
  普通のコピー操作にまで反応してしまうか。
- **元に戻す手順**: 検証後、設定で「クリップボード監視を有効にする」をオフに戻す
  （常時有効にしておきたい場合はオンのままで構いません）。

## 3. 余裕があれば（目安 約25分）

### 3-1. グローバルホットキー（Ctrl+Alt+V）

- [ ] **なぜ確認するか**: `RegisterHotKey` によるOS全体のホットキー登録はWindows実機でしか
      確認できないため。既定のキーは `Ctrl+Alt+V` です。
- **所要時間**: 5分
- **手順**:
  1. Graftのウィンドウを最小化する、または別のアプリを前面に出す。
  2. `01_正常系_文字コード改行往復.txt` の中身をコピーする。
  3. `Ctrl+Alt+V` を押す。
- **期待する結果**: Graftのウィンドウが最前面に復元され、コピーしていたパッチが
  自動的に貼り付け・解析される（手順1-3で `Ctrl+V` を押したときと同じ状態になる）。
- **結果が違った場合に報告してほしいこと**: 何も起きないか。別のアプリが先に
  `Ctrl+Alt+V` を使っていて競合するか（お使いのPCに他のツールが入っている場合、
  そちらが先に反応することがあります。その場合はその旨だけ教えてください）。

### 3-2. システムテーマ追従（ライト/ダーク切り替え）

- [ ] **なぜ確認するか**: レジストリの `AppsUseLightTheme` 値の読み取りと変更通知は
      Windows実機でしか確認できないため。
- **所要時間**: 5分
- **手順**:
  1. Graftを起動したまま、Windowsの設定 → 個人用設定 → 色 で「モードを選ぶ」を
     「ライト」⇔「ダーク」に切り替える。
- **期待する結果**: （Graftのテーマ設定が「システムに合わせる」になっている場合）
  数秒以内にGraftの配色が追従して切り替わる。
- **結果が違った場合に報告してほしいこと**: 追従しないか。Graftを再起動しないと
  反映されないか。

### 3-3. エクスプローラで表示

- [ ] **なぜ確認するか**: `explorer.exe /select,` の起動はWindows実機でしか確認できないため。
- **所要時間**: 3分
- **手順**:
  1. Graftのエクスプローラでいずれかのファイルを右クリックし、「エクスプローラで表示」を
     選ぶ。
- **期待する結果**: Windowsのエクスプローラが新しく開き、該当ファイルが選択された状態で
  表示される。
- **結果が違った場合に報告してほしいこと**: 何も起きないか、エラーが出るか。

### 3-4. 自動起動（PC起動時に自動で立ち上がる）

- [ ] **なぜ確認するか**: レジストリではなくスタートアップフォルダへ `.cmd` ファイルを
      置く方式を採っており、この `.cmd` が実機で問題なく動くかは未確認のため。
- **所要時間**: 5分
- **手順**:
  1. 設定（`Ctrl+,`）→「一般」タブ→「PC起動時に自動で起動する」をオンにする。
  2. エクスプローラのアドレスバーに
     `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup` と入力してEnterを押し、
     `Graft.cmd` が作成されていることを確認する。
  3. 可能であればPCを再起動し、自動的にGraftが起動することを確認する。再起動が
     難しい場合は、手順2のフォルダの `Graft.cmd` をダブルクリックで手動実行し、
     Graftが問題なく起動することだけ確認してください。
- **期待する結果**: `Graft.cmd` が作成される。実行すると、黒いコンソール画面がほぼ表示
  されないまま（一瞬だけなら正常）、Graft本体だけが起動する。
- **結果が違った場合に報告してほしいこと**: 黒いコンソール画面が表示されっぱなしに
  なるか。Graft本体が起動しないか。
- **元に戻す手順**: 設定の「PC起動時に自動で起動する」をオフに戻す
  （`Graft.cmd` は自動的に削除されます）。手動で消したい場合は、上記スタートアップ
  フォルダから `Graft.cmd` を直接削除しても構いません。

### 3-5. タスクトレイに常駐する（×ボタンの動作を変更）

- [ ] **なぜ確認するか**: 1-1で確認したのは既定の「終了する」設定です。「タスクトレイに
      常駐する」を選んだ場合の、Windowsのシェル通知領域(NotifyIcon)との連携は別途
      確認が必要なため。
- **所要時間**: 5分
- **手順**:
  1. 設定（`Ctrl+,`）→「一般」タブ→「ウィンドウを閉じたときの動作」を
     **「タスクトレイに常駐する」** に変更する。
  2. ウィンドウ右上の×ボタンをクリックする。
  3. タスクマネージャーで `Graft.exe` のプロセスが残り続けていることを確認する。
  4. タスクトレイ（画面右下、隠れている場合は `^` マークの中）のGraftアイコンを右クリックし、
     「開く」「クリップボード監視」「設定」「終了」などのメニューが表示されることを確認する。
  5. 「開く」を選び、ウィンドウが元どおり表示されることを確認する。
  6. 最後にトレイメニューの「終了」を選び、Graftを完全に終了する。
- **期待する結果**: ×を押してもプロセスは終了せず、タスクトレイから操作を再開したり
  完全に終了したりできる。
- **結果が違った場合に報告してほしいこと**: ×を押すとプロセスごと終了してしまうか
  （常駐しない）。トレイアイコンが表示されないか。メニューの項目を選んでも反応しないか。
- **元に戻す手順**: 設定の「ウィンドウを閉じたときの動作」を **「終了する」**（既定値）に
  戻す。
