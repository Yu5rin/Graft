# 確認手順: AttachThreadInputによる前面化回避策

前回の Windows 実機確認で、クリップボード監視での前面化がタスクバーの**点滅のみ**に
とどまり（`SetForegroundWindow` がOSのフォーカス窃取防止に拒否される）前面へ出なかった件の
修正確認です。所要時間は 20 分程度を想定しています。

対象の変更:

| コミット | 内容 | 実機確認 |
|---|---|---|
| （本ドキュメント作成時点の HEAD） | `WindowsSingleInstanceGuard.ActivateWindowHandle` に `AttachThreadInput` による回避策を追加 | 必要 |

---

## 1. ビルド

```powershell
cd C:\Users\YUGO\Graft
git pull
git log --oneline -1
```

コミットハッシュがこのブランチの最新（本対応のコミット）であることを確認してください。

```powershell
cd C:\Users\YUGO\Graft
Remove-Item -Recurse -Force publish\Graft -ErrorAction SilentlyContinue
dotnet publish src\Graft\Graft.csproj -c Release -r win-x64 --self-contained true -o publish\Graft
```

> **注意**: 発行先には `settings.json` `projects.json` `back/` `logs/` も置かれます。
> `Remove-Item` でそれごと消えるため、履歴を残したい場合は先に退避してください。

`publish\Graft\Graft.exe` を起動してから、以下へ進んでください。

## 2. 前面化（今回の本命）

### 2-1. 他アプリ操作中に前面へ出る　★最重要

前回 **NG**（点滅のみで前面に出なかった）だった状況の再確認です。

- [ ] Graft を起動したまま、**メモ帳を開いて前面**にする（Graft は背後）。
- [ ] メモ帳の入力欄をクリックして操作中の状態にする（カーソルを点滅させておく）。
- [ ] メモ帳に何か適当な文字を打ち込んでから、次を貼り付け、**全選択してコピー**する。

```
<<<< PATCH
summary: AttachThreadInput確認1
type: feat
>>>>

<<<< FILE: note.txt
<<<<<<< SEARCH
バージョン: 初期
=======
バージョン: 1
>>>>>>> REPLACE
```

**期待**: コピーした瞬間に Graft が**前面に出てくる**（タスクバーの点滅で終わらない）。

**NG のとき（前面に出ず点滅のみ等）報告してほしいこと**:
- タスクバーの Graft アイコンが**点滅したか**
- 次のログ（末尾20行。`縮退しました` の警告が出ているはず）

```powershell
Get-Content -Encoding UTF8 (Get-ChildItem C:\Users\YUGO\Graft\publish\Graft\logs\*.log | Sort-Object LastWriteTime | Select-Object -Last 1) -Tail 20
```

### 2-2. 複数のアプリ・複数回で安定して前面へ出る

- [ ] メモ帳の代わりに**別のアプリ**（ブラウザ・エクスプローラ等）を前面にした状態で、
      2-1 と同様にパッチをコピーする（内容は毎回変える。同じ内容だと反応しません）。
- [ ] 上記を **3〜4 種類のアプリ**で試す。

**期待**: いずれのアプリが前面でも Graft が前面に出る。

### 2-3. それでも縮退する場合の切り分け（NGのときのみ）

2-1・2-2 で NG だった場合のみ実施してください。

- [ ] ログに次の警告が出ているか確認する。

```
warn clipboard: クリップボード監視での前面化がOS側の制約により縮退しました
```

- [ ] 出ている場合は「AttachThreadInputでも回避できなかった」ケースです。上記ログの
      末尾20行と、その時点で前面にあったアプリ名を報告してください。
- [ ] 出ていない場合（前面化はできていないが警告ログも無い）は、前面化の判定
      （`ClipboardActivationOutcome`）自体が別の分岐に入っている可能性があるため、
      ログをもう少し広めに（末尾50行）採取して報告してください。

### 2-4. 最小化・既に前面・通常テキストは従来どおり（回帰していないか）

前回 OK だった項目です。壊れていないことの確認。

- [ ] Graft を**最小化**し、また別の内容のパッチをコピーする。
      **期待**: 最小化から復帰して前面に出る。
- [ ] Graft を**前面にしたまま**、また別の内容のパッチをコピーする。
      **期待**: ウィンドウの位置・大きさが変わらず、ちらつきもない。
- [ ] 「これはただの文章です」など、パッチ形式でないテキストをコピーする。
      **期待**: 前面化も通知も起きない。

### 2-5. 多重起動検出時の前面化は変わっていないか（回帰していないか）

- [ ] Graft を起動したまま、`Graft.exe` をもう一つ起動する（またはショートカットから
      二重起動を試みる）。

**期待**: 従来どおり（後発のプロセスは起動を継続せず、既存のウィンドウが前面化を試みる。
これはOS側の制約で点滅にとどまることがあり、それ自体は今回の対応範囲外・変更していません）。

## 3. 他アプリのキーボード入力への影響確認　★最重要

`AttachThreadInput` は解除を漏らすと**他アプリのキーボード入力・IME変換に影響し得る**
仕組みです。解除漏れが無いことを、前面化を繰り返したあとの入力で確認します。

- [ ] メモ帳を開き、日本語入力（IME）をオンにしておく。
- [ ] 2-1・2-2 の要領で、**内容を変えながら前面化を 10 回ほど繰り返す**
      （メモ帳を前面に戻す → パッチをコピー → Graft が前面に出る → メモ帳をまた前面にする、
      を1セットとして10回）。
- [ ] 10 回終えたら、メモ帳の入力欄をクリックし、日本語で適当な文章を入力してみる
      （例:「これはあいうえおのてすとです」と打って変換する）。

**期待**:
- 通常どおり日本語入力ができ、**変換候補が出て変換できる**。
- キー入力の**取りこぼし・重複・無反応**が無い。
- メモ帳以外のアプリ（ブラウザのアドレスバー等）でも同様に入力できる。

**NG のとき報告してほしいこと**: どのアプリで・どの操作（入力／変換／ショートカットキー等）が
おかしくなったか、できるだけ具体的に。
