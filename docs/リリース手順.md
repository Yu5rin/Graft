# リリース手順

Graftの配布物（Windows版のZIPとLinux版のtar.gz）を作成し、GitHub Releaseとして公開するまでの
手順です。`tools\New-Release.ps1` がビルド・同梱物の配置・書庫の作成・検証までを1コマンドで
行うので、手作業で個々のファイルを
集める必要はありません。

## 手順

1. **`main` を最新にする**

   ```
   git checkout main
   git pull origin main
   ```

2. **`tools\New-Release.ps1` を実行する**

   ```
   powershell -ExecutionPolicy Bypass -File tools\New-Release.ps1
   ```

   既定では `src\Graft\Graft.csproj` の `<Version>` からバージョンを算出し、`publish\release\Graft`
   へ発行したうえで、リポジトリ直下に `Graft-<バージョン>-win-x64.zip` と
   `Graft-<バージョン>-linux-x64.tar.gz` を作成します。Windows上からでもLinux版を
   発行できます（.NETがクロスOSの発行に対応しているため）。
   作業ツリーが汚れている場合は警告して中断します（問題なければ `-Force` を付けて再実行してください）。

3. **出力された配布物と `リリース説明.md` を確認する**

   - Windows版: リポジトリ直下の `Graft-<バージョン>-win-x64.zip`
   - Linux版: リポジトリ直下の `Graft-<バージョン>-linux-x64.tar.gz`
   - リリース本文の前文: `publish\release\リリース説明.md`
     （`docs\リリース説明_テンプレート.md` をそのまま書き出したものです）

   スクリプトが表示する「ZIPの中身一覧」「tar.gzの中身」「`Graft.exe` のファイルバージョン」も
   合わせて確認してください。

   Linux版をzipではなくtar.gzにしているのは、zipがUnixのファイル属性を持てず実行権限が
   失われるためです。ただし**Windows上で作ったtar.gzは実行権限が付かないことがあります**
   （NTFSにその概念が無いため）。同梱の `はじめにお読みください.txt` には常に
   `chmod +x Graft` の案内を載せてあります。

4. **タグを作成してpushする**

   ```
   git tag -a v<バージョン> -m "Graft <バージョン>"
   git push origin v<バージョン>
   ```

5. **GitHubでリリースを作成する**

   [リリース作成画面](https://github.com/Yu5rin/Graft/releases/new) を開き（`tools\New-Release.ps1`
   の実行結果にも直接開けるURLが表示されます）、次を行います。

   - **Target は `main`** を選ぶ
   - タグは手順4で作成した `v<バージョン>` を選ぶ
   - 本文に `publish\release\リリース説明.md` の内容を貼り付ける
   - 続けて **「Generate release notes」** を押し、`What's Changed` と
     `Full Changelog` を末尾に足す
   - `Graft-<バージョン>-win-x64.zip` と `Graft-<バージョン>-linux-x64.tar.gz` を添付する

---

## 注意点

### バージョン表記は3点区切り（例: `1.0.1`）

ZIP名・タグ・`はじめにお読みください.txt`・リリース説明.md等、利用者向けの表記は
`src\Graft\Graft.csproj` の `<Version>` の値をそのまま使います（桁を補いません）。
**`v1.0.0.0` / `Graft-1.0.0.0-win-x64.zip` だけは例外**で、最初のリリースを実際に4点区切り
（`v1.0.0.0`）で公開してしまった経緯により、過去の実物に合わせてそのままにしています。
`1.0.1` 以降は3点区切りが基本です。

### 発行先は `publish\Graft` とは別

`tools\New-Release.ps1` の発行先は既定で **`publish\release\Graft`** です。これは利用者が普段
使う **`publish\Graft`（README「発行」節の手順で作る場所）とは別のフォルダ**です。

`tools\New-Release.ps1` は実行前に発行先フォルダを削除してから発行し直します。誤って
`publish\Graft` を発行先に指定すると、そこに置いてある `settings.json` / `projects.json` /
`back/`（バックアップ）/ `logs/` が消えてしまいます。過去に実際、利用者へ「`publish\Graft` を
消してからpublishする」という手順を案内してしまい、設定・履歴・バックアップを毎回失わせる
という迷惑をかけたことがあります。同じ事故を防ぐため、スクリプト側でも `publish\Graft` を
発行先に指定した場合は `-Force` を付けても中断するようにしています。

### `.github/workflows/release.yml` はタグpushで自動発火しない

Graftのリリースは、上の手順のとおり `tools\New-Release.ps1` で作った書庫を手作業で
GitHub Releaseへ添付する方針です。`.github/workflows/release.yml` はテスト・発行から
GitHub Release作成までを自動で行うワークフローですが、タグpushで自動発火する設定のままだと
手作業のリリースと二重に動いてしまい、同じ版の書庫が複数並んで公開される事故になります
（実際に`v1.0.1`で発生し、`Graft-1.0.1-win-x64.zip`と`Graft-v1.0.1-win-x64.zip`・
`Graft-v1.0.1-linux-x64.tar.gz`が同じリリースに混在してしまいました）。そのため
`release.yml`のトリガは`workflow_dispatch`（Actions画面からの手動実行）のみにしてあります。
タグをpushしても`release.yml`は動きません。

### コード署名をしていない

Graftにはコード署名証明書を付けていません。配布したZIPを展開して `Graft.exe` を実行すると、
Windowsの SmartScreen が「WindowsによってPCが保護されました」という警告を表示します。
これは異常ではなく、内容を確認のうえ「詳細情報」→「実行」で起動できます。
（`はじめにお読みください.txt` にも同じ案内を同梱しています。）

### `datapath.txt` とフォルダの差し替え

保存先をユーザーフォルダ（`%APPDATA%\Graft`）へ移した利用者の環境では、実際の保存先を指す
`datapath.txt` が `Graft.exe` と同じフォルダに置かれます。新しい版のフォルダへ差し替える際に
この `datapath.txt` ごと入れ替えてしまっても、Graftは起動時に「以前ユーザーフォルダに保存した
データが見つかりました」と復帰確認ダイアログを出すため、そこで「はい」を選べば設定・履歴・
バックアップを失わずに済みます（詳細は `docs\取扱説明書.md` の「データの保存場所」章を参照）。

## リリース本文の形式

リリース本文は、次の2つを上下に並べた形で統一します。

1. **前文**（`docs\リリース説明_テンプレート.md`）
   導入・動作環境と、「変更点は下の自動生成された一覧を参照してください。」の一文まで。
   バージョン番号は含めません（版ごとに書き換える箇所を作らないため）。
2. **変更点**（GitHubの「Generate release notes」が出す `What's Changed` と `Full Changelog`）

変更点の一覧をこちらで組み立てないのは、GitHub側の自動生成と二重になり、書き漏れや
食い違いが起きるためです。`tools\New-Release.ps1` も前文を書き出すだけで、変更点には
一切触れません。

`docs\変更履歴.md` はリポジトリ側の記録として残していますが、リリース本文には
差し込みません。
