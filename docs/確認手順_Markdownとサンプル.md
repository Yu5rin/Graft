# 確認手順: Markdownプレビューと構文強調のサンプル確認

対象コミット: （このドキュメントをコミットした時点の HEAD。`git log --oneline -1` で確認してください）
ブランチ: `claude/spec-implementation-7fhplo` から分岐した作業ブランチ

この手順書は、`tools\New-MarkdownTestSample.ps1` が生成するサンプル一式を使って、Markdownプレビューと構文強調（シンタックスハイライト）が**Windows実機で正しく動くか**を確認するためのものです。

Markdownの記法拡張（斜体・打ち消し線・引用・画像・入れ子リスト・脚注など）は開発が進行中の機能です。この手順は「現時点で何が正しく表示され、何がまだ表示されないか」を洗い出すためのものでもあります。**表示されない記法があっても、それ自体は異常ではありません**（下の「現時点で正しく表示されないと分かっている記法」を参照）。ここで報告してほしいのは、期待どおりに表示された/されなかったことの事実そのものです。

所要時間の目安: 約15〜20分。

---

## 0. 現時点で正しく表示されないと分かっている記法（Linux開発環境での確認結果）

開発環境（Linux/Xvfb）で事前に確認した限り、以下の記法は**現時点では未対応**で、記号がそのまま文字として見えてしまいます。Windows実機でも同じはずですが、**違いがあれば report してください**（例: Linuxでは動かなかったのにWindowsでは動く、あるいはその逆）。

- 斜体（`*text*` / `_text_`）… 記号がそのまま見える
- 打ち消し線（`~~text~~`）… 記号がそのまま見える
- 引用（`>` / `>>`）… 記号がそのまま見え、複数行がくっついて1行のように表示される
- 画像（`![alt](url)`）… 画像は表示されず、「!」と代替テキストのリンクふうの表示になる
- 箇条書きの入れ子（2階層目以降）… インデントが付かず、すべて同じ階層に見える
- 脚注（`[^1]`）… 記号がそのまま見え、ジャンプもしない

一方、以下は**現時点で正しく動いています**（Linux開発環境での確認結果）。

- 見出し（レベル1・2は文字の大きさが違う。レベル3〜6は同じ大きさ）
- 太字（`**text**`）
- インラインコード（`` `code` ``。中の`**`等の記号は装飾されずそのまま表示される）
- 箇条書き・番号付きリスト（1階層のみ。混在時はリストの種類ごとに別ブロックとして表示される）
- チェックリスト（チェック済み・未チェックとも表示される。ただし入れ子は上と同じくインデントされない）
- 表（見出し行・複数列・セル内の太字/インラインコード）
- 水平線
- リンク（文書内アンカー・相対リンク・外部リンクの3種とも）
- コードブロック（言語指定ありは対応言語なら色が付き、なし/未対応なら等幅のまま）

## 1. ビルド

PowerShell を開いて、上から順に貼り付けて実行してください。


続けて自動テストとビルドを実行します。


**期待する結果**: `dotnet build` が警告0・エラー0で成功する。両方の `dotnet test` が全件成功する（Linux開発環境では Graft.Tests 552件、Graft.UiTests 550件がすべて成功しています。Windows実機でこれと異なる結果になった場合は、そのまま報告してください）。

続けて発行（単一ファイルの exe を作る）します。


## 3. Markdownプレビューの確認

`publish\Graft\Graft.exe` を起動してください。初回起動時にオンボーディング画面が出た場合は「スキップ」で閉じてください。

- [ ] プロジェクトペインで、デスクトップの `Graft検証サンプル_Markdown\project` フォルダを登録する。
- [ ] `sample.md` をダブルクリックで開く。既定でプレビュー表示になっているはずです（なっていなければ、プレビュー切り替えボタンを押してください）。

**期待する結果**: 上から順に「Markdown記法とシンタックスハイライトの確認サンプル」というタイトルと、目次以下の本文が装飾された状態で表示される（生のMarkdown記号`#`や`**`がそのまま見えている箇所がある場合は、上の「0. 現時点で正しく表示されないと分かっている記法」に該当するかどうかを確認してください）。

### 3-1. 目次（文書内アンカー）

- [ ] 目次の「表の確認」をクリックする。

**期待する結果**: 本文の「表の確認」見出しへ表示がジャンプする。

### 3-2. 相対リンク（別のMarkdownファイル）

- [ ] 「リンクの確認」章の「相対リンクの確認: 同じフォルダのlinked.mdを開く」をクリックする。

**期待する結果**: `linked.md` がGraftの新しいタブとして開く。中身に「これは`sample.md`から相対リンクで開くための確認用ファイルです。」という文章があること。`linked.md` 内の「sample.mdへ戻る」リンクをクリックすると `sample.md` のタブへ戻れることも確認してください。

### 3-3. 外部リンク

- [ ] 「リンクの確認」章の「外部リンクの確認: example.comを開く」をクリックする。

**期待する結果**: 確認ダイアログが出る（すぐにブラウザが開かない）。ダイアログで開くことを選ぶと、既定のブラウザで `https://example.com` が開く。

### 3-4. 見出し・太字・インラインコード・チェックリスト・表・コードブロック

- [ ] 「見出しの確認」〜「コードブロックの確認」まで、上から順にスクロールしながら目視で確認する。各見出しの直下に書かれた「期待される見た目」の説明と、実際の表示を見比べてください。

**期待する結果（今回の実装で正しく動くはずの項目）**:
  - 見出しレベル1・2は他より大きく表示される
  - 太字・インラインコードが正しく装飾される
  - チェックリストにチェックボックスが表示される（入れ子はインデントされなくても構いません）
  - 表が罫線付きで表示される
  - コードブロックが言語ごとに色分けされる（Python/C#/JavaScript/TypeScript/CSS/JSON/HTML/XML/YAML/SQL/シェルスクリプトの11種、それぞれキーワード・文字列・コメントの色が違うこと）
  - 言語指定なしのコードブロックは色が付かず等幅表示のみになる

**期待する結果（現時点では未対応のはずの項目。表示されなくても異常ではありません）**:
  - 斜体・打ち消し線・引用・入れ子の箇条書き・画像・脚注

**違った場合に報告してほしいこと**: 「0. 現時点で正しく表示されないと分かっている記法」に挙げた項目が**Windows実機では逆に正しく表示された**場合、あるいは「正しく動くはずの項目」が**Windows実機では正しく表示されなかった**場合は、両方とも報告してください（前者は良い意味での差異、後者は環境依存の不具合の可能性があります）。可能であればスクリーンショットを添えてください。

## 4. 構文強調（エディタ本体）の確認

Markdownプレビューとは別に、通常の編集画面での構文強調（シンタックスハイライト）も確認します。

- [ ] プロジェクトペインで `project\構文ハイライト確認` フォルダの中を開き、`highlight-sample.css`・`highlight-sample.py`・`highlight-sample.js`・`highlight-sample.json`・`highlight-sample.cs`・`highlight-sample.html`・`highlight-sample.xml`・`highlight-sample.yaml`・`highlight-sample.sql`・`highlight-sample.sh` を順番に開く。

**期待する結果**: いずれのファイルも**1行目から内容が表示される**（1行目が空白・欠落していないこと。過去に「1行目が欠ける」不具合があったための確認項目です）。拡張子に応じてキーワード・文字列・コメントに色が付く。

**違った場合に報告してほしいこと**: 1行目が欠けている・空白になっている場合は最優先で報告してください。色が付かない拡張子があれば、そのファイル名を報告してください。
