## 1. Graftとは何か

Graftは、**AI（ChatGPT・Claudeなど）が提案したコードの変更を、手元のプロジェクトへ安全に取り込むためのデスクトップアプリ**です。

AIにコードの修正を頼むと、多くの場合「このファイルのこの部分をこう直してください」という形で回答が返ってきます。その回答を自分の目でファイルへ手作業で反映するのは、範囲が広くなるほど手間がかかり、写し間違いも起きがちです。Graftは、AIに決まった書式（後述の「パッチの形式」）で回答してもらい、その回答を読み取って実際のファイルへ機械的に適用します。

Graftが担っているのは、次のような一連の往復です。

1. Graftから「この形式で答えてください」という指示文（プロンプト）をコピーし、AIとの会話の最初に貼り付ける
2. AIに直してほしい内容を伝え、AIの回答をコピーする
3. Graftへ貼り付けて解析する
4. 実際にどう変わるか（差分）を画面で確認する
5. 問題なければ適用する。ファイルへ書き込まれる直前に必ずバックアップが作られるので、結果が気に入らなければいつでも元に戻せる

Graftはこの往復を素早く・安全に繰り返すための道具です。汎用のコードエディタやAIチャットの機能そのものを置き換えるものではなく、あくまで「AIの出力とファイルの橋渡し」に専念しています。

## 2. 最初の5分

初めて起動すると「Graftへようこそ」という初回起動ガイドが開きます。3つの画面（導入・プロジェクト登録・プロンプトのコピー）を順に進めるだけで、ひととおりの流れを体験できます。ガイドは「スキップ」でいつでも終了でき、あとから同じ操作を通常の画面からやり直すこともできます。

### 2.1 自分のプロジェクトを使わずに試したいとき（サンプルで試す）

初回起動ガイドの2画面目「プロジェクトを登録」には、「サンプルで試す」というボタンがあります。これを押すと、自分のフォルダには一切触れずに、Graftが用意した練習用のサンプル（サンプルのPythonファイル1件と、それを直すためのサンプルパッチ）が一時フォルダへ生成され、そのままプロジェクト一覧に登録されます。サンプルパッチは自動的にクリップボードへコピーされるので、あとはツールバーの「解析」→内容確認→「適用」の順に押すだけで、実際にファイルが書き換わり、履歴にも記録される様子を一通り体験できます。体験が済んだら「サンプルを削除」でいつでも片付けられます（消さずに終了しても一時フォルダなので、最終的にはOSが片付けます）。

### 2.2 自分のプロジェクトで使う場合の最短の流れ

1. **起動する**
   Graftを起動すると、前回開いていたプロジェクトとウィンドウの配置がそのまま復元されます。
2. **プロジェクトを登録する**
   まだ一度も登録していないフォルダを使う場合は、コマンドバーのプロジェクト選択や設定画面から、これから変更を加えたいプロジェクトのルートフォルダ（普段コードエディタで開いているフォルダ）を選んで登録します。フォルダの中身自体はこの時点では変更されません。
3. **AI向けのプロンプトをコピーする**
   コマンドバーの「プロンプト」ボタンを押すとテンプレートを選ぶ小さな一覧が開くので、選んで「コピー」を押します。急いでいるときはCtrl+Shift+Cを押すと、一覧を開かずに推奨のテンプレートをその場で直接コピーできます。どちらも、AIに「Graftが読み取れる決まった形式で回答してください」と伝えるための指示文がクリップボードへコピーされます。これをAIとの会話の最初に貼り付けてから、直してほしい内容を伝えます。
4. **AIの回答をコピーして貼り付ける**
   AIの回答（パッチ本文）をコピーし、Graftのコマンドバーの「解析」ボタン（またはCtrl+Shift+V）を押します。クリップボードの内容が読み取られ、接ぎ木パネルにブロック（1件ずつの変更）の一覧として表示されます。
5. **差分を確認する**
   一覧の各行を選ぶと、その変更が実際にどう反映されるかの差分（変更前後の比較）を確認できます。適用したくない変更があれば、チェックを外して対象から外せます。
6. **適用する**
   問題なければコマンドバーの「適用」ボタン（またはCtrl+Enter）を押します。書き込む前に自動でバックアップが作られ、設定によっては書き込み直前の最終確認画面（プレビュー）も挟まります。適用が終わると、変更したファイルはエディタで最新の内容に更新され、履歴にも記録されます。

慣れてきたら、最初の登録以降は3〜6の繰り返しだけで、AIとの往復を回せるようになります。

## 3. パッチの形式

Graftは、AIの回答から2種類の形式を読み取れます。**どちらの形式かを自分で指定する必要はなく、貼り付けた内容から自動的に判別されます。**

### 3.1 Graft形式（推奨）

Graft独自の形式で、AIに直接この形で出力させることを想定しています。パッチ全体は要約（`<<<< PATCH` 〜 `>>>>`）から始まり、続けてファイルごとの変更ブロックが並びます。

**既存ファイルの一部を直す場合（SEARCH/REPLACE形式）**: 変更前のコード（`SEARCH`）と変更後のコード（`REPLACE`）を対で示します。AIはファイル全文を出力する必要がなく、変更箇所だけを書けばよいので、長いファイルでも効率よく扱えます。

```
<<<< PATCH
summary: greet関数であいさつ文を組み立てて返すようにする
type: fix
>>>>

<<<< FILE: src/app.py
<<<<<<< SEARCH
def greet(name):
    pass
=======
def greet(name):
    return f"Hello, {name}!"
>>>>>>> REPLACE
```

**新規ファイルを作る場合（FULL形式）**: `MODE=FULL` を指定し、ファイルの全文をそのまま書きます。

```
<<<< FILE: src/new_module.py MODE=FULL
（ファイルの全文）
>>>> END
```

このほか、ファイルの削除（`<<<< DELETE:`）・改名（`<<<< RENAME: 旧パス -> 新パス`）・フォルダの作成（`<<<< MKDIR:`）・末尾/先頭への追記（`<<<< APPEND:` / `<<<< PREPEND:`）にも対応しています。

### 3.2 unified diff形式

`git diff` や多くのAIが標準で出力する `--- a/ファイル` / `+++ b/ファイル` / `@@ ... @@` から始まる一般的な差分形式（unified diff）も、そのまま貼り付けて解析できます。Graft形式の指示をしていないAIの回答でも、diff形式で出力してくれれば取り込めます。

### 3.3 AIに出力させるためのプロンプト例

コマンドバーの「プロンプト」ボタンから選べる指示文（プロンプトテンプレート）のうち、最初にAIへ貼り付ける「初回用（完全版）」の内容は次のとおりです。これをAIとの会話の最初に貼り付けてから、直してほしい内容を伝えてください。

```
コードの修正を提案する際は、必ず以下の形式で出力してください。

まずパッチ全体の要約を書きます。
<<<< PATCH
summary: （変更内容を1行で）
type: feat|fix|refactor|docs|test|chore
>>>>

【原則】既存ファイルの修正はSEARCH/REPLACE形式を使い、
ファイル全文の再出力はしないでください。

<<<< FILE: 相対パス
<<<<<<< SEARCH  # このペアの変更内容を1行で
（修正前のコード。一意に特定できる最小限の行数）
=======
（修正後のコード）
>>>>>>> REPLACE

新規ファイルのみ以下を使用してください。
<<<< FILE: 相対パス MODE=FULL
（全文）
>>>> END

説明文はブロックの外に書いてください。

【エスケープ規則】ブロック本文の行頭に <<<<、>>>>、======= が現れる場合は、直前に \ を置いてエスケープしてください（例: \<<<< FILE: 相対パス）。パーサ適用時に先頭の \ を1つ取り除きます。多数のエスケープが必要な場合は、ヘッダに FENCE=<任意文字列> を指定し、終了マーカーを >>>> END:<任意文字列> に変更できます。

<<<< PATCH は出力全体で1回だけにし、必ず >>>> で閉じてください。SEARCH/REPLACEは ======= と >>>>>>> REPLACE で、MODE=FULLは >>>> END で、開いたブロックは必ず閉じてください。出力する前に、開始マーカーと終了マーカーの数が対応しているか自分で確認してください。

パッチ全体（<<<< PATCH から最後の >>>> や >>>> END まで。説明文は含めない）を、1つのコードブロックとして囲んで出力してください（1行目に ```text、最終行に ``` と書きます。チャットのコピー機能で一括コピーできるようにするためです）。パッチ本文に ``` が含まれる場合（Markdownファイルの編集など）は、外側をバッククォート4個にし、1行目を ````text、最終行を ```` としてください。
```

同じ会話を続けて2回目以降にAIへ回答させるときは、直近1時間以内であれば「継続用（短縮版）」（「先ほどと同じGraft形式（PATCHメタ + SEARCH/REPLACE）で出力してください。<<<< PATCH は1回だけにし、パッチ全体を1行目```text・最終行```で囲んでください（本文に```を含む場合は````）。」）が自動的に選ばれ、指示文を短く済ませられます。このほか、AIに一部の変更だけをやり直させる「修正依頼」、新規ファイルの作成を頼む「新規実装」、コードを直接出力させず原因の説明から始めさせる「調査依頼」のテンプレートも用意されています。プロンプトの内容自体は、設定画面の「プロンプトテンプレート」タブから自由に書き換えられます。

## 4. 画面の説明

Graftの画面は、左からサイドバー・サイドビュー・エディタ（中央）・接ぎ木パネルの順に並びます。

### 4.1 サイドバー（画面左端の細い帯）

4つのアイコンで、下のサイドビューに表示する内容を切り替えます。同じアイコンをもう一度押すとサイドビューを折りたたんで隠せます。

- **プロジェクト**: 登録済みのプロジェクトの一覧。
- **エクスプローラ**: 選択中プロジェクトのファイル・フォルダ構成。ファイルを開く、新規作成、名前の変更、削除などの操作をここで行います。
- **履歴**: これまでに適用・復元した変更（リビジョン）の一覧。
- **検索**: プロジェクト全体を横断したファイル内検索。

### 4.2 エディタ（画面中央）

タブ形式のコードエディタです。ファイルを開くとタブとして並び、複数のファイルを同時に編集できます。差分の確認も、専用のタブとしてこの領域に開きます。

### 4.3 接ぎ木パネル（既定では画面下部、右配置にも切り替え可能）

パッチを解析すると自動的に開きます。解析された変更が1ブロックずつ一覧になっており、各行にはファイルパスと変更内容のひとこと説明、適用できるかどうかの状態アイコン、適用対象に含めるかどうかのチェックボックスが並びます。上部には「解析結果を破棄」「プレビューを再実行（ドライラン）」「適用」などの操作ボタンがあります。パネルのヘッダーから、パネルを画面下と画面右のどちらに配置するかも切り替えられます。

### 4.4 ステータスバー（画面最下部）

現在のカーソル位置（行:列）、選択文字数、文字コード、改行コード、言語、クリップボード監視の状態、直前の適用・削除の取り消し案内などを表示します。

## 5. 主な機能

### 5.1 クリップボード監視

設定でオンにすると、AIの回答らしき内容がクリップボードにコピーされたことを自動的に検知します。検知したときの挙動（自動で解析する、Graftを前面に表示する、通知だけにする、など）は設定画面の「表示・コンテキスト」タブで細かく調整できます。ステータスバーのアイコンから、一時的に監視を止める（一時停止）こともできます。

### 5.2 履歴と復元

「適用」するたびに1件のリビジョンとして記録され、サイドバーの「履歴」ビューから一覧で確認できます。

- **単発復元（このリビジョンを取り消す）**: 選んだ1件だけを取り消し、適用する直前の状態に戻します。
- **ここまで戻す（選択したリビジョンまでまとめて戻す）**: 選んだリビジョンより新しい変更をすべて取り消し、その時点までまとめて戻します。
- **ファイル単位の履歴**: エクスプローラでファイルを右クリックし「このファイルの変更履歴」を選ぶと、履歴ビューがそのファイルに関わるリビジョンだけに絞り込まれます。

履歴の一覧は、summary（変更のひとこと要約）による絞り込み検索、種別、期間（今日・今週などのプリセットも含む）でも絞り込めます。

### 5.3 コンテキスト収集

サイドバーのエクスプローラ上部やコマンドバーの「ファイル」ボタンから開けます。プロジェクトのファイル構成や中身をAIへ渡すための文章として組み立て、クリップボードへコピーしたりファイルへ保存したりできます。「ツリーのみ」「選択ファイルの中身も含める」「前回からの差分のみ」といった集め方を選べ、除外パターン（`*.log`、`node_modules/` など）も登録できます。組み立てた内容の推定トークン数もその場で確認できます。

### 5.4 適用後フック

設定画面の「適用後フック」タブで、プロジェクトごとに「適用が成功したら実行するコマンド」を登録できます（例: フォーマッタやテストの自動実行）。プロジェクトのルートフォルダを作業ディレクトリとして実行され、失敗（0以外の終了コードやタイムアウト）したときの扱いも選べます。

### 5.5 Git連携

プロジェクトがGit管理下にある場合、エディタの行番号ガターに追加・変更・削除を色で表示します（Gitガター）。設定で「適用後に自動コミットする」をオンにすると、「適用」が成功するたびにそのプロジェクトのGitへ自動でコミットされます（既定はオフ）。

### 5.6 コマンドパレット（Ctrl+Shift+P）

Graftの主な操作を名前で検索してその場から実行できます。ツールバーのボタンやショートカットの場所を覚えていなくても、操作名の一部を入力するだけで見つけられます。

### 5.7 クイックオープン（Ctrl+P）

ファイル名の一部をあいまい検索して、目的のファイルを素早く開けます。

## 6. 安全機構

Graftは「何が起きても元に戻せる」ことを設計の中心に置いています。

### 6.1 バックアップの仕組み（`back/` フォルダ）

「適用」でファイルへ書き込む**直前に**、必ず変更前の内容がバックアップとして退避されます。バックアップはデータ保存先の `back/<プロジェクトID>/<リビジョン>/` フォルダにリビジョンごとに保存され、履歴ビューからいつでも中身を確認・復元できます。保持するリビジョン数（既定100件）やバックアップ全体の上限サイズ（既定500MB）を超えると、古いものから自動的に整理されます（既定ではごみ箱経由で削除するため、直後であればOSのごみ箱からも拾えます）。

### 6.2 適用前プレビュー・ドライラン

設定「適用前にプレビューを表示する」（既定オン）をオンにしていると、「適用」を押したときに実際に書き込む前の差分を確認する画面が必ず挟まります。また接ぎ木パネルの「プレビューを再実行」は、対象ファイルを編集した後などに、各ブロックが実際に適用できるかどうかをもう一度確かめる試し適用（ドライラン）です。ドライランの段階ではファイルは一切書き換わりません。

### 6.3 削除の取り消し（Ctrl+Z）

エクスプローラからファイルやフォルダを削除した直後であれば、Ctrl+Z（エクスプローラにフォーカスがある状態）で元に戻せます。OSのごみ箱とは別に、Graftが自前で退避コピーを保持する仕組みです。

### 6.4 適用の失敗時の扱い

設定「適用モード」で、AIの回答の一部だけが実際のコードに当てはまらなかったときの挙動を選べます。既定の「部分適用可」は、当てはまった変更だけを書き込み、当てはまらなかった変更は失敗として一覧に残ります（適用そのものは成功として履歴に記録され、「元に戻す」でいつでも取り消せます）。完了メッセージには、当てはまらなかった変更の件数もあわせて表示します。複数のブロックが互いに依存し合っているなど、一部だけの適用では中途半端な状態になってしまう場合は、「全件適用（All or Nothing）」を選ぶと、1件でも当てはまらない変更があれば、その回答に含まれる変更を1つも書き込まずに中止します。この場合は「「全件適用」の設定のため中止しました」という案内が表示されるので、設定のせいだと分かります。

### 6.5 適用を許可する範囲の制限

設定画面「安全機構」タブで、適用を許可するファイルの拡張子（既定は `.py` `.js` `.ts` `.cs` など主要な開発用拡張子と `.md` `.txt` など）、1ファイルあたりの最大サイズ（既定10MB）、1回の適用で書き換えられるファイル数の上限（既定200件）を設定でき、これを超える変更はブロックされます。

これらの仕組みにより、「AIの提案どおりに適用してみたが結果が良くなかった」という場合でも、履歴から確実に元の状態へ戻せます。

## 7. キーボードショートカット一覧

同じ内容は画面右上の「?」ボタン→「キーボードショートカット一覧」（またはCtrl+/）からいつでも確認できます。

### 接ぎ木の操作

| キー | 動作 |
|---|---|
| Ctrl+Shift+V | クリップボードのAIの回答を読み取って解析します。接ぎ木の入口です。 |
| Ctrl+Enter | 解析した変更を実際のファイルへ適用します。 |
| Ctrl+Alt+Z | 直前に適用したリビジョンを元に戻します。 |
| Ctrl+J | 接ぎ木パネル（下部）を開閉します。 |
| Ctrl+Shift+C | AIへの依頼文（プロンプトテンプレート）をコピーします。 |
| Ctrl+Alt+1〜9 | 登録したプロジェクトを番号で切り替えます。 |
| Space | （ブロック一覧にフォーカス中）選択したブロックの適用チェックを切り替えます。 |
| Escape | 解析中のパッチを破棄し、ブロック一覧を空にします。 |

### ファイル・エディタ

| キー | 動作 |
|---|---|
| Ctrl+P | ファイル名であいまい検索して開きます（クイックオープン）。 |
| Ctrl+S | 現在のタブを保存します。 |
| Ctrl+Shift+S | 開いているタブをすべて保存します。 |
| Ctrl+W | 現在のタブを閉じます（未保存なら保存確認あり）。 |
| Ctrl+Shift+T | 直前に閉じたタブを、カーソル位置ごと開き直します（最大10件、新しい順）。 |
| Ctrl+Tab | 直近使用した順にタブを切り替えます。 |
| Ctrl+G | 指定した行番号へ移動します。 |
| Ctrl+/ | （ファイル編集中）現在行のコメントを切り替えます。 |

## 8. 設定

設定画面はコマンドバーの「設定」ボタン（またはCtrl+,）から開きます。タブは「一般」「エディタ」「マッチング」「安全機構」「表示・コンテキスト」「プロンプトテンプレート」「適用後フック」「トークン統計」「JSON編集」「バージョン情報」に分かれています。ほとんどの項目は変更した瞬間に自動で保存され、保存ボタンを押す必要はありません。ここでは、よく変更する項目を中心に紹介します（各項目にマウスを乗せると出るツールチップにも、より詳しい説明があります）。

### 一般タブ

- **テーマ**: 画面全体の配色。既定ライト／既定ダークに加え、セピア・GitHub風・Solarized Light／Dark・Nord・Dracula・Nightの計9種のプリセットと「システム追従」から選べます。既定はシステム追従（既定ライト／既定ダークのどちらかへ自動的に切り替わります。9つのプリセットへは追従しません）。
- **本文フォント／等幅フォント**: 画面の文字（本文フォント）とコード表示（等幅フォント）に使うフォントを、OSにインストール済みのフォントから選べます。既定は「(既定)」（アプリの既定フォント）。選ぶと即座にプレビューへ反映されます。
- **操作の説明**: ツールチップの詳しさ（表示しない／最低限／標準の説明／くわしい説明）。既定は標準の説明。「最低限」は今その項目に入っている値だけを一言で示します。
- **適用モード**: 部分適用可（既定）／全件適用。「6.4 適用の失敗時の扱い」参照。
- **適用前にプレビューを表示する**: 既定オン。
- **グローバルホットキー**: バックグラウンドから貼り付けて解析するキー。既定はCtrl+Alt+V。
- **ログレベル**: ログファイルへ書き出す情報の詳しさ。普段は既定の「info」のままで問題ありません。
- **閉じたときの動作**: 「終了する」か「タスクトレイに常駐する」か。
- **データ保存先**: 「ポータブル」と「ユーザーフォルダ」の切り替え。「10. データの保存場所」参照。
- **履歴の保持数／バックアップ上限**: 既定100件・500MB。超えると古いものから自動整理されます。
- **適用後に自動コミットする**: 既定オフ。

### エディタタブ

文字の大きさ（既定13）、行の折り返し、行番号、現在行のハイライト、Gitガター表示、タブ幅（既定4）、インデントの自動検出（既定オン）、括弧の自動閉じ、コード折りたたみ、単語補完などを調整できます。多くの項目は既定のままで快適に使える設定になっています（コード表示のフォントの種類は「一般」タブの「等幅フォント」で選びます）。

### マッチング・安全機構タブ

AIのコードが完全一致しない場合にどこまで「似ている」とみなすかの厳しさ（類似度、既定0.85）や、適用を許可する拡張子・ファイルサイズの上限（既定10MB）・1回の適用で書き換えられるファイル数の上限（既定200件）を調整できます。通常は既定値のままで構いません。

### 表示・コンテキストタブ

差分表示の並列／統合、空白の可視化、`.gitignore` を尊重するか（既定オン）、コンテキスト収集のトークン概算比率・警告閾値、クリップボード監視のオン/オフと反応方法を設定します。

### プロンプトテンプレートタブ

「初回用（完全版）」などの既定テンプレートに加え、自分用のテンプレートを追加・編集できます（「3.3 AIに出力させるためのプロンプト例」参照）。

### 適用後フックタブ

プロジェクトごとの適用後フックを登録します（「5.4 適用後フック」参照）。

### バージョン情報タブ

Graftのバージョン、更新の確認（起動時に確認するかどうか・チェック先URL・「今すぐ更新を確認」ボタン）、ログフォルダを開く・最新のログを表示するボタン、使用しているオープンソースライブラリのライセンス表記があります（ログについては「9. 困ったときは」、更新については次の「更新」を参照してください）。

### 更新

Graftは、GitHubで公開しているリリース（`github.com/Yu5rin/Graft`）に新しいバージョンが出ていないか確認し、同意すればダウンロードして自動的に入れ替える機能を持っています。

- **確認するタイミング**: 起動するたびに（ただし前回の確認から24時間以上経っている場合のみ）、または設定「バージョン情報」タブの「今すぐ更新を確認」を押したときです。それ以外のタイミングでは通信しません。
- **見つかったら**: 「新しいバージョン vX.Y.Z が利用可能です」というダイアログが出ます。「今すぐ更新」を押した場合だけダウンロードが始まり、押さなければ何も起きません（無断でダウンロードされることはありません）。
- **ダウンロードと確認**: ダウンロード中は進捗が表示され、「中断」でいつでも取りやめられます。ダウンロードしたファイルは壊れていないか・改ざんされていないかを検証してから使います。検証に失敗した場合は、更新を中止し利用中のバージョンのまま動作を続けます。
- **反映には再起動が必要**: 準備ができると「再起動して更新を完了しますか？」と聞かれます。未保存の変更があれば先に保存を確認するダイアログが出ます。「今すぐ再起動」を押すと、Graftが自動的に再起動して新しいバージョンで立ち上がります。
- **自動でできない場合**: Graftを `Program Files` など書き込みが制限された場所に置いている場合、自動更新はできません。その場合はリリースページを開く案内が出るので、そちらから手動でダウンロードして入れ替えてください。
- **設定を変える**: 設定「バージョン情報」タブの「起動時に更新を確認する」をオフにすると、起動時の自動確認をやめられます（オフでも「今すぐ更新を確認」はいつでも使えます）。「チェック先URL」で確認先を変更・確認できます（既定はGraft本体のリポジトリです）。
- **通信について**: Graftが外部と通信するのは、この「更新の確認・ダウンロード」のときだけです。使用状況の送信やテーマのダウンロードなど、それ以外の通信は行いません。

## 9. 困ったときは

### 適用が失敗する

- 接ぎ木パネルの各ブロックには、適用できるかどうかの状態が表示されます。失敗しているブロックを選ぶと理由を確認できます。
- ファイルの内容がAIの回答を作った時点から変わっている（自分で編集した、他のツールが変更したなど）と、変更前のコードが見つからず失敗することがあります。「プレビューを再実行」でもう一度試すか、失敗したブロックの「修正依頼」（現在のファイルの内容を添えた依頼文をコピーする機能）でAIに直してもらってください。
- 対象ファイルの拡張子・サイズが「安全機構」タブの制限を超えていないか確認してください。

### ウィンドウが前面に出てこない

グローバルホットキーやクリップボード監視の検知で前面に呼び出す際、OS（特にWindows）がアプリの勝手なフォーカス奪取を制限していることがあります。この場合、ウィンドウは実際には最前面になっていても、タスクバーのアイコンが点滅するだけのことがあります。タスクバーのアイコンをクリックすれば表示に切り替わります。

### クリップボード監視が反応しない

設定「表示・コンテキスト」タブで「クリップボード監視を有効にする」がオンになっているか確認してください。環境によっては監視機能自体が使えないことがあり、その場合はチェックボックス自体が無効化されています。監視がオンでも、内容がパッチ形式・unified diff形式のいずれとしても認識できない文章はスキップされます。

### ログの場所と見方

設定画面「バージョン情報」タブの「ログフォルダを開く」でログファイルが入ったフォルダを、「最新のログを表示」で直近のログの内容をその場で確認できます（全文コピーも可能）。ログはデータ保存先の `logs/` フォルダに1日1ファイル（`logs/yyyyMMdd.log`）で保存され、1行が1件の記録（JSON）になっています。ファイルの中身そのものは記録されません。

### 不具合の報告方法

操作中にエラーダイアログが表示された場合、多くは「詳細をコピー」ボタンが付いています。押すとエラーコード・エラーの内容・対処方法をまとめた文章がクリップボードへコピーされるので、これを不具合報告に貼り付けてください。

## 10. データの保存場所

Graftが扱うデータは、既定では**実行ファイルと同じフォルダ**（ポータブル）に保存されます。

| ファイル・フォルダ | 内容 |
|---|---|
| `settings.json` | 設定画面で変更した内容一式。 |
| `projects.json` | 登録したプロジェクトの一覧・プロジェクトごとの状態（適用後フックなど）。 |
| `back/` | リビジョンごとのバックアップ本体（`back/<プロジェクトID>/<リビジョン>/`）。ファイル削除の取り消し用の一時退避（`back/trash/`）もここに置かれます。 |
| `logs/` | 1日1ファイルのログ（`logs/yyyyMMdd.log`）。 |
| `templates.json` | 自分で追加したプロンプトテンプレート。 |
| `queue.json` | 保留中のパッチキューの内容。 |
| `update-check.json` | 更新を最後に確認した日時（「8. 設定」の「更新」参照）。設定の内容そのものではないため`settings.json`とは別ファイルです。 |

Program Filesなど、書き込み権限の無い場所にGraftを置いた場合は、設定画面「一般」タブの「データ保存先」から**ユーザーフォルダ**（Windowsなら `%APPDATA%\Graft` 相当の場所）へ切り替えられます。切り替えを押すと、現在のデータ一式を新しい場所へコピーしたうえで切り替え用の設定を書き換えます。元の場所のデータはコピー後も削除されずそのまま残るため、万一のときも元の状態に戻せます。切り替えの反映にはGraftの再起動が必要です。ポータブルへ戻す操作も同じ場所から行えます。
