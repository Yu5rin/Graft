## 1. Graftとは何か

Graftは、**AI（ChatGPT・Claudeなど）が提案したコードの変更を、手元のプロジェクトへ安全に適用するためのデスクトップアプリ**です。

AIにコードの修正を頼むと、多くの場合「このファイルのこの部分をこう直してください」という形で回答が返ってきます。その回答を自分の目でファイルへ手作業で反映するのは、範囲が広くなるほど手間がかかり、写し間違いも起きがちです。Graftは、AIに決まった書式（後述の「パッチの形式」）で回答してもらい、その回答を読み取って実際のファイルへ機械的に適用します。

Graftが担っているのは、次のような一連の往復です。

1. Graftから「この形式で答えてください」という依頼文をコピーし、AIとの会話の最初に貼り付ける
2. AIに直してほしい内容を伝え、AIの回答をコピーする
3. Graftへ貼り付けて解析する
4. 実際にどう変わるか（差分）を画面で確認する
5. 問題なければ適用する。ファイルへ書き込まれる直前に必ずバックアップが作られるので、結果が気に入らなければいつでも取り消せる

Graftはこの往復を素早く・安全に繰り返すための道具です。汎用のコードエディタやAIチャットの機能そのものを置き換えるものではなく、あくまで「AIの出力とファイルの橋渡し」に専念しています。

## 2. 最初の5分

初めて起動すると「Graftへようこそ」という初回起動ガイドが開きます。4つの画面（導入・プロジェクト登録・依頼文のコピー・準備完了）を順に進めるだけで、ひととおりの流れを体験できます（画面下に「1 / 4」〜「4 / 4」と表示されます）。ガイドは「スキップ」でいつでも終了でき、あとから同じ操作を通常の画面からやり直すこともできます。

### 2.1 自分のプロジェクトを使わずに試したいとき（使い方を学ぶ）

初回起動ガイドの最後の画面「準備ができました」には、「使い方を学ぶ」というボタンがあります。これを押すと、自分のフォルダには一切触れずに、Graftが用意した練習用のサンプル（サンプルのPythonファイル1件と、それを直すためのサンプルパッチ）が一時フォルダへ生成され、解析→差分確認→適用→履歴確認→取り消しまでの一連の流れを、実際のGraftの画面上でコントロールを指しながら体験できるチュートリアルが始まります。いつでもEscキーか吹き出しの「終了」ボタンで中断でき、あなたのプロジェクトが変更されることはありません。あとから画面右上の「？」メニュー→「使い方を学ぶ」でも同じチュートリアルを再実行できます。

### 2.2 自分のプロジェクトで使う場合の最短の流れ

1. **起動する**
   Graftを起動すると、前回開いていたプロジェクトとウィンドウの配置がそのまま復元されます。
2. **プロジェクトを登録する**
   まだ一度も登録していないフォルダを使う場合は、サイドバーの「プロジェクト」ビュー上部の「プロジェクトを追加」ボタン（＋）から、これから変更を加えたいプロジェクトのルートフォルダ（普段コードエディタで開いているフォルダ）を選んで登録します。フォルダの中身自体はこの時点では変更されません。
3. **AI向けの依頼文をコピーする**
   コマンドバー「AIに渡す」の「依頼文をコピー」を押すと、既定の依頼文がその場でコピーされます（Ctrl+Shift+Cでも同じです）。別のテンプレートを使いたいときは、右の▼を押して一覧から選び、「コピー」を押します。どちらも、AIに「Graftが読み取れる決まった形式で回答してください」と伝えるための依頼文がクリップボードへコピーされます。これをAIとの会話の最初に貼り付けてから、直してほしい内容を伝えます。
4. **AIの回答をコピーして貼り付ける**
   AIの回答（パッチ本文）をコピーし、Graftのコマンドバー「AIから受け取る」の「貼り付けて解析」（またはCtrl+Shift+V）を押します。保存したファイルから読み込むときは、右の▼から「ファイルから解析…」を選びます。クリップボードの内容が読み取られ、接ぎ木パネルにブロック（1件ずつの変更）の一覧として表示されます。
5. **差分を確認する**
   一覧の各行を選ぶと、その変更が実際にどう反映されるかの差分（変更前後の比較）を確認できます。適用したくない変更があれば、チェックを外して対象から外せます。
6. **適用する**
   問題なければ接ぎ木パネルの見出しにある「適用」ボタン（またはCtrl+Enter）を押します。ボタンの「(N件)」は、いま書き込まれる件数です。書き込む前に自動でバックアップが作られ、設定によっては書き込み直前の「適用前の確認」画面も挟まります。適用が終わると、変更したファイルはエディタで最新の内容に更新され、履歴にも記録されます。

慣れてきたら、最初の登録以降は3〜6の繰り返しだけで、AIとの往復を回せるようになります。

## 3. パッチの形式

Graftは、AIの回答から3種類の形式を読み取れます。**どの形式かを自分で指定する必要はなく、貼り付けた内容から自動的に判別されます。**

### 3.1 標準SEARCH/REPLACE形式（既定・おすすめ）

多くのAIコーディングツール（Aider、Cline、Roo Code など）で使われている、いちばん一般的な形式です。目印がGitの衝突マーカーそのものなので、AIが自然に出力しやすく、形式の指示に従ってもらいやすいのが利点です。**Graftの既定の依頼文テンプレートはこの形式になっています。**

書き方は「**対象ファイルのパスだけを書いた行**」→「ブロック」の順です。

**既存ファイルの一部を直す場合**:

```
src/app.py
<<<<<<< SEARCH
def greet(name):
    pass
=======
def greet(name):
    return f"Hello, {name}!"
>>>>>>> REPLACE
```

**新規ファイルを作る場合**: 次の2通りのどちらでも受け付けます。上は一般的なツールでの本来の書き方（`SEARCH` の中身を空にする）、下は指定の形で書きたい場合の書き方です。

```
src/new_module.py
<<<<<<< SEARCH
=======
（ファイルの全内容）
>>>>>>> REPLACE
```

```
src/new_module.py
<<<<<<< NEW_FILE
（ファイルの全内容）
>>>>>>> END_FILE
```

**既存ファイルを全面的に書き換える場合**は `WHOLE_FILE`、**ファイルを削除する場合**は `DELETE_FILE` を使います。どちらも終わりの目印は `>>>>>>> END_FILE` です。

```
README.md
<<<<<<< WHOLE_FILE
（ファイルの全内容）
>>>>>>> END_FILE
```

```
src/old.py
<<<<<<< DELETE_FILE
>>>>>>> END_FILE
```

パスは必ずプロジェクトからの相対パスで書きます。`../` で上の階層へ出るパスや絶対パス（`/etc/...`・`C:/...`）は、安全のためGraftが受け付けずエラーになります。

なお、AIが「直す場所を正確に指定できない」と判断したときは、`NEED_MORE_CONTEXT: src/Example.cs` のように、見たいファイルのパスを添えた行だけを返すことがあります（必要なファイルごとに1行。パスの無い `NEED_MORE_CONTEXT` だけの場合もあります）。この場合Graftは「AIが「情報が足りない」と答えました」という専用のメッセージ（E710）を出し、AIが求めたファイルの一覧も表示します。メッセージの下の「要求されたファイルを収集に追加」を押すと、「ファイルを選ぶ」画面（5.3）が開き、求められたファイルが「内容も出す」に設定された状態になります。そのまま「コピー」してAIへ渡し、あらためて依頼してください（プロジェクト内に見つからないファイルや、除外されていて選べないファイルは、画面のステータス表示に理由つきで出ます）。

ファイルの移動・改名、フォルダの作成、末尾や先頭への追記は、この形式では表せません。これらが必要なときは次の「3.2 Graft独自形式」を使ってください。**1回の回答の中で2つの形式を混ぜることはできません**（混ざっている場合はGraft独自形式として読み取られ、解析に失敗します）。

### 3.2 Graft独自形式

Graft独自の形式です。パッチ全体は要約（`<<<< PATCH` 〜 `>>>>`）から始まり、続けてファイルごとの変更ブロックが並びます。3.1の形式では表せない操作（ファイルの移動・改名、フォルダの作成、末尾や先頭への追記）ができるほか、変更全体の要約（`summary`）を付けられるため、履歴の見出しが分かりやすくなるという利点があります。この形式で出力させたいときは、依頼文テンプレートの「初回用（Graft独自形式）」を使ってください。

**既存ファイルの一部を直す場合（SEARCH/REPLACE形式）**: 変更前のコード（`SEARCH`）と変更後のコード（`REPLACE`）を対で示します。AIはファイル全文を出力する必要がなく、変更箇所だけを書けばよいので、長いファイルでも効率よく扱えます。

```
<<<< PATCH
summary: greet関数であいさつ文を組み立てて返すようにする
type: fix
>>>>

<<<< FILE: src/app.py
<<<<<<< SEARCH
def greet(name):
    pass
=======
def greet(name):
    return f"Hello, {name}!"
>>>>>>> REPLACE
```

**新規ファイルを作る場合（FULL形式）**: `MODE=FULL` を指定し、ファイルの全文をそのまま書きます。

```
<<<< FILE: src/new_module.py MODE=FULL
（ファイルの全文）
>>>> END
```

このほか、ファイルの削除（`<<<< DELETE:`）・改名（`<<<< RENAME: 旧パス -> 新パス`）・フォルダの作成（`<<<< MKDIR:`）・末尾/先頭への追記（`<<<< APPEND:` / `<<<< PREPEND:`）にも対応しています。

### 3.3 unified diff形式

`git diff` や多くのAIが標準で出力する `--- a/ファイル` / `+++ b/ファイル` / `@@ ... @@` から始まる一般的な差分形式（unified diff）も、そのまま貼り付けて解析できます。形式の指示をしていないAIの回答でも、diff形式で出力してくれれば取り込めます。

### 3.4 AIに出力させるための依頼文の例

コマンドバーの「依頼文をコピー」（右の▼で選べる依頼文テンプレート）のうち、最初にAIへ貼り付ける「初回用（完全版）」の内容は次のとおりです。これをAIとの会話の最初に貼り付けてから、直してほしい内容を伝えてください。

```
コードの修正を提案する際は、必ず次の SEARCH/REPLACE ブロック形式で出力してください。

【1】既存ファイルの部分修正
相対パス
<<<<<<< SEARCH
（現在のファイルに存在する完全一致テキスト）
=======
（置換後テキスト）
>>>>>>> REPLACE

【2】新規ファイルの作成
相対パス
<<<<<<< NEW_FILE
（ファイルの全内容）
>>>>>>> END_FILE

【3】既存ファイルの全面書き換え
相対パス
<<<<<<< WHOLE_FILE
（ファイルの全内容）
>>>>>>> END_FILE

【4】ファイルの削除
相対パス
<<<<<<< DELETE_FILE
>>>>>>> END_FILE

ブロックの直前の行には、対象ファイルのパスだけを単独で書いてください（引用符・太字・行番号・見出し記号は付けない）。
パスは必ずプロジェクトからの相対パスにし、親階層へ出る記法は使わないでください（安全のためGraft側で拒否します）。
【2】は、SEARCH 部を空にした【1】の書き方でも構いません（どちらでも新規作成として扱われます）。

【必ず守ること】
- SEARCH 部は現在のファイルの内容と1文字も違わないこと（インデント・空行・コメントを含めて完全一致させる）。
- SEARCH 部はファイル内で一意に定まるまで広く取ること。同じ並びが他にもある場合は、前後の行まで含めて一意にしてください。
- 省略記号（3点リーダや ... など）やプレースホルダを書かないこと。書くと一致しなくなります。
- 依頼と無関係な整形（インデント・並べ替え・改行位置の変更）はしないこと。
- SEARCH 部を正確に作れない場合は、推測でブロックを書かず、「NEED_MORE_CONTEXT: <ファイルパス>」の行だけを出力してください（現在のコードの提示が必要なファイルごとに1行）。
- 説明文はブロックの外に書いてください。

【必要なときだけ使う追加記法】ファイルの移動・改名（RENAME）、フォルダ作成（MKDIR）、末尾への追記（APPEND）、先頭への挿入（PREPEND）は上の4種では表せません。これらが必要なときだけ、Graft独自形式（テンプレート「初回用（Graft独自形式）」を参照）へ切り替えてください。ただし1回の出力で2つの形式を混ぜないでください。混ぜるとGraft独自形式として解釈され、標準形式で書いたブロックが取り込まれません。
また、SEARCH 部をどれだけ広げても一意にできない場合に限り、SEARCH マーカーの行末へ OCCURRENCE=2 や OCCURRENCE=ALL と書いて何番目を対象にするか指定できます。

出力全体（最初のパス指定行から最後の >>>>>>> REPLACE ・ >>>>>>> END_FILE まで。説明文は含めない）を、1つのコードブロックとして囲んで出力してください（1行目に ```text、最終行に ``` と書きます。チャットのコピー機能で一括コピーできるようにするためです）。本文に ``` が含まれる場合（Markdownファイルの編集など）は、外側をバッククォート4個にし、1行目を ````text、最終行を ```` としてください。
```

同じ会話を続けて2回目以降にAIへ回答させるときは、直近1時間以内であれば「継続用（短縮版）」（「先ほどと同じ SEARCH/REPLACE ブロック形式で出力してください。対象ファイルの相対パスはブロックの直前の行に単独で書き、SEARCH 部は現在のファイルと完全一致させてください。出力全体を1行目```text・最終行```で囲んでください（本文に```を含む場合は````）。」）が自動的に選ばれ、依頼文を短く済ませられます。このほか、AIに一部の変更だけをやり直させる「修正依頼」、新規ファイルの作成を頼む「新規実装」、コードを直接出力させず原因の説明から始めさせる「調査依頼」のテンプレートも用意されています。

**従来のGraft独自形式で出力させたい場合**は、「初回用（Graft独自形式）」「継続用（Graft独自形式）」「修正依頼（Graft独自形式）」「新規実装（Graft独自形式）」を選んでください。内容は従来と同じままです。プロンプトの内容自体は、設定画面の「依頼文テンプレート」タブから自由に書き換えられます。

## 4. 画面の説明

Graftの画面は、左からサイドバー・サイドビュー・エディタ（中央）・接ぎ木パネルの順に並びます。

### 4.1 サイドバー（画面左端の細い帯）

4つのアイコンで、下のサイドビューに表示する内容を切り替えます。同じアイコンをもう一度押すとサイドビューを折りたたんで隠せます。

- **プロジェクト**: 登録済みのプロジェクトの一覧。項目を右クリックすると、ピン留め、パスのコピー（数秒で消える通知が出ます）、フォルダをエクスプローラー（Linuxではファイルマネージャー）で表示、タグの編集、表示名の変更、場所の変更、削除ができます。フォルダが見つからないプロジェクトでは、フォルダの表示だけ使えません。
- **エクスプローラ**: 選択中プロジェクトのファイル・フォルダ構成。ファイルを開く、新規作成、名前の変更、削除などの操作をここで行います。
- **履歴**: これまでに適用・取り消した変更の一覧。
- **検索**: プロジェクト全体を横断したファイル内検索。

### 4.2 エディタ（画面中央）

タブ形式のコードエディタです。ファイルを開くとタブとして並び、複数のファイルを同時に編集できます。差分の確認も、専用のタブとしてこの領域に開きます。

### 4.3 接ぎ木パネル（既定では画面下部、右配置にも切り替え可能）

パッチを解析すると自動的に開きます。解析された変更が1ブロックずつ一覧になっており、各行にはファイルパスと変更内容のひとこと説明、適用できるかどうかの状態アイコン、適用対象に含めるかどうかのチェックボックスが並びます。見出しには、左から「修正を依頼」「破棄」「キューへ追加」「再チェック」「適用 (N件)」の操作ボタンが並びます。「修正を依頼」は失敗したブロックがあるときだけ使えます。「破棄」は解析結果を捨てます（押し間違えても、数秒のあいだ画面下に出る「元に戻す」で解析結果を戻せます）。「キューへ追加」は解析した変更をすぐ適用せず、順番待ち（キュー）へ溜めます。「再チェック」は、解析した変更が今のファイルに適用できるかを、書き込まずにもう一度調べます。「適用」は主のボタンで、チェックの付いた変更を書き込みます。パネルのヘッダーから、パネルを画面下と画面右のどちらに配置するかも切り替えられます。

### 4.4 ステータスバー（画面最下部）

現在のカーソル位置（行:列）、選択文字数、文字コード、改行コード、言語、クリップボード監視の状態、直前の適用・削除の取り消し案内などを表示します。

## 5. 主な機能

### 5.1 クリップボード監視

設定でオンにすると、AIの回答らしき内容がクリップボードにコピーされたことを自動的に検知します。検知したときの挙動（自動で解析する、Graftを前面に表示する、通知だけにする、など）は設定画面の「表示・コンテキスト」タブで細かく調整できます。ステータスバーのアイコンから、一時的に監視を止める（一時停止）こともできます。

### 5.2 履歴と復元

「適用」するたびに1件の履歴として記録され、サイドバーの「履歴」ビューから一覧で確認できます。

- **この適用を取り消す**: 選んだ1件だけを取り消し、適用する直前の状態に戻します。
- **ここまで戻す（選択した履歴までまとめて戻す）**: 選んだ履歴より新しい変更をすべて取り消し、その時点までまとめて戻します。実行の前に確認が出ます。戻し終わると、画面下に「r5 まで戻しました（3件を取り消しました）」のような通知が数秒だけ出ます。通知の「元に戻す」を押すと、この操作を取り消して戻す前の状態に戻せます（この操作自体も新しい履歴として記録されるので、あとから履歴の「この適用を取り消す」でも同じことができます）。一部のファイルで注意が必要だった場合や失敗した場合は、通知ではなくダイアログで内容をお知らせします。
- **ファイル単位の履歴**: エクスプローラでファイルを右クリックし「このファイルの変更履歴」を選ぶと、履歴ビューがそのファイルに関わる履歴だけに絞り込まれます。

履歴の一覧は、summary（変更のひとこと要約）による絞り込み検索、種別、期間（今日・今週などのプリセットも含む）でも絞り込めます。

### 5.3 AIに渡すファイルを選ぶ（コンテキスト収集）

コマンドバー「AIに渡す」の「ファイルを選ぶ」ボタン（またはコマンドパレットの「AIに渡すファイルを選ぶ」）から開けます。プロジェクトのファイル構成や中身をAIへ渡すための文章として組み立て、クリップボードへコピーしたりファイルへ保存したりできます。集め方は「ツリーのみ」（構成だけ）・「選択ファイル」（選んだファイルの中身だけ）・「ツリー＋選択」（構成全体＋選んだファイルの中身、既定）・「差分のみ」（前回からの変更点だけ）の4つから選べ、除外パターン（`*.log`、`node_modules/` など）も登録できます。組み立てた内容の推定トークン数もその場で確認できます。

AIが「このファイルも見せて」と返してきたとき（3.1のE710）は、接ぎ木パネルのエラー表示にある「要求されたファイルを収集に追加」から、この画面を開いたうえで、求められたファイルを「内容も出す」にした状態にできます。それ以外のファイルの選択は変わりません。

**ファイル名で絞り込む**: ファイル一覧の上の「ファイル名で絞り込み」欄に文字を入れると、パス（フォルダ名を含む）にその文字を含むファイルだけが、パスつきで一覧に並び、一致した件数が出ます。大文字小文字は区別せず、`/` と `\` は同じに扱います。空白で区切って複数の語を入れると、すべてを含むファイルだけに絞ります（例: `api user`）。絞り込み中はフォルダの行と「すべて」の行を出しません（フォルダの行を押すと、見えていないファイルまで切り替わってしまうため）。各ファイルの「内容も出す／構成だけ／出さない」の切り替えは絞り込み中も同じように使え、欄を空にすると、切り替えた結果がそのままツリーに反映されて戻ります。この欄は一覧の表示を絞るだけで、AIへ渡す内容から外す設定ではありません（外すときは右の「追加の除外パターン」を使います）。Ctrl+Fでこの欄へ移れ、欄に文字があるときのEscで欄を空にできます（欄が空のときのEscは、これまでどおり画面を閉じます）。

**gitの変更ファイルだけを選ぶ**: 一覧の上の「gitの変更ファイルだけ」を押すと、gitで未コミットの変更があるファイル（変更・追加・新規作成・名前を変えたもの）だけを「内容も出す」にし、それ以外のファイルはすべて「構成だけ」にします。作業中のファイルだけ中身をAIへ渡し、全体の形も伝えたいときに使います。削除したファイルは対象外です。今の選択をまとめて書き換えるため、押すと先に確認が出ます。変更が0件のとき、または変更したファイルがすべて除外されていて選べないときは、選択を変えずにその旨を表示します。変更したのに除外されていて選べなかったファイルは、パスと理由が下のメッセージに出ます。収集モードが「ツリーのみ」「差分のみ」のときは、中身が出力に載らないため「ツリー＋選択」に切り替わります。プロジェクトがgitのリポジトリの中にないとき、またはgitが見つからないときはボタンが押せず、ボタンにマウスを載せると理由が表示されます。

**依頼文とファイルを1回のコピーで渡す**: 既定の「初回用（完全版）」など、本文に `{{files}}` を含まないテンプレートは、依頼文だけがコピーされます。コマンドバー「依頼文をコピー」の右の▼で開く一覧にある「選んだファイルも付ける」をオンにすると、依頼文の後ろに、この画面で「内容も出す」にしたファイルが続けてコピーされ、1回の貼り付けでAIへ渡せます（Ctrl+Shift+Cのコピーも同じです）。本文に `{{files}}` を含むテンプレート（「修正依頼」など）では、そこへファイルが入るため二重には付きません。既定はオフで、切り替えは保存されて次回も効きます（設定の「表示・コンテキスト」タブにも同じ項目があります）。テンプレートの本文自体は書き換わりません。収集モードが「差分のみ」のときは、選んだ履歴以降に変更されたファイルが付きます。

**依頼の観点を選ぶ**: 「依頼文をコピー」の右の▼で開く一覧と、この画面の右側に、「依頼の観点」のボタンが並びます（「きれいに」「正しく」「品質」「デザイン」の4つの見出しに、読みやすく・不具合を直す・速く・見た目を整える、などの14個。Excel VBA のプロジェクトでは「VBA」の見出しに3個が加わります）。選んだものは、依頼文に「# 依頼の観点」として、AIへの指示が入ります。「このコードを何のために直してほしいか」を、毎回自分で文章に書かなくて済みます。

- 複数選べます。**既定では何も選びません**。何も選ばなければ、依頼文は今までと同じです。
- 優先順位は、画面の並びの上のものほど高くなります（選んだ順ではありません）。観点を選ぶと、動作を変えないことと正しさを見た目より優先する、渡したファイルの中だけを変える、コードの前に変更点を短く書く、という「進め方の決まり」が1回だけ付きます。
- ボタンにマウスを載せると、一言の説明が出ます。AIに渡す指示文そのものは画面に出ません（設定の「依頼の観点」タブで読めます）。見出しの「すべて解除」で選択をまとめて外せます。
- 依頼文コピーのドロップダウンとこの画面は**同じ選択を共有**します。選んだ観点は、プロジェクトごとに覚えられ、開き直すと戻ります。
- 自分の観点は、設定の「依頼の観点」タブで追加できます（組み込みの観点は編集できないので、「複製」して編集します）。指示文の中では `{{files}}` などの変数は使えません。`focus.json` を他のアプリが開いているなどで書けなかったときは、「追加しました」とは出ず、保存できなかったことが表示されます（閉じてから、もう一度試してください）。読めなかった間も、選んでいた自分の観点の選択は消えません。

### 5.4 適用後に実行するコマンド

設定画面の「適用後に実行するコマンド」タブで、プロジェクトごとに「適用が成功したら実行するコマンド」を登録できます（例: フォーマッタやテストの自動実行）。プロジェクトのルートフォルダを作業ディレクトリとして実行され、失敗（0以外の終了コードやタイムアウト）したときの扱いも選べます。

### 5.5 Git連携

プロジェクトがGit管理下にある場合、エディタの行番号ガターに追加・変更・削除を色で表示します（Gitガター）。設定で「適用後に自動コミットする」をオンにすると、「適用」が成功するたびにそのプロジェクトのGitへ自動でコミットされます（既定はオフ）。

### 5.6 コマンドパレット（Ctrl+Shift+P）

Graftの主な操作を名前で検索してその場から実行できます。ツールバーのボタンやショートカットの場所を覚えていなくても、操作名の一部を入力するだけで見つけられます。

### 5.7 クイックオープン（Ctrl+P）

ファイル名の一部をあいまい検索して、目的のファイルを素早く開けます。

### 5.8 Excel の VBA を直接編集する（Windows 版のみ）

Excel で開いているブック（.xlsm / .xlsb / .xlam / .xls）の VBA コードを、AIの回答（SEARCH/REPLACE）で直接書き換えられます。AIに頼む → 貼り付けて解析 → 差分を確認 → 適用、という普段の流れのまま、適用した内容が Excel の VBE（Visual Basic Editor）に反映されます。Windows 版で、Excel がインストールされているときだけ使えます（Linux 版や Excel が無い環境では、関係するボタンやメニューは出ません）。

**仕組み**: Graft は、ブックのコードを「ミラー」というフォルダにモジュールごとのテキストファイルとして書き出します。AIにはこのファイルを見せ、回答はこのファイルへ適用します。適用の前後に、Graft が Excel とミラーの間で内容を同期します。Excel からミラーへ取り込むのが「取込」、ミラーから Excel へ送るのが「反映」です。ミラーの中身は VBE の画面に見えているコードそのもので（`Attribute` 行などのヘッダは含みません）、`Modules/`（標準モジュール）、`Classes/`（クラスモジュール）、`Forms/`（ユーザーフォームのコード部分）、`Documents/`（シートと ThisWorkbook）に分かれています。

#### 使う前の準備（Excel 側の設定）

Excel の既定では、外部のアプリが VBA のコードに触れないようになっています。次の設定を、**Excel で自分で**オンにしてください（Graft からは変更しません）。

1. Excel の「ファイル」→「オプション」→「トラスト センター」→「トラスト センターの設定」を開く
2. 「マクロの設定」を開く
3. 「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」にチェックを入れる

この設定がオフだと、ブックを追加しようとしたときに E802「VBA プロジェクトへのアクセスが許可されていません」と手順が表示されます。また、ブックは**ローカルのフォルダに保存済み**で、Excel で**開いた状態**にしておく必要があります。VBA プロジェクトにパスワードがかかっているブックは使えません（VBE でロックを解除してください）。

#### ブックを追加する

1. 対象のブックを Excel で開く
2. プロジェクト一覧の見出し右側の「Excel ブックから追加」ボタンを押す（コマンドパレットの「Excel ブックからプロジェクトを追加」でも可）
3. 一覧から開いているブックを選ぶ。対象の形式は .xlsm / .xlsb / .xlam / .xls です（マクロ有効テンプレートの .xltm と、旧形式のアドイン .xla は一覧に出ません）。使えないブックは、理由つきで選べなくなっています（マクロを持てない .xlsx、ロック中、アクセス未許可、保護ビュー、OneDrive／SharePoint 上のブックなど）。一覧に出ないブックは、OneDrive の同期フォルダ上など、対応していない場所にある可能性があります
4. ミラーを置く場所を選ぶ（既定は Graft のデータ保存先の `vba-mirrors/`。バージョン管理したいときは任意のフォルダも選べます）。すでにミラーがある場所では「既存のミラーを使う」か「作り直す」を選べます。「作り直す」は、既存のモジュールのファイルだけをごみ箱へ送って作り直します。ミラーのものではないファイル（ドキュメントや別の作業ファイルなど）が混じっている場所では、作り直しは選べません

追加すると、すべてのモジュールがミラーに書き出され、プロジェクトとして登録されます。プロジェクトの「常設コンテキスト」には、VBA プロジェクトであることと守ってほしいルール（削除・名前変更はできない、Shift_JIS で表せない文字は使わない、など）を伝える文が最初から入ります（編集できます）。

#### 日常の使い方

- **AIに渡す**: 「ファイルを選ぶ」や「依頼文をコピー」の前に、Excel 側で変わったモジュールが自動でミラーに取り込まれます（設定の「VBA 連携」タブで切れます）。VBE で直接編集した内容も、古いまま AI に渡りません。
- **適用する**: 解析の前に、対象のモジュールの Excel 側の変更が自動で取り込まれます。適用が成功すると、変わったモジュールが自動で Excel に反映されます。通知に「Excel へ反映済み」と出ます。反映は VBE を開いたままでも効き、ブックの保存は自分で Excel で行います（保存まで自動にしたいときは、右クリックの「反映後にブックを保存する」をオンにします）。
- **取り消す・履歴から戻す**: ミラーを戻すと、戻した内容が Excel にも反映されます（自動反映をオフにしているプロジェクトでは、ミラーだけが戻り、「未反映」の印が付きます）。
- **反映に失敗したとき**: 「ファイルの変更は残す（Excel には未反映）」（既定）、「もう一度反映する」、「この適用を取り消す」から選びます。既定を選ぶと、ファイルの変更は残り、Excel には未反映のままになります。あとで「Excel へ反映」で送れます。

#### ブックの情報を AI に渡す（値の見本の注意）

「ファイルを選ぶ」の画面と「依頼文をコピー」では、AI が「どんなシートや表があるブックか」を知らずに VBA を書いてしまわないよう、**ブックの情報**を依頼文に含められます。ファイル一覧の先頭の「ブックの情報」の行で、出し方を選べます（クリックのたびに巡ります）。

- **内容も出す**（既定）: シート（名前・コード名・使用範囲・非表示かどうか）、テーブルと列名、名前付き範囲、各シートの先頭行（1 行目）の見出し、参照設定。名前付き範囲は、セル範囲を指すものは参照先も出します。**定数や数式を指す名前（例: `="税込"`・`=0.1`）は、値の見本がオフの間は名前だけ**です（式に値そのものが書かれているため）。
- **構成だけ**: シート・テーブル・名前付き範囲だけ（見出しと参照設定は出さない）。
- **出さない**: 何も渡さず、Excel にも問い合わせません。

ミラーにファイルは作りません。依頼文を作るたびに Excel から読み、**メモリにだけ**置きます（ディスクにも、ログにも書きません）。Excel に繋がらないときも、依頼文の作成は止まりません（警告を出し、前回読めた分があれば取得日時つきで使います）。トラストセンターの設定がオフでも、シート・テーブル・名前は読めます（参照設定だけが省かれます）。

**値の見本について（必ずお読みください）**: 行の「値の見本」ボタンをオンにすると、各シートの見出し行に続く数行（既定 5 行）の**セルの値そのもの**が依頼文に入り、AI に渡ります。個人情報や社外秘が含まれていないか確認してください。**各シートの 1 行目（見出し）は、値の見本がオフでも「内容も出す」のときは渡ります**（1 行目がデータのシートがあるときは「構成だけ」にしてください）。**既定はオフ**で、オンにするときは確認が出ます（Enter で押されるのは「やめる」です）。プロジェクトを別の Excel ブックに結び直したときは、値の見本はオフに戻り、改めて確認が出ます。値の見本・数式・出し方を切り替えると、プレビュー欄の内容も消えます（見たいときは押し直してください）。設定の「AI に渡すとき、ブックの情報も取る」をオフにした直後の依頼文には、それまでに取った内容も含まれません。オンの間は、ブックの情報の行と、依頼文コピーの一覧に「値の見本: オン」の注意が常に出ます。数式も渡したいときは「数式も含める」をオンにします（これも既定はオフ。数式は参照先のシート名やセルの構造まで AI に伝えます）。値の見本はこのプロジェクトの設定として覚えられますが、見本の中身そのものはどこにも保存されません。長い内容は、設定の「VBA 連携」タブの上限で切られます。

#### プロジェクト一覧の表示と右クリック

VBA プロジェクトの行には「VBA」バッジが付きます。

- ブックが Excel で開いていないときは、バッジがグレーになり、マウスを載せると「ブックが開いていません」と出ます。
- 名前の下の「未反映 N」は、ミラーでは変わっているのに Excel にはまだ届いていないモジュールの数です。「削除保留 N」は、ミラーのファイルを消したが Excel にはモジュールが残っているものの数です。「衝突 N」は、「保存したらそのモジュールを Excel へ反映する」（下記）をオンにしているときに、Excel 側と両方が変わっていたため送らなかったモジュールの数です（右クリックの「Excel へ反映」で、どちらを残すかを選べます。アプリを閉じると消えます）。
- 設定で VBA 連携をオフにしていると、「VBA 連携オフ」と出ます。

バッジの開閉は、Graft の起動直後・ウィンドウが前面に出たとき・取込や反映の後に調べ直します（定期的な監視はしません）。

右クリックのメニューには、次の項目があります（VBA プロジェクトのときだけ）。

- **Excel から取込**: Excel 側だけが変わったモジュールをミラーに取り込みます。
- **Excel へ反映**: ミラー側だけが変わった（未反映の）モジュールを Excel へ送ります。ファイルを自分で編集した場合もここで送れます（既定では、保存しただけでは自動では送られません。保存のたびに送りたいときは、下の「保存したらそのモジュールを Excel へ反映する」をオンにします）。
- **Excel から復元**: ミラーのファイルを消したために同期を保留しているモジュールを、Excel の内容で作り直します。
- **ブックを前面化**: そのブックの Excel のウィンドウを前面に出します。
- **Excel 側の控えを見る…**: 「Excel へ反映」で上書きされる前の Excel 側の本文の控えを見ます（下記「Excel 側の控え」）。Excel が開いていなくても開けます。
- **適用後に Excel へ自動反映する**（チェック項目）: オフにすると、適用しても Excel には送らず、「未反映」の印だけが付きます。
- **保存したらそのモジュールを Excel へ反映する**（チェック項目。既定はオフ）: 下記「保存したときに自動で反映する」。
- **反映後にブックを保存する**（チェック項目）: オンにすると、Excel へ反映したあとにブックも保存します。読み取り専用で開いているブックは保存できません。

エディタの本文と差分表示を右クリックすると、「VBE でこの行を開く」が出ます（VBA プロジェクトのモジュールのときだけ）。Excel の VBE でそのモジュールのその行を開いて前面に出します。

#### Excel 側と Graft 側の両方が変わったとき（衝突）

Excel（VBE）で直接編集した内容と、Graft のミラーの内容が両方変わっていると、どちらを残すかを選ぶ画面が出ます。モジュールごとに、左（Excel 側）と右（Graft 側）の差分を見て選べます。

- **Graft 側で上書き**: Excel 側の内容を `vba-sync/<プロジェクトID>.rescue/` に控えに残してから、Graft の内容で Excel を置き換えます。
- **Excel 側を採用**: Graft のファイルを Excel の内容で置き換えます（適用の前などに出ます。適用の後や取り消しの後には出ません）。
- **反映しない**: 何もせず、「未反映」の印を付けます（適用や取り消しの後に出ます）。
- **中止**: 何もしません（適用の前に出ます）。

Enter で押される既定のボタンは、Excel を壊さない側（「Excel 側を採用」、適用や取り消しの後は「反映しない」）です。

#### Excel 側の控え（上書きされる前の内容を戻す）

「Excel へ反映」（手動・適用後・取り消し後・保存時のどれも）で Excel 側のモジュールが上書きされる直前に、Graft は**上書きされる前の Excel 側の本文を、毎回、控えとして残します**。VBE で直接編集した内容を、思わぬ上書きで失っても取り戻せるようにするためです。控えは `vba-sync/<プロジェクトID>.rescue/` に、`<モジュール名>-<日時>-auto.txt`（反映前の自動控え）、`…-mirror.txt`（控えを戻す直前のミラーの内容）、`<モジュール名>-<日時>.txt`（衝突で「Graft 側で上書き」を選んだときや、書き戻しに失敗したときの控え）として残ります。同じ内容の自動控えは重ねません。

プロジェクトの右クリック「**Excel 側の控えを見る…**」で、モジュールごとの控えの一覧（日時・種類・行数・サイズ）と、**選んだ控えと現在のミラーの差分**を見られます。

- **ミラーへ戻す**: 選んだ控えの内容を、Graft のファイル（ミラー）へ書きます。**Excel へは直接書きません**。戻したあと、そのモジュールは「未反映」になるので、「今すぐ Excel へ反映」（または右クリックの「Excel へ反映」）で送ります（Excel 側が変わっていれば、衝突の画面が出ます）。戻す直前のミラーの内容は `…-mirror.txt` として残るので、戻したことも取り消せます。エディタで未保存のタブがあるときは、先に保存するかを確認します。
- **履歴には記録されません**。戻した結果は、Graft の履歴（リビジョン）には出ません（履歴は Graft が適用した変更だけを持つため）。ログに残ります。
- **控えを削除**・**保存先を開く**: 不要な控えを消す、控えのフォルダを開く。
- 控えは、1つのモジュールにつき自動控えとミラーの控えを合わせて**新しい20件まで**、控え全体で**50MBまで**残り、古いものから自動で消えます（設定の「VBA 連携」タブで変えられます）。衝突の上書き前・書き戻し失敗の控えは自動では消えません。プロジェクトを一覧から削除しても、控えは残ります。
- 控えを書けなかったとき（ディスクの空き不足など）は、反映は続けて「控えを保存できませんでした」（E816）と警告します。

#### 保存したときに自動で反映する（既定はオフ）

右クリックの「**保存したらそのモジュールを Excel へ反映する**」をオンにすると、Graft のエディタで VBA のモジュールを保存したとき、**そのモジュールだけ**が Excel へ送られます。手で直して Excel で試す往復が速くなります。VBE で同じモジュールを開いたままでも反映されます（既定はオフです。マクロを実行中のブックには、送らないでください）。

- 続けて保存したとき（「すべて保存」を含む）は、最後の保存から約0.5秒待って、まとめて1回送ります。
- 送るのは保存したモジュールだけです。ほかのモジュールには触れません。送る前に、上の「Excel 側の控え」が残ります。
- **衝突のとき（Excel 側も変わっているとき）は送りません**。ダイアログは出さず、プロジェクトの名前の下に「衝突 N」と出ます。右クリックの「Excel へ反映」で、どちらを残すかを選べます。
- マクロの実行中（E813）、Excel が応答しない（E805）、ブックが開いていない（E804）、Shift_JIS で表せない文字がある（E811）ときは、**ステータスバーに知らせるだけ**でダイアログは出しません。ファイルは保存済みで、「未反映」のまま残ります（同じ理由の知らせは、60秒に1回までです）。自動では再試行しません。直したあとにもう一度保存するか、「Excel へ反映」で送ってください。
- 対象は、エディタでの保存（Ctrl+S・すべて保存）だけです。タブを閉じるときの保存、適用の前の保存確認、エクスプローラーでの新規作成・名前変更・削除、ファイルの取り込みは対象外で、「未反映」のまま残ります。適用の最中の保存は送りません（適用後の反映がまとめて扱います）。

#### 制限事項

- **ユーザーフォームのデザイン**（ボタンなどの配置、.frx）は扱いません。コードの部分だけです。新しいフォームは作れません（Excel 側で作ってから、ブックを追加し直してください）。
- **モジュールの削除と名前変更は自動で反映しません。** AIの回答に DELETE や RENAME が含まれていると、E814 として適用を始めません。該当のブロックのチェックを外して適用し、削除や名前変更は VBE で行ってください。新しいモジュールは標準モジュール（`Modules/`）とクラス（`Classes/`）にだけ作れます。シートやフォームのファイルを新しく作ることはできません。
- **新規モジュールを含む適用を取り消すと、そのモジュールは Excel 側に残ります。** ミラーからは消えて「削除保留」になるので、残したくなければ VBE で削除してください。戻したいときは右クリックの「Excel から復元」を使います。
- **ブックのパスの比較**は、大文字小文字を区別せず、`.` や区切りの違いを正規化するだけです。同じブックでも、ネットワークのパス（`\\server\share\…`）とドライブ文字（`Z:\…`）のように別の書き方で開いていると、別のブックとして扱います。
- **OneDrive／SharePoint 上のブックは使えません。** デスクトップやドキュメントを OneDrive に同期している環境では、ブックのパスがウェブのアドレスになります。ローカルのフォルダ（例: `C:\Work`）に保存してから、開き直してください。
- **Shift_JIS で表せない文字は反映できません。** VBE は日本語版 Windows では Shift_JIS（CP932）で動くため、絵文字、emダッシュ（—）、enダッシュ（–）、波ダッシュ（〜）、中黒の丸（•）などを含むモジュールは、解析の段階で E811 として止めます（全角チルダ「～」と丸数字は使えます）。該当のブロックのチェックを外すか、AIに使わない文字で出し直してもらってください。日本語以外の言語の Windows では動作を保証しません。
- VBE が書き込み時にコードを自動で整形する（空白やキーワードの大文字小文字が変わる）ことがあります。その場合も、Graft のミラーは書き換えません（Excel 側の本文が少し異なるだけで、同期は崩れません）。
- **空白と大文字小文字だけの違いは「Excel 側の変更」とは見なさず、取り込みません。** VBE の自動整形と、利用者の編集を区別できないためです。ただし、見なさないのは**文字列（`"…"`）とコメントの外側だけ**です。文字列の中身、コメントの文言、行頭の字下げの変更は、通常の変更として取り込みます。Excel 側のモジュールが、直前の同期から整形だけ違う状態で Graft の変更を反映するときは、念のため、上書きの前に Excel 側の本文を `vba-sync/<プロジェクトID>.rescue/` に控えます。
- 同名のモジュールは、種別が違っても作れません（VBA のモジュール名は種別をまたいで一意です）。たとえば Excel にシートの `ThisWorkbook` があるのに `Classes/ThisWorkbook.cls` を作る回答は、E808 として適用の前に止まります。`Documents/ThisWorkbook.cls` に書いてもらってください。
- 反映の最中（Excel へ書いている間）は、ウィンドウを閉じる操作が反映の終わりまで待たされ、プロジェクトの削除・場所の変更・取込・反映・復元と、設定の変更の反映は、終わるまで保留または無効になります。
- マクロの実行中・中断中は反映できません（E813）。セルを編集中・ダイアログを開いている間は、Excel が応答せず（E805）、少し待っても通らないときは中止します。マクロを終了する、セルを確定する、ダイアログを閉じるなどしてから、もう一度お試しください。
- Excel の「参照設定」の編集や、VBA プロジェクトのパスワードの解除はできません。
- ミラーのフォルダを Git で管理する場合、Excel からの取込（Pull）で書き換わった内容は、Graft の履歴にも自動コミットにも入りません（履歴は Graft が適用した変更だけを持ちます）。そのため、未コミットの差分がたまることがあります。必要に応じて自分でコミットしてください。

設定は、設定画面の「VBA 連携」タブにあります（「8. 設定」参照）。

## 6. 安全機構

Graftは「何が起きても元に戻せる」ことを設計の中心に置いています。

### 6.1 バックアップの仕組み（`back/` フォルダ）

「適用」でファイルへ書き込む**直前に**、必ず変更前の内容がバックアップとして退避されます。バックアップはデータ保存先の `back/<プロジェクトID>/<リビジョン>/` フォルダに履歴ごとに保存され、履歴ビューからいつでも中身を確認・復元できます。保持する履歴数（既定100件）やバックアップ全体の上限サイズ（既定500MB）を超えると、古いものから自動的に整理されます（既定ではごみ箱経由で削除するため、直後であればOSのごみ箱からも拾えます）。

### 6.2 適用前の確認とチェック

設定「適用前に確認画面を表示する」（既定オン）をオンにしていると、「適用」を押したときに実際に書き込む前の差分を確認する画面（適用前の確認）が必ず挟まります。また接ぎ木パネルの「再チェック」ボタンは、対象ファイルを編集した後などに、各ブロックが実際に適用できるかどうかを、書き込まずにもう一度調べます。解析した直後にも同じチェックが自動で行われ、このチェックの段階ではファイルは一切書き換わりません。

### 6.3 削除の取り消し（Ctrl+Z）

エクスプローラからファイルやフォルダを削除した直後であれば、Ctrl+Z（エクスプローラにフォーカスがある状態）で元に戻せます。OSのごみ箱とは別に、Graftが自前で退避コピーを保持する仕組みです。

### 6.4 適用の失敗時の扱い

設定「適用モード」で、AIの回答の一部だけが実際のコードに当てはまらなかったときの挙動を選べます。既定の「部分適用可」は、当てはまった変更だけを書き込み、当てはまらなかった変更は失敗として一覧に残ります（適用そのものは成功として履歴に記録され、「元に戻す」でいつでも取り消せます）。完了メッセージには、当てはまらなかった変更の件数もあわせて表示します。複数のブロックが互いに依存し合っているなど、一部だけの適用では中途半端な状態になってしまう場合は、「全件適用（All or Nothing）」を選ぶと、1件でも当てはまらない変更があれば、その回答に含まれる変更を1つも書き込まずに中止します。この場合は「「全件適用」の設定のため中止しました」という案内が表示されるので、設定のせいだと分かります。

### 6.5 適用を許可する範囲の制限

設定画面「適用の制限」タブで、適用を許可するファイルの拡張子（既定は `.py` `.js` `.ts` `.cs` など主要な開発用拡張子と `.md` `.txt` など）、1ファイルあたりの最大サイズ（既定10MB）、1回の適用で書き換えられるファイル数の上限（既定200件）を設定でき、これを超える変更はブロックされます。

これらの仕組みにより、「AIの提案どおりに適用してみたが結果が良くなかった」という場合でも、履歴から確実に元の状態へ戻せます。

## 8. 設定

設定画面はコマンドバー右端の歯車アイコン（「設定を開く」。マウスを乗せると説明が出ます）またはCtrl+,から開きます。左側に縦に並んだ一覧からタブを選びます。タブは「一般」「適用と履歴」「適用の制限」「差分の表示」「エディタ」「AIに渡す内容」「クリップボード監視」「依頼文のテンプレート」「適用後に実行するコマンド」「統計」「詳細（settings.json）」「更新とバージョン情報」の12枚です。ほとんどの項目は変更した瞬間に自動で保存され、保存ボタンを押す必要はありません（「適用後に実行するコマンド」「依頼文のテンプレート」の編集内容だけは、各タブの「保存」ボタンで確定します）。ここでは、よく変更する項目を中心に紹介します（各項目の下に1行の説明があり、マウスを乗せると出るツールチップにも、より詳しい説明があります）。

右下の「既定に戻す」で、この画面の設定（settings.jsonの内容）をすべて既定値に戻せます。登録したプロジェクトの一覧、適用後に実行するコマンド、依頼文のテンプレート、履歴は消えません。

### 一般タブ

見た目と、起動・常駐、キーの設定です。

- **表示**
  - **テーマ**: 画面全体の配色。既定ライト／既定ダークに加え、セピア・GitHub風・Solarized Light／Dark・Nord・Dracula・Nightの計9種のプリセットと「システム追従」から選べます。既定はシステム追従（既定ライト／既定ダークのどちらかへ自動的に切り替わります。9つのプリセットへは追従しません）。
  - **操作の説明**: ツールチップの詳しさ（表示しない／最低限／標準の説明／くわしい説明）。既定は標準の説明。「最低限」は今その項目に入っている値だけを一言で示します。
  - **画面のフォント／本文フォント／コード用のフォント（等幅）**: メニュー・ボタン・一覧など画面全体の文字（画面のフォント）、取扱説明書やMarkdownプレビューの地の文（本文フォント）、コード表示（等幅フォント）に使うフォントを、それぞれ独立にOSにインストール済みのフォントから選べます。既定は「(既定)」（アプリの既定フォント。本文フォントの既定は画面のフォントと同じフォントのため、これらを一度も設定していない場合の見た目は変わりません）。選ぶと即座に下の「見本」と画面へ反映されます（等幅フォントの見本には、幅の違いが出やすい文字も並びます）。
  - **エディタの文字の大きさ**: コード表示の文字の大きさ（既定13）。エディタ上でCtrl+マウスホイールでも変えられます。
- **起動と常駐**
  - **ウィンドウを閉じたとき**: 「終了する」か「タスクトレイに常駐する」か。
  - **最小化でタスクトレイへ格納する**: 既定オフ。
  - **PC起動時に自動で起動する**: パソコンを起動したときにGraftも自動で起動します。
- **キー**
  - **グローバルホットキー**: バックグラウンドから貼り付けて解析するキー。既定はCtrl+Alt+V。
  - **依頼文コピーのホットキー**: バックグラウンドからAIへの依頼文をコピーするキー。既定はCtrl+Shift+C。空欄にするとOS全体には登録しません。

### 適用と履歴タブ

パッチを適用するときの動きと、履歴・バックアップの残し方です。

- **適用**
  - **適用モード**: 「部分適用可」（既定）／「全件適用（All or Nothing）」。「6.4 適用の失敗時の扱い」参照。
  - **適用前に確認画面を表示する**: 既定オン。オンだと、「適用」を押したときに書き込む前の差分確認画面が開きます。オフにすると差分確認画面は出ず、「N件を適用します。よろしいですか？」という確認のダイアログだけが出て、「はい」で書き込まれます（確認なしに即座に書き込まれることはありません）。
  - **要約（summary）の入力を必須にする**: 既定オン。オンだと、summary（変更のひとこと要約）が無いパッチを適用するとき、要約の入力を求められます。入力せずに閉じると適用は中止されます（要約が書かれているパッチでは何も聞かれません）。オフにすると、要約が無くてもそのまま適用します。
- **履歴とバックアップ**
  - **履歴の最大保持数／バックアップの合計上限（MB）**: 既定100件・500MB（0で無制限）。適用のたびに履歴が1件（r3 のような番号）残り、超えると古いものから自動整理されます。
  - **古い履歴の整理にごみ箱を使う**: 既定オン。整理で消す履歴を、完全に消さずにごみ箱へ送ります。
- **新規ファイル**: パッチで新しく作るファイルの文字コード（既定 utf-8）、改行コード、BOMの有無（既定オフ）を選べます。改行コードの既定は「自動」で、作る場所と同じフォルダ（無ければ親のフォルダをプロジェクトのルートまで順に）にある既存のテキストファイルで多い方の改行（LF または CRLF）に合わせます。手がかりが無いときはOSの既定（Windows は CRLF、それ以外は LF）にします。「CRLF」「LF」を選ぶと、周りのファイルに関わらず常にその改行で作ります。改行が1つも無い既存のファイルに行を追記するときも、同じ決め方です。既存のファイルを編集するときは、そのファイル自身の文字コードと改行がそのまま使われます。
- **Git**: 「適用後に自動コミットする」（既定オフ）。
- **データの保存場所**: 「ポータブル（実行ファイルのフォルダ直下の data フォルダ）」と「ユーザーフォルダ」の切り替え。「10. データの保存場所」参照。

### 適用の制限タブ

意図しない大量の書き換えや、対象外のファイルへの適用を防ぐための条件です（「6.5 適用を許可する範囲の制限」参照）。適用を許可する拡張子、1ファイルの上限サイズ（既定10MB）、1回の適用で書き換えるファイル数の上限（既定200件）を決めます。あわせて、AIのコードが完全一致しない場合にどこまで「似ている」とみなして当てはめるか（一致率のしきい値、既定0.85）と、変更の範囲が広すぎるときの警告（既定300行）も、このタブで調整します。通常は既定値のままで構いません。

### 差分の表示タブ

適用前の確認などに出る差分の見え方です。左右に並べるか上下に統合するか（既定は左右）、長い行の折り返し、空白文字の可視化、行番号、コードの色分け、変更箇所の前後に表示する行数（既定3行）を設定します。

### エディタタブ

中央のコード編集領域の設定です。行の折り返し、行番号、現在行のハイライト、Gitの変更状態の表示、タブ幅（既定4）、インデントの自動検出（既定オン）、括弧の自動閉じ、コードの折りたたみ、単語の簡易補完などを調整できます。多くの項目は既定のままで快適に使える設定になっています（文字の大きさは「一般」タブ、コード表示のフォントの種類は「一般」タブの「コード用のフォント（等幅）」で選びます）。

「行の折り返し」をオンにしていると、画面の幅に収まらない長い行は折り返して表示されます。このとき折り返された続きの行は、元の行のインデント位置（行頭の字下げの分だけ右）から書き出されるため、深く字下げされたコードでも「どこからどこまでが1行なのか」が目で追えます。この字下げに設定項目はなく、常に有効です（アラビア語・ヘブライ語など右横書きの文字を含む行だけは、字下げせずそのまま表示します）。

### AIに渡す内容タブ

「ファイルを選ぶ」画面で集めてAIへ渡す内容の設定です。`.gitignore` を尊重するか（既定オン）、依頼文のコピーに選んだファイルも付けるか（既定オフ）、渡す量の概算に使うトークン数の概算比率（既定2.5。文字数÷この値）と、大きすぎると知らせる量（既定50000トークン）を設定します。トークンは、AIが文章を数える単位です。概算比率は、「依頼文のテンプレート」タブの一覧の数字にも使われます。

### クリップボード監視タブ

クリップボード監視のオン/オフ（既定オフ）と、AIの回答らしき内容を見つけたときの知らせ方、自動で解析するか（既定オン）、Graftのウィンドウを前面に出すか（既定オン）を設定します。「5.1 クリップボード監視」参照。

### 依頼文のテンプレートタブ

「初回用（完全版）」などの既定テンプレートに加え、自分用のテンプレートを追加・編集できます（「3.4 AIに出力させるための依頼文の例」参照）。一覧の右の数字は、そのテンプレートをコピーしたときの文面の概算のトークン数です（上で選んだプロジェクトの内容を差し込んだあとの文面を、「AIに渡す内容」タブの概算比率で数えます。「ファイル」画面で選んだファイルの内容は含みません）。

### 適用後に実行するコマンドタブ

プロジェクトごとに、適用が成功した直後に自動で実行するコマンドを登録します（「5.4 適用後に実行するコマンド」参照）。コマンドの制限時間（既定120秒）も、このタブで設定します。失敗したときの扱いは、「記録のみ」「警告表示」「適用の取り消しを確認する」「自動で適用を取り消す」から選べます。

### VBA 連携タブ

Excel の VBA を直接編集する機能（5.8）の設定です。Windows 版以外では、このタブの中身は表示されず、「この環境では使えない機能です」と出ます。

- **Excel VBA 連携を有効にする**（既定オン）: 機能全体のオン・オフ。オフにすると、Excel には一切接続せず、VBA のボタン・メニュー・自動の取込と反映がすべて止まります。すでに追加してある VBA プロジェクトは、ミラーのフォルダを普通のファイルプロジェクトとして編集・適用できます（プロジェクト一覧には「VBA 連携オフ」と出ます）。
- **AI に渡すファイルを集める前に、Excel の最新を取り込む**（既定オン）: 「ファイルを選ぶ」や「依頼文をコピー」の前に、Excel 側の変更を取り込みます。Excel に接続できないときは、集めること自体は続け、警告を出します。
- **解析の前に、対象モジュールの Excel の最新を自動で取り込む**（既定オン）: オフにすると、取り込むかどうかをその都度確認します。
- **再試行の上限（ミリ秒）**（既定5000、1000〜30000）: Excel がセル編集中などで呼び出しを断ったときに、再試行を続ける時間です。
- **呼び出し全体の時間切れ（ミリ秒）**（既定30000、5000〜120000）: マクロの実行中などで Excel が戻ってこないときに、待つのをやめる時間です。再試行の上限以上にしてください。
- **AI に渡すとき、ブックの情報も取る**（既定オン）: オフにすると、ブックの情報（5.8）のために Excel を呼びません。**値の見本の行数**（既定5、1〜20）・**見出し・見本の最大列数**（既定30、5〜100）・**1 セルの最大文字数**（既定60、10〜500）・**ブックの情報の最大文字数**（既定20000、2000〜100000）で、渡す量を抑えられます。
- **控えの世代数**（既定20、1〜200）・**控え全体の容量**（MB。既定50、5〜1000）: Excel 側の控え（5.8）の残す量です。

プロジェクトごとの「適用後に Excel へ自動反映する」「保存したらそのモジュールを Excel へ反映する」「反映後にブックを保存する」と、ブックの情報の出し方・値の見本は、このタブではなく、プロジェクト一覧の右クリックメニューとファイルを選ぶ画面で切り替えます。

### 依頼の観点タブ

「依頼文をコピー」と「ファイルを選ぶ」に並ぶ「依頼の観点」（5.3）の一覧です。組み込みの観点は、指示文を読めますが編集・削除はできません。「複製」で自分用の観点に写して、名前・見出し・ツールチップ・指示文（Excel VBA のプロジェクトで足す追記と、VBA 専用にするかも）を編集できます。自分用の観点は、組み込みのあとに並びます。指示文の先頭は `## 名前` の見出しにします（無ければ自動で補います）。指示文の中の `{{…}}` は変数としては展開されません。

### 統計タブ

プロジェクトごとに、これまでの適用で使ったおおよそのトークン数を、日別・週別・月別に確認できます。実際にAIへ送って数えた値ではなく、文字数からの概算です。

### 詳細（settings.json）タブ

普段は触らなくて構わない設定です。ログファイルへ書き出す情報の詳しさ（ログレベル。既定は「info」）、設定の書き出し／読み込み（別のPCへ設定を持っていくときに使います。「設定だけを対象にする」をオンにすると、登録したプロジェクトの一覧は含めません）、そして設定ファイル（settings.json）の中身を直接編集する欄があります。直接編集した内容は「検証して保存」で確かめてから反映され、不正な値は既定値に置き換わります。

### 更新とバージョン情報タブ

Graftのバージョン、更新の確認（起動時に確認するかどうか・確認せずに自動で更新するかどうか・チェック先URL・「今すぐ更新を確認」ボタン）、ログフォルダを開く・最新のログを表示するボタン、使用しているオープンソースライブラリのライセンス表記があります（ログについては「9. 困ったときは」、更新については次の「更新」を参照してください）。

### 更新

Graftは、GitHubで公開しているリリース（`github.com/Yu5rin/Graft`）に新しいバージョンが出ていないか確認し、同意すればダウンロードして自動的に入れ替える機能を持っています。

- **確認するタイミング**: Graftを起動するたびに、または設定「更新とバージョン情報」タブの「今すぐ更新を確認」を押したときです。それ以外のタイミングでは通信しません。ただし、テーマ変更・データ保存先の移動・自動更新の適用後など、Graft自身が再起動して立ち上がったときは確認しません（利用者が自分の意思で起動したときだけが対象です）。
- **見つかったら**: 「新しいバージョン vX.Y.Z が利用可能です」というダイアログが出ます。「今すぐ更新」を押した場合だけダウンロードが始まり、押さなければ何も起きません（下の「確認せずに自動で更新する」をオンにした場合を除き、無断でダウンロードされることはありません）。
- **ダウンロードと確認**: ダウンロード中は進捗が表示され、「中断」でいつでも取りやめられます。ダウンロードしたファイルは壊れていないか・改ざんされていないかを検証してから使います。検証に失敗した場合は、更新を中止し利用中のバージョンのまま動作を続けます。
- **反映には再起動が必要**: 準備ができると「再起動して更新を完了しますか？」と聞かれます。未保存の変更があれば先に保存を確認するダイアログが出ます。「今すぐ再起動」を押すと、Graftが自動的に再起動して新しいバージョンで立ち上がります。
- **自動でできない場合**: Graftを `Program Files` など書き込みが制限された場所に置いている場合、自動更新はできません。その場合はリリースページを開く案内が出るので、そちらから手動でダウンロードして入れ替えてください。
- **確認せずに自動で更新する**: 設定「更新とバージョン情報」タブの「確認せずに自動で更新する」をオンにすると、起動時の確認で新しいバージョンが見つかったとき、ダイアログを出さずに裏でダウンロード・検証・入れ替えまで進めます。**既定はオフ**です。「起動時に更新を確認する」がオフのときは確認自体が行われないため、この項目は選べません（選んでいた状態は保たれます）。
- **確認なしの自動更新と再起動**: 再起動は勝手にしません。入れ替えが済むと、画面下のステータスバーに「Graft を x.y.z に更新しました。次回の起動から新しい版になります」と表示されます。「今すぐ再起動」を押すとその場で切り替わります（未保存の変更があれば先に保存を確認するダイアログが出ます）。押さなければ、次にGraftを起動したときから新しいバージョンになります。通知は「×」で閉じられます。
- **確認なしでは進めない場合**: 自動では進めず、これまでどおりダイアログで確認します。配布物の整合性（SHA256）を照合できないとき（配布元への問い合わせが回数の上限に達したときなど）、「チェック先URL」を既定から変更しているとき、Linuxなど自分で入れ替えられない環境のとき、書き込めない場所に置いているときです。照合を省いたまま、確認なしで入れ替えることはありません。
- **確認なしの自動更新が失敗したとき**: いまのバージョンのまま動作を続け、ステータスバーに「自動更新に失敗しました。設定の「今すぐ更新を確認」から手動で更新できます」と控えめに知らせます。理由はログ（`logs/`）に残ります。同じバージョンの失敗は、次の起動以降は通知しません（更新は起動のたびにあらためて試みます）。
- **手動の確認**: 「今すぐ更新を確認」は、この設定に関わらず、見つかったときに必ずダイアログで確認します（自分で押した操作のため）。
- **設定を変える**: 設定「更新とバージョン情報」タブの「起動時に更新を確認する」をオフにすると、起動時の自動確認をやめられます（オフでも「今すぐ更新を確認」はいつでも使えます）。「チェック先URL」で確認先を変更・確認できます（既定はGraft本体のリポジトリです）。
- **通信について**: Graftが外部と通信するのは、この「更新の確認・ダウンロード」のときだけです。使用状況の送信やテーマのダウンロードなど、それ以外の通信は行いません。

## 9. 困ったときは

### 適用が失敗する

- 接ぎ木パネルの各ブロックには、適用できるかどうかの状態が表示されます。失敗しているブロックを選ぶと理由を確認できます。
- ファイルの内容がAIの回答を作った時点から変わっている（自分で編集した、他のツールが変更したなど）と、変更前のコードが見つからず失敗することがあります。「再チェック」でもう一度調べるか、失敗したブロックの「修正を依頼」（AIが出した変更前のコードと現在のファイルの内容を添え、受け取ったのと同じ形式で出し直すよう頼む依頼文をコピーする機能）でAIに直してもらってください。ブロックを右クリックして「修正依頼文をコピー」を選ぶと、そのブロックの分だけをコピーできます。また、失敗したブロックの差分画面では変更前のコード（SEARCH部）を自分で書き換えて再判定でき、1箇所に一致したら「この修正で適用に含める」を押すと、そのままこのブロックを適用できる状態になります（変更後のコードと貼り付けた元のパッチは変わらず、書き換えた事実は履歴に記録されます）。
- 対象ファイルの拡張子・サイズが「適用の制限」タブの制限を超えていないか確認してください。
- 「文字コードを判定できないため、内容を壊さないよう書き込みを止めました」（E218）と出る場合、そのファイルの文字コードが UTF-8・Shift_JIS・UTF-16（BOM付き）のいずれでもありません（EUC-JP や Windows-1252 など）。そのまま書き込むと日本語などが文字化けして元に戻せなくなるため、Graftは適用を止めます。エディタで開くと読み取り専用になり、保存もできません（内容の確認や、コンテキスト収集・検索は使えます）。他のエディタで UTF-8 か Shift_JIS に変換して保存し直してから、もう一度お試しください。
- 「ファイルの文字コードで表せない文字が含まれています」（E219、要確認）と出る場合、Shift_JIS のファイルに、Shift_JIS に無い文字（絵文字・€・✓・é など）を書こうとしています。そのまま適用すると、その文字は「？」などに置き換わります。エディタで保存するときも同じ確認が出ます。置き換わってよければそのまま続け、困る場合はその文字を取り除くか、ファイルを UTF-8 に変換してください。
- 「ほかの変更と置き換える範囲が重なっています（または同じ変更が重複しています）」（E105）と出る場合、同じファイルに対する2つ以上の変更が、同じ行を置き換えようとしています。両方を適用すると内容が壊れるため、後ろの変更を適用しません。重なっている変更を1つにまとめるか、重複している変更を1つ取り除いてから、もう一度お試しください（「修正を依頼」でAIに直してもらう方法もあります）。

### Excel の VBA を編集できない

- 「VBA プロジェクトへのアクセスが許可されていません」（E802）: Excel の「トラスト センター」で「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」をオンにしてください（5.8 の手順）。
- 「紐付けたブックが開いていません」（E804）: ブックを Excel で開いてください。エラーの画面の「Excel で開く」ボタンでも開けます。ブックを移動した・名前を変えたときは、プロジェクトの「場所を変更」ではなく、新しい場所のブックを追加し直してください。
- 「Excel が応答しません」（E805）: セルの編集を確定する、開いているダイアログを閉じる、マクロの実行中でないか確認してから、もう一度お試しください。
- 「マクロの実行中または中断中です」（E813）: マクロを終了（リセット）してから、もう一度お試しください。
- 「Shift_JIS で表せない文字があります」（E811）: 絵文字や波ダッシュ（〜）などを含んでいます。該当のブロックのチェックを外すか、AIに使わない文字で出し直してもらってください。
- ブックのバッジがグレー: ブックが Excel で開いていません。開くと、Graft のウィンドウを前面に出したときにバッジが戻ります。
- Excel 側で直接編集した内容が取り込まれない: 右クリックの「Excel から取込」を試してください。それでも出ない場合は、ブックが開いているか、VBE の編集が反映されているか（VBE 上で保存や再コンパイルは不要です）を確認してください。空白や大文字小文字だけを直した場合（文字列とコメントの外側）は、VBE の自動整形と区別できないため、取り込まれません（文字列の中身・コメント・行頭の字下げの変更は取り込まれます）。
- 「Excel と通信できませんでした」（E801）に 0x…… の数値が付いている: Excel が想定外の返事をしています。数値を控えて、Excel を確認してください（トラストセンターの設定とは限りません。設定が原因のときは E802 になります）。保護ビューで開いているブックや、OneDrive／SharePoint 上のブックは、その旨の理由つきで E801 になります。

### 保存しても Excel に反映されない

右クリックの「保存したらそのモジュールを Excel へ反映する」がオンか確認してください（既定はオフです）。オンでも、ステータスバーに「保存しました。Excel への自動反映は行いませんでした（E…）」と出たときは、そのコードの理由（マクロの実行中・Excel が応答しない・ブックが開いていない・Shift_JIS で表せない文字）を直してから、もう一度保存するか、右クリックの「Excel へ反映」で送ってください。名前の下に「衝突 N」と出ているときは、Excel 側も変わっているため送っていません（「Excel へ反映」で選べます）。

### ウィンドウが前面に出てこない

グローバルホットキーやクリップボード監視の検知で前面に呼び出す際、OS（特にWindows）がアプリの勝手なフォーカス奪取を制限していることがあります。この場合、ウィンドウは実際には最前面になっていても、タスクバーのアイコンが点滅するだけのことがあります。タスクバーのアイコンをクリックすれば表示に切り替わります。

### クリップボード監視が反応しない

設定「クリップボード監視」タブで「クリップボード監視を有効にする」がオンになっているか確認してください。環境によっては監視機能自体が使えないことがあり、その場合はチェックボックス自体が無効化されています。監視がオンでも、内容が標準SEARCH/REPLACE形式・Graft独自形式・unified diff形式のいずれとしても認識できない文章はスキップされます。

### ログの場所と見方

設定画面「更新とバージョン情報」タブの「ログフォルダを開く」でログファイルが入ったフォルダを、「最新のログを表示」で直近のログの内容をその場で確認できます（全文コピーも可能）。ログはデータ保存先の `logs/` フォルダに1日1ファイル（`logs/yyyyMMdd.log`）で保存され、1行が1件の記録（JSON）になっています。ファイルの中身そのものは記録されませんが、ファイルやフォルダの絶対パス（Windowsのユーザー名・フォルダ名・サーバ名を含みます）は記録されます。不具合報告などで公開の場に貼り付ける前に、この点をご確認ください。

### 不具合の報告方法

操作中にエラーダイアログが表示された場合、多くは「詳細をコピー」ボタンが付いています。押すとエラーコード・エラーの内容・対処方法をまとめた文章がクリップボードへコピーされるので、これを不具合報告に貼り付けてください。

## 10. データの保存場所

Graftが扱うデータは、既定では**実行ファイルのフォルダ直下の `data` フォルダ**（ポータブル）に保存されます。**PCを引っ越すときは、実行ファイルのフォルダごとコピーすれば**、設定・履歴・バックアップ・ログがすべて一緒に移ります。更新（自動更新も手動の上書きも）は `data` フォルダに触れません。

以下はすべて `data` フォルダの中にあります。

| ファイル・フォルダ | 内容 |
|---|---|
| `settings.json` | 設定画面で変更した内容一式。 |
| `projects.json` | 登録したプロジェクトの一覧・プロジェクトごとの状態（適用後に実行するコマンドなど）。 |
| `back/` | 履歴ごとのバックアップ本体（`back/<プロジェクトID>/<リビジョン>/`）。ファイル削除の取り消し用の一時退避（`back/trash/`）もここに置かれます。 |
| `logs/` | 1日1ファイルのログ（`logs/yyyyMMdd.log`）。 |
| `vba-mirrors/` | Excel VBA 連携（5.8）のミラー。ブックごとのフォルダに、モジュールのテキストファイルが入ります。 |
| `vba-sync/` | Excel VBA 連携の同期状態（プロジェクトIDごとの `.json`）と、Excel 側の控え（`<プロジェクトID>.rescue/`。「Excel へ反映」の前の自動控え、衝突で上書きしたときの控え、控えを戻す前のミラーの控え）。 |
| `templates.json` | 自分で追加した依頼文テンプレート。 |
| `queue.json` | 保留中のパッチキューの内容。未処理のパッチ本文（AIの応答本文＝ソースコードを含む）を保持します。 |
| `update-check.json` | 更新を最後に確認した日時（「8. 設定」の「更新」参照）。設定の内容そのものではないため`settings.json`とは別ファイルです。 |

1.0.25 以前は、これらを実行ファイルと同じフォルダに直接保存していました。1.0.26 の最初の起動で、`data` フォルダへ自動で移します（コピーして内容を確かめてから、元を削除します。途中で止まっても、次の起動で続きから終えます。移せなかったときは、これまでの場所のまま起動し、理由をログ（`logs/`）に残して、一度だけ画面でお知らせします）。

Program Filesなど、書き込み権限の無い場所にGraftを置いた場合は、設定画面「適用と履歴」タブの「データの保存場所」から**ユーザーフォルダ**（Windowsなら `%APPDATA%\Graft` 相当の場所）へ切り替えられます。切り替えを押すと、現在のデータ一式を新しい場所へコピーしたうえで切り替え用の設定（`datapath.txt`）を書き換えます。元の場所のデータは、再起動したときに、新しい場所へ取り込み直して内容を確かめたうえで削除されます。切り替えの反映にはGraftの再起動が必要です。ここで自分で選んだユーザーフォルダは、次の起動で自動的に `data` へ戻ることはありません。1.0.25 以前からユーザーフォルダを使っていた場合に限り、1.0.26 の最初の起動で一度だけ `data` フォルダへ自動で移します（実行ファイルのフォルダへ書き込めないなどで移せないときは、ユーザーフォルダのまま使います）。`data` フォルダへ戻す操作は、同じ場所の「実行ファイルの data フォルダへ戻す」ボタンから行えます。

実行ファイルの横に残るのは、配布物のファイル（`Graft.exe` など）と、ユーザーフォルダを使っている場合の `datapath.txt` だけです。
