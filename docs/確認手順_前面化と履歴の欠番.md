# 確認手順: クリップボード検知時の前面化・履歴の欠番修正

このセッションで入った変更のうち、**Windows 実機でしか確かめられないもの**に絞った手順です。
所要時間は 15〜20 分程度を想定しています。

対象の変更:

| コミット | 内容 |
|---|---|
| `0bb1b4e` | クリップボード監視でパッチを検知したら Graft を前面化する（新設定・既定オン） |
| `f575d62` | 前面化が OS に拒否されたときに通知が出なくなる回帰の修正 |
| `7ed8555` | 「ここまで戻す」で変更ゼロだったときにリビジョン番号が欠番になる不具合の修正 |
| `22b2768` | テストの不安定さの解消（実機の挙動には影響しません） |

`22b2768` はテストだけの変更なので、実機で確かめることはありません。

---

## 1. ビルド

PowerShell を開いて、上から順に貼り付けて実行してください。

```powershell
cd C:\Users\YUGO\Graft
git pull origin claude/spec-implementation-7fhplo
git log --oneline -1
```

`git log` の1行目が `22b2768` で始まっていれば、最新を取得できています。

> `git pull` が「ローカルの変更と衝突する」旨で失敗した場合、`git status --short` を実行して
> その出力をそのまま報告してください。`D` で始まる行（＝ファイルが消えている）が出ている場合は
> `git restore .` で復元してから `git pull` をやり直してください。

続けて発行（単一ファイルの exe を作る）します。

```powershell
cd C:\Users\YUGO\Graft
Remove-Item -Recurse -Force publish\Graft -ErrorAction SilentlyContinue
dotnet publish src\Graft\Graft.csproj -c Release -r win-x64 --self-contained true -o publish\Graft
```

成功すると `C:\Users\YUGO\Graft\publish\Graft\` に4ファイル（`Graft.exe` ほか）ができます。

```powershell
Get-ChildItem publish\Graft | Select-Object Name, @{n='MB';e={[math]::Round($_.Length/1MB,1)}}
```

> **注意**: 発行先を今までと同じ場所にしている場合、`settings.json` や `back/` などの
> データも同じフォルダにあります。`Remove-Item` でそれごと消えるため、履歴を残したい場合は
> 先に `publish\Graft\back` と `publish\Graft\projects.json` をどこかへ退避してください。

---

## 2. 検証

`publish\Graft\Graft.exe` を起動してから進めてください。

### 2-1. 新しい設定が既定でオンになっている

- [ ] 設定画面（右上の歯車）→「表示・コンテキスト」タブを開く。
- [ ] 「検知したら前面に表示する」というチェックボックスがあり、**チェックが入っている**ことを確認する。
- [ ] マウスを乗せて説明（ツールチップ）が日本語で出ることを確認する。

**期待する結果**: チェックボックスが存在し、既定でオン。説明が表示される。

**違った場合に報告してほしいこと**: 項目が見当たらない／チェックが外れている／説明が出ない、のどれか。可能ならスクリーンショット。

---

### 2-2. 背面にある Graft が前面に出る

- [ ] Graft を起動したまま、メモ帳など**別のアプリを前面**にする（Graft は背後に隠れている状態）。
- [ ] メモ帳に次のテキストを貼り付け、**全選択してコピー**する。

```
<<<< PATCH
summary: 前面化の確認
type: feat
>>>>

<<<< FILE: note.txt
<<<<<<< SEARCH
バージョン: 初期
=======
バージョン: 1
>>>>>>> REPLACE
```

**期待する結果**: コピーした直後に Graft のウィンドウが前面に出てくる。

**違った場合に報告してほしいこと**:
- 何も起きなかった → タスクバーの Graft アイコンが**点滅**していないか確認してください。点滅していれば「OS に前面化を拒否された（想定内の縮退）」で、これは異常ではありません。**点滅していたかどうか**を報告してください。
- 点滅もしなかった場合は、`publish\Graft\logs\<今日の日付>.log` の末尾を報告してください。

```powershell
Get-Content -Encoding UTF8 (Get-ChildItem C:\Users\YUGO\Graft\publish\Graft\logs\*.log | Sort-Object LastWriteTime | Select-Object -Last 1) -Tail 20
```

---

### 2-3. 最小化されていても復帰する

- [ ] Graft を**最小化**する。
- [ ] メモ帳で、2-2 とは**中身の違うパッチ**をコピーする（`バージョン: 1` を `バージョン: 2` に変えるなど。同じ内容だと「同じクリップボード」と見なされて反応しません）。

**期待する結果**: Graft が最小化から復帰して前面に出る。

**違った場合に報告してほしいこと**: 復帰しなかったか、復帰したが最小化のままだったか。

---

### 2-4. 既に前面にあるときは何も起きない（ちらつかない）

- [ ] Graft を**前面にしたまま**、Graft 内のどこかのテキスト欄で、また別の内容のパッチをコピーする。

**期待する結果**: ウィンドウの位置・大きさが**一切変わらず**、ちらつきも起きない。

**違った場合に報告してほしいこと**: ウィンドウが動いた／点滅した／フォーカスが飛んだ、など具体的な挙動。

---

### 2-5. 設定をオフにすると従来どおりの通知になる（**今回の回帰修正の要点**）

- [ ] 設定画面で「検知したら前面に表示する」の**チェックを外す**。
- [ ] 同じ画面で「反応時の挙動」を **「トレイ通知のみ」** にする。
- [ ] 設定画面を閉じ、Graft を背面に置いて、また別の内容のパッチをコピーする。

**期待する結果**: 前面化はせず、**タスクトレイに通知（バルーン）が出る**。

**違った場合に報告してほしいこと**: 通知が出なかった／前面化してしまった。

> この項目は、修正前は「前面化に失敗したときに通知も出ず、何も起きない」状態でした。
> ここが正しく動くことの確認が今回いちばん重要です。

---

### 2-6. 通常のテキストには反応しない

- [ ] メモ帳で「これはただの文章です」など、パッチ形式ではないテキストをコピーする。

**期待する結果**: 前面化も通知も起きない。

---

### 2-7. 「ここまで戻す」で番号が飛ばない（**今回の不具合修正**）

サンプルを作り直します。

```powershell
cd C:\Users\YUGO\Graft
powershell -ExecutionPolicy Bypass -File tools\New-RevisionTestSample.ps1
```

デスクトップに `Graft履歴検証サンプル` が作られます。

- [ ] Graft で `Graft履歴検証サンプル\project` をプロジェクトとして登録する。
- [ ] `patches\01_r1.txt` 〜 `04_r4.txt` の中身を順にコピーして貼り付け、**4回「適用」**する。履歴に **r1〜r4** が並ぶことを確認する。
- [ ] 履歴で **r2 を右クリック →「ここまで戻す」** を実行する。**r5** として記録されることを確認する。
- [ ] **もう一度、同じ r2 を右クリック →「ここまで戻す」** を実行する。

**期待する結果**: 2回目は「変更はありませんでした。リビジョンは記録していません」という趣旨のメッセージが出て、**履歴に新しい行は増えない**。

- [ ] その状態で、次のパッチを貼り付けて適用する。

```
<<<< PATCH
summary: 欠番確認用
type: feat
>>>>

<<<< FILE: note.txt
<<<<<<< SEARCH
バージョン: 2
=======
バージョン: 9
>>>>>>> REPLACE
```

> r2 まで戻した直後は `note.txt` が「バージョン: 2」になっているため、SEARCH 側が
> `バージョン: 2` である必要があります。また、過去に適用したどのパッチとも中身が
> 違うので「適用済みパッチの再投入」（E302）にも掛かりません。

**期待する結果**: 新しいリビジョンが **r6** になる（**r7 に飛ばない**）。

**違った場合に報告してほしいこと**: 実際に付いた番号（r6 だったか r7 だったか）。あわせて次の出力を報告してください。

```powershell
Get-Content -Encoding UTF8 C:\Users\YUGO\Graft\publish\Graft\projects.json
```

> これが今回の修正点です。修正前は番号だけが消費されて `r7` に飛び、履歴上 `r6` が
> 存在しないように見えていました。
