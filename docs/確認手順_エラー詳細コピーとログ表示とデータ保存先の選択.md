# 確認手順: エラー詳細コピー・ログ表示・データ保存先の選択

対象コミット: （このドキュメントをコミットした時点の HEAD。`git log --oneline -1` で確認してください）
ブランチ: `claude/spec-implementation-7fhplo` から分岐した作業ブランチ

この手順書は、次の3機能が **Windows実機で正しく動くか**を確認するためのものです。

1. エラー/失敗ダイアログの「詳細をコピー」ボタン
2. 設定画面「バージョン情報」タブのログ参照手段（ログフォルダを開く／最新のログを表示）
3. 設定画面「一般」タブのデータ保存先の選択（ポータブル ⇔ ユーザーフォルダ）

このうち **3番目（データ保存先の選択）が最も慎重な確認が必要です**。実際にファイルを
コピーし、アプリの読み書き先を切り替える機能のため、Windows実機でしか完全には確認できません
（Linux開発環境での自動テスト・Xvfb実行では、ポインタファイル自体の読み書きロジックと
コピー・検証ロジックの単体テスト、および実際にXvfbで動かしての一連の操作（後述）までは
確認済みですが、Windows特有のパス表記・`%APPDATA%`の実際の解決・レジストリ等を経由しない
単純なフォルダ移動が実機でも期待どおりに動くかは、この手順で確認してください）。

所要時間の目安: 約20〜30分。

---

## 0. 事前に知っておいてほしいこと（安全性について）

- データ保存先の切り替え（3番目の機能）は **既存データを新しい場所へ「コピー」するだけ**
  で、**元の場所のデータは一切削除しません。** 移行に失敗しても、コピー先が不完全な場合は
  切り替え用のポインタファイル（`datapath.txt`）を書き込まないため、次回起動時も元の場所が
  そのまま使われ続けます（=壊れません）。この手順ではその「元の場所が残っていること」を
  実際に目で確認する項目があります（2-3-2・2-3-4）。ここが今回もっとも安全性が重要な箇所
  なので、必ず確認してください。
- 検証中に作られる `datapath.txt`・ユーザーフォルダ（`%APPDATA%\Graft`）は、検証後に
  「4. 後片付け」の手順で削除できます。

```powershell

**期待する結果**: `dotnet build` が警告0・エラー0で成功する。両方の `dotnet test` が

（データ保存先の移行は既存データへ直接影響する検証のため、普段使っている発行フォルダとは

Remove-Item -Recurse -Force publish\GraftDataDirTest -ErrorAction SilentlyContinue
dotnet publish src\Graft\Graft.csproj -c Release -r win-x64 --self-contained true -o publish\GraftDataDirTest
```

## 2. 検証

### 2-1. エラーダイアログの「詳細をコピー」

わざと `settings.json` を壊して、起動時に「設定・履歴データの破損」（E404）の通知ダイアログ
を出します。

```powershell
cd publish\GraftDataDirTest
"これは壊れたJSONです {{{" | Out-File -Encoding utf8 settings.json
.\Graft.exe
```

- [ ] 起動直後に「1件の問題を検出しました。」というダイアログが出て、
      「・E404 設定・履歴データの破損（...）: ... をJSONとして解析できなかったため
      ... へ退避し、既定値で再生成しました。」という文言が表示される。
- [ ] ダイアログの左下（OK/キャンセル等の主要ボタンとは反対側）に**「詳細をコピー」**
      ボタンがある。

**期待する結果**: 「詳細をコピー」ボタンをクリックし、メモ帳等に貼り付けると、次がすべて
含まれている。

- タイトル（「起動時の確認事項」等）
- エラーコード（E404）と要約（「設定・履歴データの破損」）
- 詳細（`.corrupt.日時` へ退避したファイルパスなど、ダイアログ本文と同じ内容）
- 「対処:」という見出しと、E404の対処方法（「退避のうえ再生成しました」）
- 「バージョン: Graft 1.0.0.0」のようなアプリのバージョン
- 「OS: Microsoft Windows ...」のようなOSの情報

- [ ] OKでダイアログを閉じる。設定画面を開き、「一般」タブ下部の「既定に戻す」ボタンを押す。
      「すべての設定を既定値に戻します。よろしいですか？」という確認ダイアログが出る。

**期待する結果**: この確認ダイアログには「詳細をコピー」ボタンが**出ない**（エラーコードを
含まない通常の確認メッセージのため）。「キャンセル」を押してダイアログを閉じる。

**違った場合に報告してほしいこと**: ボタンが出ない／貼り付けた内容に上記のいずれかが
欠けている／通常の確認ダイアログにもボタンが出てしまう、のいずれか。

### 2-2. ログの参照手段

設定画面を開き、「バージョン情報」タブを選ぶ。

- [ ] 「ログ」という見出しの下に「ログフォルダを開く」「最新のログを表示」の2つのボタンが
      ある。それぞれにマウスを乗せると説明（ツールチップ）が出る。
- [ ] 「ログフォルダを開く」を押す。

**期待する結果**: エクスプローラが開き、`publish\GraftDataDirTest\logs` フォルダの中身
（`20260810.log` のような日付名の`.log`ファイル）が表示される。

- [ ] エクスプローラを閉じ、Graftへ戻って「最新のログを表示」を押す。

**期待する結果**: 「最新のログ」という専用ウィンドウが開き、上部に対象のログファイルの
パスが表示され、本文に直近のログ（1行1件のJSON形式。整形はされない）の末尾が表示される。

- [ ] ウィンドウ内の「コピー」ボタンを押し、メモ帳等に貼り付ける。

**期待する結果**: ウィンドウに表示されていた内容がそのままクリップボードにコピーされている。

- [ ] 「閉じる」ボタン、またはEscapeキーでウィンドウが閉じる。

**違った場合に報告してほしいこと**: フォルダが開かない／ウィンドウが開かない／末尾が
200行程度より極端に多い・少ない／コピーした内容が画面の表示と異なる、のいずれか。

### 2-3. データ保存先の選択（最重要・最も慎重に確認してください）

#### 2-3-1. 現在の状態を確認する

設定画面「一般」タブを開き、下の方へスクロールして「データ保存先」の欄を探す。

- [ ] 「現在の保存先」が「ポータブル（実行ファイルと同じフォルダ）」と表示され、その下に
      `publish\GraftDataDirTest` のパスが表示されている。
- [ ] ボタンの表示が「ユーザーフォルダへ移動」になっている。

#### 2-3-2. ユーザーフォルダへ移動する

- [ ] 「ユーザーフォルダへ移動」ボタンを押す。

**期待する結果**: 確認ダイアログが出て、「データ（設定・プロジェクト定義・バックアップ・
ログ）を次の場所へコピーします。」に続けて `C:\Users\<ユーザー名>\AppData\Roaming\Graft`
のようなパスが表示され、「元の場所のデータは削除せずそのまま残します。」「コピー完了後、
この変更を使い始めるにはGraftの再起動が必要です（実行中の切り替えは行いません）。」という
文言がある。

- [ ] 「OK」を押す。

**期待する結果**: 「データを次の場所へコピーしました。」というダイアログが出て、コピー先の
パス・「元の場所（...）のデータはそのまま残しています。」・「この変更を使い始めるには、
Graftを再起動してください。」が表示される。OKで閉じる。

- [ ] （Graftを終了する前に）エクスプローラで `publish\GraftDataDirTest` フォルダを確認する。

**期待する結果**: `settings.json`・`projects.json`（登録していれば）・`back\`・`logs\` が
**まだそこに残っている**（コピーであり移動ではないこと、削除されていないことの確認。
最重要）。

- [ ] エクスプローラで `%APPDATA%\Graft`（`C:\Users\<ユーザー名>\AppData\Roaming\Graft`）
      を確認する。

**期待する結果**: 同じファイル・フォルダ一式がコピーされている。

#### 2-3-3. 再起動して切り替わることを確認する

- [ ] Graftを終了し、`Graft.exe` をもう一度起動する。設定画面「一般」タブの「データ保存先」
      を確認する。

**期待する結果**: 「現在の保存先」が「ユーザーフォルダ」に変わり、パスが
`%APPDATA%\Graft` になっている。ボタンの表示が「ポータブルへ戻す」に変わっている。
（実行中は切り替えないが、再起動後は新しい場所が使われることの確認。）

- [ ] 何かプロジェクトを1つ登録し、適当なファイルにパッチを1件適用してみる（履歴が
      1件増える操作であれば何でも構いません）。

**期待する結果**: 通常どおり動作し、`%APPDATA%\Graft\back` 配下に新しいリビジョンの
フォルダが増える（`publish\GraftDataDirTest\back` 側は増えない）。

#### 2-3-4. ポータブルへ戻す

- [ ] 設定画面「一般」タブの「ポータブルへ戻す」ボタンを押す。

**期待する結果**: 確認ダイアログが出て、コピー先が `publish\GraftDataDirTest` を指している
（exeと同じフォルダへ戻すことの確認）。「OK」を押すと同様に完了ダイアログが出る。

- [ ] Graftを終了し、`Graft.exe` をもう一度起動する。

**期待する結果**: 「現在の保存先」が再び「ポータブル」に戻る。2-3-3で増やしたリビジョン
（`%APPDATA%\Graft\back` にあったもの）が `publish\GraftDataDirTest\back` へコピーされて
おり、参照できる（`%APPDATA%\Graft` 側のデータもそのまま残っていることを確認）。

**違った場合に報告してほしいこと**: 確認ダイアログの文言・パスが期待と異なる／コピーが
行われない、または元データが消える（**特にこれが起きた場合は最優先で報告してください**）／
再起動しても切り替わらない／再起動前に切り替わってしまう、のいずれか。

#### 2-3-5. （可能であれば）書き込めない場所からの起動

Program Files 配下など、通常のユーザーでは書き込めない場所へ発行し、そこから起動できると
理想ですが、管理者権限が必要になるなど手順が煩雑になるため、**必須ではありません**。試せる
場合は次を確認してください。

- [ ] Program Files 配下へ発行し、一般ユーザー権限で `Graft.exe` を起動する。

**期待する結果**: 起動時に「このフォルダへ書き込めません。」という警告ダイアログが出る
（この警告自体は今回の変更より前から存在するものです）。設定画面の「データ保存先」欄で
「ユーザーフォルダへ移動」を押すと、コピー自体は成功するが、確認ダイアログの案内どおり
`datapath.txt`（切り替え用のポインタファイル）を書き込めないため、「データのコピーは
完了しましたが、切り替え用ファイル（datapath.txt）を書き込めませんでした。」という趣旨の
失敗ダイアログになり、再起動しても元のまま（Program Files配下）が使われ続ける。

**違った場合に報告してほしいこと**: このケースでクラッシュする、または警告なく起動する、
のいずれか。試せなかった場合は「未確認」とだけ報告してもらえれば構いません。

## 4. 後片付け

- `publish\GraftDataDirTest` フォルダは削除して構いません。
- `%APPDATA%\Graft`（`C:\Users\<ユーザー名>\AppData\Roaming\Graft`）を検証で作成した場合、
  そのフォルダも削除して構いません（エクスプローラのアドレスバーに `%APPDATA%` と入力すると
  すぐ移動できます）。
- 2-3-5を試した場合、Program Files 配下へ発行したフォルダも削除して構いません。
```
