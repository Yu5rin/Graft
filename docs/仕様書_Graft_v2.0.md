# Graft — 仕様書 v2.0

プロジェクト管理を中核に、コードエディタと、対話型AIが出力したコードの安全な「接ぎ木」を統合した Windows デスクトップ開発ツール。

> **実装者へ**: 本仕様書は実装の唯一の基準である。着手前に**附録A（実装者向け指示）**を必読のこと。v1.5 からの変更点は**附録B**にまとめる。v1.5 で実装済みの資産（パーサ・マッチング・適用・リビジョン・テーマ等）は捨てずに再利用する。

---

## 0. v2.0 改訂の背景

v1.5 は「AI出力の適用」に特化した3ペイン固定のツールだった。v2.0 では製品コンセプトを次の3本柱に再定義する。

1. **プロジェクト管理**（中核） — 複数プロジェクトの登録・切替・状態管理
2. **コードエディタ** — 一般的なコードエディタとして日常の閲覧・編集ができる
3. **接ぎ木** — AI出力のパッチを安全に適用し、リビジョンとして蓄積する

ユーザーは Graft の中でプロジェクトを開き、コードを読み書きし、AIとやり取りした結果をその場で適用・確認できる。「適用のためだけに起動する補助ツール」から「開発の主戦場となるエディタ」への転換である。

## 1. 概要

### 1.1 設計目標

1. **プロジェクト管理を中核とする。** 起動して最初に触れるのはプロジェクトであり、すべての機能（編集・収集・適用・履歴）はプロジェクトに従属する。
2. **一般的なコードエディタの機能を市販ソフト水準で備える。** タブ、ファイルツリー、検索置換、横断検索、折りたたみ、アンドゥ等。エディタとして単体でも使えること。
3. **トークン消費の最小化**（v1.5から継続）。search/replace形式を第一級の入力として扱う。
4. **変更の追跡可能性**（v1.5から継続）。適用単位をリビジョンとして記録する。
5. **製品相当の完成度**（v1.5から継続）。UI・エラー処理・異常系からの復帰を市販ソフトの水準で作り込む。

### 1.2 用語定義

v1.5 の用語（パッチ、ブロック、SR形式、FULL形式、リビジョン、プロジェクトルート）に以下を追加する。

| 用語 | 定義 |
|---|---|
| エクスプローラ | 左サイドのファイルツリー。プロジェクトルート配下を表示する |
| エディタタブ | 中央領域で開かれる1ファイルの編集画面 |
| 接ぎ木パネル | パッチのブロック一覧と適用操作をまとめた下部パネル |
| サイドバー | 左端の縦型アイコンバー。表示するビューを切り替える |

## 3. プロジェクト管理（中核）

v1.5 の3章の内容（projects.json、登録と未接続状態、常設コンテキスト、自動判定の3段階しきい値）を**すべて維持**したうえで、以下を追加・変更する。

### 3.1 プロジェクトを開く

- サイドバーの「プロジェクト」ビューに一覧を表示する。ピン留め優先→最終使用日時降順。
- プロジェクトを選択すると、エクスプローラ・エディタ・履歴・接ぎ木のすべてがそのプロジェクトへ切り替わる。開いていたエディタタブの構成はプロジェクトごとに記憶し、次回選択時に復元する。
- D&D またはフォルダ選択で登録。未接続（ルート不存在）はグレー表示し、パス再指定で復帰。
- プロジェクト切替のショートカットは **Ctrl+Alt+1〜9**（エディタでの数字入力と衝突させない。v1.5 の素の 1〜9 から変更）。

### 3.2 プロジェクトごとに記憶する状態

layout.json に、プロジェクトIDをキーとして以下を保存する。

- 開いていたエディタタブ（パスとアクティブタブ、各タブのカーソル位置）
- エクスプローラの展開状態
- ペイン幅・接ぎ木パネルの高さ
- エディタのフォントサイズ

### 3.3 自動判定

v1.5 の3.4のとおり（90%以上=自動選択 / 50〜90%=要確認 / 50%未満=ブロック、無効化不可）。加えて、判定の結果いま開いているプロジェクトと**別のプロジェクト**が選ばれた場合は、切替の確認を必ず挟む。

## 4. コードエディタ

### 4.1 エンジン

AvalonEdit（`ICSharpCode.AvalonEdit`）を採用する。テーマ・配色は8章のカラートークンへ完全に追従させ、AvalonEdit 既定の配色を残さない。

シンタックスハイライトは v1.5 で実装済みの**自前レキサ（SyntaxLexer、11言語）を唯一の定義**とし、AvalonEdit の `IHighlighter`/カラライザへ接続する。AvalonEdit 内蔵の .xshd 定義は使用しない（配色・対応言語の一元管理のため）。

### 4.2 エクスプローラ（ファイルツリー）

- プロジェクトルート配下をツリー表示する。フォルダ優先・名前順。
- 既定でコンテキスト収集と同じ除外規則（10章）を適用した表示とし、「除外ファイルを表示」トグルで全件表示に切り替えられる。除外中のノードはグレー表示。
- 操作: 開く（ダブルクリック/Enter）、新規ファイル・新規フォルダ、リネーム（F2）、削除（Delete、**ごみ箱へ**）、パスのコピー、エクスプローラで表示。
- リネーム・削除は13章の安全機構（ルート外拒否等）を通す。
- `FileSystemWatcher` による自動更新。外部（他のエディタやgit操作）でのファイル増減・変更をツリーへ反映する。

### 4.3 エディタタブ

- 複数タブ。タブにはファイル名と変更マーカー（未保存時は●）を表示。閉じるボタンはホバー時に表示。
- 未保存のタブを閉じる・アプリを終了する際は保存確認（保存 / 破棄 / キャンセル）。
- シングルクリックはプレビュータブ（イタリック表示・次のプレビューで置換される）、ダブルクリックまたは編集で固定タブへ昇格する。
- Ctrl+Tab で直近使用順のタブ切替。Ctrl+W で閉じる。中クリックでも閉じる。

### 4.4 編集機能

一般的なコードエディタとして以下を備える。

- アンドゥ/リドゥ（Ctrl+Z / Ctrl+Y、AvalonEditのアンドゥスタック）
- 検索・置換（Ctrl+F / Ctrl+H、正規表現・大文字小文字・単語単位。エディタ内オーバーレイ）
- **ファイル横断検索**（Ctrl+Shift+F。サイドバーの検索ビュー。除外規則を尊重し、結果はファイル→行のツリーで表示、クリックで該当行へジャンプ。置換も可能）
- 指定行へ移動（Ctrl+G）
- 行操作: 行の複製（Shift+Alt+↓）、行の移動（Alt+↑↓）、行削除（Ctrl+Shift+K）
- コメントアウト切替（Ctrl+/。言語ルールの行コメント記号を使用）
- 括弧の自動対応（入力時の自動閉じ・対応括弧の強調）
- オートインデント（改行時に前行のインデントを継承。言語別の追加インデントは行わない）
- コード折りたたみ（インデントベース。C系は括弧ベース）
- 矩形選択（Alt+ドラッグ、AvalonEdit標準）
- 空白文字の可視化トグル、折り返しトグル
- Ctrl+マウスホイールでフォントサイズ変更（プロジェクトごとに記憶）
- 現在行のハイライト、行番号表示（設定で切替）
- **簡易補完**: 開いているファイル内の識別子を候補とする単語ベース補完（Ctrl+Space。AvalonEditのCompletionWindowを使用）。LSP等の意味解析は行わない（22章）

### 4.5 エンコーディングと改行

- 読み込み時の判定は v1.5 の 7.4（BOM → UTF-8妥当性 → Shift_JIS）と同一。保存時はエンコーディング・BOM・改行コード・末尾改行を**元のまま保持**する。
- ステータスバーに現在のエンコーディング・改行コードを表示し、クリックで変換（UTF-8/Shift_JIS、CRLF/LF）できる。変換は明示操作のみで自動変換はしない。
- バイナリと判定したファイルは開かず、その旨を表示する（E703）。

### 4.6 外部変更の検知

開いているファイルがディスク上で変更された場合（適用エンジンによる書き換えを含む）:

- エディタ側に未保存の変更が**なければ**黙って再読込する。
- 未保存の変更が**あれば**「ディスク上で変更されています」バーを表示し、再読込（編集破棄）/ 無視を選ばせる（E702）。
- Graft自身の適用（7章）で書き換わったタブは、適用処理が未保存変更の有無を事前に確認している（4.8）ため、常に黙って再読込できる。

### 4.7 Git変更表示

プロジェクトがGit管理下の場合、編集中ファイルの行番号ガターに `HEAD` との差分を色帯で表示する（追加=緑、変更=青、削除=赤の三角マーク。色はトークン参照）。git コマンドの呼び出しは既存の `GitIntegration` を拡張して行い、保存時に更新する。Git管理外では何も表示しない。

### 4.8 接ぎ木との連携

- **適用前**: 対象ファイルに未保存のエディタ変更がある場合、ドライラン開始時に警告し、保存してから続行する（破棄しての続行は不可。ユーザーの編集を黙って失わない）。
- **適用後**: 書き換わったファイルを開いているタブは自動で再読込する。
- **diffからジャンプ**: diff表示の行をダブルクリックすると、該当ファイルの該当行をエディタで開く。
- **ブロック一覧からジャンプ**: ブロックの「エディタで開く」でマッチ位置へ移動する。

## 7. 適用エンジン

v1.5 の6章を**維持**したうえで、以下を追記する。

- **エディタ連携**（4.8）: ドライラン開始時に、対象ファイルへ未保存のエディタ変更があれば保存を促す。適用後は該当タブを再読込する。

### 9.2 レイアウト（全面改訂）

エディタを中央の主役に据え、接ぎ木は下部パネルに移す。

```
┌──────────────────────────────────────────────────────┐
│ コマンドバー                                    40px │
├──┬───────────────┬───────────────────────────────────┤
│サ│ サイドビュー   │ エディタタブ ──────────────────── │
│イ│ （エクスプローラ│ ┌────┬────┬────┐                  │
│ド│ ／プロジェクト │ │a.py│b.cs│diff│                  │
│バ│ ／履歴        │ └────┴────┴────┘                  │
│｜│ ／検索）      │  1  def get_user(id):             │
│48│               │  2      return db.query(id)       │
│px│               ├───────────────────────────────────┤
│  │               │ 接ぎ木パネル（ブロック一覧・適用） │
├──┴───────────────┴───────────────────────────────────┤
│ ステータスバー                                  24px │
└──────────────────────────────────────────────────────┘
```

- **サイドバー（48px）**: エクスプローラ / プロジェクト / 履歴 / 検索 の4ビューをアイコンで切替。同じアイコンの再クリックでサイドビューを折りたたむ。
- **サイドビュー**: 選択中のビューを表示。幅はドラッグで調整し記憶する。
- **エディタ領域**: タブ付きエディタ。**diff はこの領域に専用タブとして開く**（v1.5 の右ペイン diff を廃止し、広い領域で差分を見られるようにする）。diffタブの機能（折りたたみ・並列/統合・空白可視化・文字単位ハイライト・インライン編集）は v1.5 の8.7・8.13を維持する。
- **接ぎ木パネル（下部）**: ブロック一覧（1行目パス・2行目変更説明、状態アイコン、チェックボックス）と「プレビュー / 適用」ボタン、適用サマリ（2件適用可 / 1件要確認）。通常時は折りたたまれ、パッチ解析時に自動展開する。高さはドラッグで調整し記憶する。
- **ステータスバー（24px）**: 行:列、選択文字数、エンコーディング、改行コード、言語、インデント設定、接ぎ木状態、シンタックス無効化の通知。

## 18. 非機能要件

- 起動から操作可能まで1秒以内（v1.5維持）
- 1000行のファイル10件に対し、解析からドライラン完了まで1秒以内（v1.5維持）
- **10万行のファイルを開いてスクロール・編集が遅延なく行えること**（AvalonEditの仮想化を維持し、全行を一括処理する実装を持ち込まない）
- ファイル横断検索は10万ファイル規模でもUIをブロックしない（非同期・逐次表示・キャンセル可能）
- 常駐時のメモリ使用量150MB以下（エディタ分を考慮しv1.5の100MBから緩和）
- v2.0時点ではネットワーク通信なし・自動更新なし（v1.5維持）だったが、**v1.0.8で自動更新機能を追加**（現行の仕様は v2.1 の 15.1章参照）。それ以外の外部通信（使用状況の送信・テーマのダウンロード等）は現在も搭載しない
