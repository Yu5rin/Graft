# Graft

Graft は、**AI（ChatGPT・Claude など）が提案したコードの変更を、手元のプロジェクトへ安全に適用するためのデスクトップアプリ**です。

AI にコードの修正を頼むと「このファイルのこの部分をこう直してください」という形で回答が返ってきます。それを手作業で写すのは、範囲が広くなるほど手間がかかり、写し間違いも起きます。Graft は、AI に決まった書式で回答してもらい、その回答を読み取って実際のファイルへ機械的に適用します。

書き込む直前には必ずバックアップを取るので、結果が気に入らなければいつでも元に戻せます。変更の履歴はリビジョンとして積み上がり、プロジェクト管理とコードエディタも一体になっています。

> 版の数え方: 配布物の版は `v1.0.20` のようにタグで数える。
> `docs/` にある「仕様書 v2.1」は仕様書自体の版で、配布物の版とは別に数える。

## 何ができるか

### 基本の流れ

1. Graft から「この形式で答えてください」という指示文をコピーし、AI との会話の最初に貼り付ける
2. AI に直してほしい内容を伝え、回答をコピーする
3. Graft へ貼り付けて解析する（Ctrl+Shift+V）
4. どう変わるかを差分で確認し、要らない変更はチェックを外す
5. 適用する（Ctrl+Enter）

AI の回答は、標準の SEARCH/REPLACE 形式（既定）・Graft 独自形式・unified diff 形式のいずれでも読み取れます。

### 主な機能

| | |
|---|---|
| **クリップボード監視** | AI の回答らしき内容がコピーされたことを自動で検知します。検知時の挙動（自動解析・前面に表示・通知のみ）は選べます |
| **履歴と復元** | 適用するたびに記録され、1件だけ取り消す／ある時点までまとめて戻す、が選べます。ファイル単位での絞り込みもできます |
| **コンテキスト収集** | AI に渡すコード一式を組み立ててコピーします。「ツリーのみ」「選択ファイル」「ツリー＋選択」（既定）「差分のみ」の4モードから選べ、推定トークン数も表示します |
| **コードエディタ** | シンタックスハイライト、折りたたみ、横断検索、クイックオープン（Ctrl+P）、コマンドパレット（Ctrl+Shift+P） |
| **Markdownプレビュー** | `.md` ファイルを装飾表示します。チェックリストはその場で操作でき、Ctrl+Z で戻せます |
| **Git連携** | 行番号の脇に追加・変更・削除を色で表示します。適用後の自動コミットも設定できます（既定オフ） |
| **適用後フック** | 適用が成功したらフォーマッタやテストを自動実行できます |
| **自動更新** | 新しい版が出たら知らせ、同意した場合だけダウンロードして入れ替えます（Windows 版。[更新](#更新)を参照） |

### 安全機構

- 適用のたびに自動バックアップ（保持数は設定可能）
- 適用前のプレビュー（設定でオン／オフ）
- 対象パスがプロジェクトの外を指していないかの検査
- 適用済みパッチの再投入を検知
- 起動時にバックアップと履歴の整合性を検証

## 動作環境

- **Windows 10（21H2 以降）/ Windows 11**（64bit）
- **Linux**（64bit、glibc ベースのディストリビューション、X11）。Wayland でも動きますが、グローバルホットキーは使えません（起動時に通知します）
- .NET のインストールは不要です（同梱しています）
- インストーラ・管理者権限・レジストリへの書き込みは不要です

## インストール

[リリースのページ](https://github.com/Yu5rin/Graft/releases/latest) から、お使いの OS 向けの書庫をダウンロードします。

### Windows

1. `Graft-<版>-win-x64.zip` をダウンロードする
2. 好きな場所に展開する（例: `C:\Tools`。展開すると `Graft` フォルダができます）
3. できた `Graft` フォルダの中の `Graft.exe` を実行する

実行ファイルのショートカットをデスクトップやスタートメニューへ作っておくと起動が楽になります。

> Windows の SmartScreen が「WindowsによってPCが保護されました」と表示することがあります。コード署名証明書を付けていないためです。内容を確認のうえ「詳細情報」→「実行」で起動できます。

### Linux

1. `Graft-<版>-linux-x64.tar.gz` をダウンロードする
2. 好きな場所に展開して起動する

```
tar -xzf Graft-<版>-linux-x64.tar.gz
cd Graft
chmod +x Graft
./Graft
```

> 展開した直後は実行権限が付いていないことがあります。「許可がありません」と出たら上の `chmod +x` を実行してください。

### 注意

- **実行ファイルだけを取り出さず、フォルダごと扱ってください。** フォルダには実行ファイルのほかにネイティブライブラリ（Windows は3つ、Linux は2つ）が入っており、これが無いと起動できません
- 既定では実行ファイルと同じフォルダに設定・履歴・バックアップを作ります。他のアプリと混ざらない専用の場所に置いてください（[データの保存場所](#データの保存場所)を参照）
- フォルダには `取扱説明書.md` と `はじめにお読みください.txt` も同梱しています

### アンインストール

フォルダを削除するだけです。データ保存先をユーザーフォルダへ移している場合は、そちら（[データの保存場所](#データの保存場所)を参照）も削除してください。

## 更新

### 自動更新

Graft は起動するたびに、新しい版が出ていないかを確認します（Graft 自身がテーマ変更や更新の適用のために再起動したときは確認しません）。設定の「バージョン情報」タブにある「今すぐ更新を確認」でも確認できます。

- 新しい版が見つかるとダイアログでお知らせします。「今すぐ更新」を押した場合だけダウンロードが始まります
- ダウンロードしたファイルは、壊れていないかを検証してから使います。検証や入れ替えに失敗した場合は、いまの版のまま動作を続けます
- 準備ができると再起動を確認します。未保存の変更があれば先に保存を確認します
- 設定・プロジェクト一覧・履歴・バックアップ・ログには触れません。入れ替えるのは実行ファイル・同梱のライブラリ・同梱の文書だけです
- 起動時の確認は、設定「バージョン情報」タブの「起動時に更新を確認する」でオフにできます（オフでも「今すぐ更新を確認」は使えます）

自動で入れ替えられるのは Windows 版だけです。Linux 版は次の「手動で更新する」の手順で入れ替えてください。

### 手動で更新する

`Program Files` など書き込みが制限された場所に置いている場合は、自動更新はできず、リリースのページを開く案内が出ます。その場合や、自動更新を使わない場合は、次の手順で入れ替えます。

1. Graft を終了する（トレイに常駐している場合はトレイから終了する）
2. 新しい版の書庫をダウンロードして展開する
3. 展開してできた `Graft` フォルダの中身を、いま使っている `Graft` フォルダへ上書きコピーする

設定や履歴などのデータは書庫に含まれていないので、上書きしても消えません。

> データ保存先をユーザーフォルダへ移した場合、保存先を指す `datapath.txt` が実行ファイルと同じフォルダに置かれます。新しい版へ差し替える際にこのファイルごと消してしまっても、Graft が起動時に「以前ユーザーフォルダに保存したデータが見つかりました」と尋ねるので、そこから復帰できます。

## 使い方

初回起動時に「Graftへようこそ」という案内が開きます。4画面進むだけでひととおりの流れを体験できます。自分のプロジェクトを使わずに試したい場合は、案内の最後の画面にある **「使い方を学ぶ」** を押してください。一時フォルダに練習用のファイルが作られ、あなたのフォルダには一切触れずに、解析から適用までを実際に体験できます（あとから画面右上の「?」メニューからも実行できます）。

詳しい使い方は、アプリ内で **F1** を押すといつでも開ける取扱説明書にあります。同じ内容を書庫に `取扱説明書.md` として同梱しており、リポジトリの [`docs/取扱説明書.md`](docs/取扱説明書.md) でも読めます。

## データの保存場所

既定では **実行ファイルと同じフォルダ**（ポータブル）に、設定・プロジェクト一覧・履歴・バックアップ・ログを保存します。フォルダごとコピーすれば、別の PC へそのまま持ち運べます。

`Program Files` など書き込めない場所に置いた場合は、設定→一般の「ユーザーフォルダへ移動」で `%APPDATA%\Graft`（Linux では `~/.config/Graft`）へ移せます。

## 外部との通信

Graft が外部と通信するのは、更新の確認とダウンロードのときだけです。確認先は GitHub（`github.com/Yu5rin/Graft` のリリース）で、設定「バージョン情報」タブの「チェック先URL」で確認・変更できます。使用状況の送信など、それ以外の通信は行いません。

## 既知の制限

- **Windows のみ動作確認済み**です。Linux 版もビルドできますが、実際のデスクトップ環境での検証は行っていません
- コード署名証明書を付けていないため、SmartScreen の警告が出ます
- インストーラはありません（書庫の展開のみ）

## 不具合の報告

うまく動かないときは Issue でお知らせください。次の情報があると調べやすくなります。

- OS のバージョン
- 何をしたときに、何が起きたか
- `logs\<日付>-<プロセスID>.log` の該当時刻あたり（設定→バージョン情報→「ログフォルダを開く」から辿れます）

エラー画面には「詳細をコピー」ボタンがあります。押すと原因の特定に必要な情報がまとめてコピーされます。

> **ログを貼り付ける前に**: ログにファイルの中身そのものは記録されませんが、ファイルやフォルダの絶対パス（ユーザー名・フォルダ名・サーバ名を含みます）は記録されます。Issue など公開の場に貼り付ける前にご確認ください。

---

ここから下は開発者向けの情報です。

## 3本柱

1. **プロジェクト管理** — 複数プロジェクトの登録・切替・状態管理
2. **コードエディタ** — タブ、エクスプローラ、検索置換、横断検索、折りたたみ、Gitガター
3. **接ぎ木** — AI出力のパッチを安全に適用し、リビジョンとして蓄積する

## 設計目標

- **トークン消費の最小化** — search/replace 形式を第一級の入力として扱う
- **変更の追跡可能性** — 適用単位をリビジョンとして記録する
- **製品相当の完成度** — UI・エラー処理・異常系からの復帰を市販ソフトの水準で作り込む

## 動作環境（開発者向けの補足）

- .NET 8 / Avalonia UI、self-contained の単一ファイル形式（ランタイムの事前導入は不要）

OS 固有機能（トレイ常駐・グローバルホットキー・クリップボード監視・ごみ箱・
ファイルマネージャ連携・システムテーマ追従・多重起動防止）は `Platform/` の抽象越しに扱い、
利用できない環境ではその機能だけを無効にして動作を続ける。
Wayland ではグローバルホットキーが使えないため、起動時にその旨を通知する。

## 構成

```
Graft.sln
├── src/Graft/
│   ├── Core/       パーサ、マッチング、適用、バックアップ、レキサ（UI非依存）
│   ├── Features/   プロジェクト管理、収集、横断検索、フック、Git（UI非依存）
│   ├── Infra/      設定、ログ（UI非依存）
│   ├── Platform/   OS 固有機能の抽象と実装（Windows / Linux / Null）
│   ├── Editor/     AvaloniaEdit によるエディタ層
│   ├── ViewModels/ 自前の軽量 MVVM
│   ├── Views/      画面
│   ├── Themes/     カラートークン、シンタックス配色、SVGアイコン、ロゴ
│   └── Assets/     アプリアイコン、同梱ライセンス
├── tests/Graft.Tests/   単体テスト（xUnit + FluentAssertions）
├── tests/Graft.UiTests/ Avalonia headless による UI テスト（画面なしで実描画）
├── docs/                仕様書
└── tools/               アイコン生成スクリプト
```

`Core/` `Features/` `Infra/` `Platform/`（抽象と Null 実装）は UI フレームワークを参照しない。
テストプロジェクトがこれらのソースを直接取り込んで `net8.0` としてビルドするため、
UI 非依存が機械的に保証される。

## ビルド

```
dotnet build Graft.sln
dotnet test Graft.sln
```

Windows / Linux のどちらのホストでもビルドとテストが完結する。UI テストは Avalonia の
headless 環境で実際に描画するため、画面のない CI 上でもレイアウト崩れとリソース解決の
失敗を検出できる。

## 発行

```
# Windows 向け
dotnet publish src/Graft -c Release -r win-x64 --self-contained true -o publish/win

# Linux 向け
dotnet publish src/Graft -c Release -r linux-x64 --self-contained true -o publish/linux
```

発行物は Windows では `Graft.exe` とネイティブDLL3つの**計4ファイル**、Linux では `Graft` と
ネイティブライブラリ2つの計3ファイルになる
（単一ファイル形式・自己展開なし。`PublishSingleFile` 等はcsproj側の既定値なので、
上記コマンドに `-p:` の追加指定は不要）。**exeファイルだけを取り出して配置しないこと**。
同梱の3つのDLLがないと `FileNotFoundException` で起動できない。実行ファイルと同じ階層に
`settings.json` / `projects.json` / `back/` / `logs/` を作るため、4ファイルをまとめて
専用の場所へ置くこと。

起動時の JIT を減らすため ReadyToRun を有効にしている（Linux 実測で約1.85秒 → 約0.72秒）。

以前は単一ファイル（`PublishSingleFile`）として発行していたが、`IncludeNativeLibrariesForSelfExtract`
（ネイティブDLLを実行時に一時フォルダへ自己展開する設定）が true だったために初回起動が
約5.44秒かかり、いったんフォルダ形式へ移行した。しかしフォルダ形式は発行物が216ファイル・
約109MBに散らばり、依存DLLを子フォルダへまとめようとしても `Graft.deps.json` が期待する
NuGetパッケージ相対パス（`lib/net8.0/Avalonia.Base.dll`）が崩れて起動不能になるなど、
整理のしようがなかった。そこで今回、`IncludeNativeLibrariesForSelfExtract` を明示的に
**false** にしたまま単一ファイル形式へ戻した。false であれば実行時展開が発生せず
（過去の5.44秒はここが原因だった）、管理コードもバンドルから直接読まれるため遅くならない。
実際、Linux実測（同一条件）でフォルダ形式 798〜1145ms に対し単一ファイル形式は
622〜637msと、むしろ高速だった。発行物も216ファイルから4ファイルに減っている。
